5皮肤联动：一套令牌，四张皮自动生效

6待你拍板（每条都标了它落在上面哪张稿子上）

D1 · 服务器地址
手机端只连云端，还是允许手填地址？
建议：只连云端。手填框会把 token 带进浏览器自动填充与历史记录。调试需求走 SSH 隧道。代价：本地联调要在 Mac 上起隧道。
稿子：状态条「云端 · 同步 12s 前」
D2 · tab 数量
底部两屏，还是三屏（审批升独立屏）？
建议：两屏 + 顶栏旗子/抽屉。这条只有你能定——如果你在外面的九成动作是「点批准」，那审批该升成 tab。代价：三屏会把花园挤到角落。
稿子：第 1 节底部 tab / 第 3 节 ①
D3 · 花园敏感过滤
长期记忆原样展示，还是加折叠？
建议：先展示层折叠（可点开），第二批再看要不要加带标签的读口。实情是 sensitivity.py 只在写与日志侧生效、家人词表只挡发布路，读口原样返回。代价：展示层是词表启发式，会有漏。
稿子：第 3 节 ④（已画出折叠态）
D4 · 逐字稿要不要进同步
手机上聊的话，Mac 端要不要看得见？
建议：第一批不动，界面文案不承诺「两端记录同步」。记忆/画像/日记会回灌 Mac（阶段 1/2/6 已闭合），但 chat.db 在架构稿阶段 2 明确「本期不动」。真要 = 架构稿下一期，另开设计。
设计稿 §1.4 · 架构稿阶段 2
D5 · SW 与缩放
装不装 Service Worker？锁不锁缩放？
建议：第一批都不。自更新站点装 SW 容易把旧版钉在手机上（我们的教训是版本一致要钉四处）；user-scalable=no 可访问性代价不值。代价：没有离线兜底。
设计稿 §六.5 / §九 D5
D6 · 桌面加不加入口提示
桌面侧栏要不要一行「手机入口」？
建议：不加。加了就破坏「桌面零改动」这个已拍板前提，得重跑桌面回归。要的话我单独出一次桌面 diff 给你过。
设计稿 §九 D6
D7 · 主屏图标与名字
图标用立绘还是皮肤景物？名字「小桔」还是「桔」？
建议：立绘重出一版干净的 180²/192² + 名字「小桔」。源图 1024²/830KB，直接缩放会糊；换肤不改小桔形象（既有注释）。要我生成一版给你挑的话说一声。
稿子：所有稿子里的头像
D8 · 她主动找你
手机上前台驻留轮询，还是切回前台拉一次？
建议：切回前台拉一次。驻留轮询在移动网络下易失败、后台会被浏览器掐。必须说清的预期：装主屏 ≠ 会收到通知。真推送要 VAPID + 订阅表，明确留第二批。
稿子：对话屏顶栏 / 设计稿 §七.7

落地批次（设计稿 §八，每批独立可回退）
M0 骨架 半天 — mobile.html + src/mobile/ + 连接自检页。验收：真机看到 WS 已连且同源取到 token；桌面 git diff 不含 App.tsx / styles.css / index.html。
M1 对话 1–2 天 — 续聊最近会话 → 历史 REST → WS 流式 → turn_done → 复用 Session 的保活/重连/outbox。验收：飞行模式发 2 条，恢复后按指纹逐条核补发不多不少；冷启动不新增空会话。
M2 审批 半天 — inbox + 抽屉。验收：手机点「允许一次」后，用产物/服务端日志证实她真的继续跑，不看 UI 绿灯；两端同点同一 ask → 先到先得、后者不报错。
M3 花园 1–2 天 — 门的清单 + 日记时间线（发/评/🩷）。验收：手机发一条日记 → ≤10 分钟 Mac user_posts 出现同 sync_uuid（按 UUID 逐条对账，不只数总量）。
M4 装主屏 半天 — 图标 + manifest + theme-color + safe-area + 键盘。验收：iOS/Android 加主屏后 standalone 冷启动；两肤 × 深浅各过一遍；桌面回归截图对比。
合计 4–6 人日（不含 D4 的 chat.db 同步、不含推送）。
构建与部署只有三个动作：① vite.config.ts 加第二个 input → 一次 npm run build 出两端；② 手机端 html 必须落在 dist 根（base:"./" 的坑，vite.config.ts:43），否则 /m/ 下相对路径 404；③ Caddy 加一行 handle /m { rewrite /m.html }，并确认 SPA 兜底不会把它吞成 index.html。deploy_web.sh 一行不改（只把那条「token 出现次数须为 0」的自检从 assets/ 扩到全目录，别留只扫一半的假绿）。
