# 技能机制对比：Hermes vs 小桔（2026-11-19）

> 目的：在动手改"读稿技能引导"之前，先把两套技能系统的**机制差距**查清楚，
> 确认是不是"仅仅引导层的问题"，再定方案。
> 方法：直接读本机 `~/.hermes/hermes-agent` 源码 vs 本项目 `coworker/skills`、`deskmate/skills`，
> 以及真实技能文件 `~/.deskmate/skills/writing/novel-review.md`。只读，未改代码。

---

## 0. 结论：不只是引导层，是四层差距

| 层 | 小桔 | Hermes | 差距性质 |
|---|---|---|---|
| ① 目录/发现机制 | 几乎一样（SKILL.md + frontmatter + 目录扫描 + 缓存） | 一样 | ✅ 已对齐（我们本来就借鉴了） |
| ② **注入引导文案** | 一句话："call load_skill(name) when relevant" | **强制 MUST + 宁滥勿缺 + 定义质量标准和失败模式** | ❌ 引导层（知道该不该加载） |
| ③ **技能内容结构** | 416 行平铺建议列表，无门禁 | **铁律 + 分阶段 + 完成检查清单 + 禁止跳步** | ❌ 结构层（加载后能不能按它做） |
| ④ **加载时副作用** | `load_skill` 只返回文本 | `skill_view` = 激活时刻（预处理、依赖安装、readiness、linked files、related skills） | ❌ 激活层（加载是不是"执行"） |

**读稿这次犯错，② 让它没加载全文、③ 让加载了也按平铺建议走、④ 让它没有"激活即进入流程"的抓手。**
所以这不是"改一句 description"就能解决的——但也不用全盘重构，方案见 §4。

---

## 1. ① 目录/发现机制：已对齐，不用动

- 小桔 `coworker/skills/base.py`：目录扫描、`_parse_skill` 解析 frontmatter、`_parsed` 按 mtime 缓存（PR6 已优化）。
- Hermes `agent/skill_utils.py` + `prompt_builder.py`：分层目录（category）、tier、同名去重、disabled 匹配。
- 两者本质相同（我们是借鉴的）。**这层不是问题。**

---

## 2. ② 注入引导文案：小桔太弱

### 小桔（`coworker/skills/base.py:147`）

```
Available skills — call load_skill(name) to load one's full instructions when it's relevant to the task:
- novel-review: 审校萧盛的历史小说章节：检查...
```

一句话，弱建议，模型容易忽略。

### Hermes（`prompt_builder.py:1342-1366`）

```
## Skills
Before replying, scan the skills below. If a skill matches or is even partially relevant to your task,
you MUST load it with skill_view(name) ... Err on the side of loading — it is always better to have
context you don't need than to miss critical steps, pitfalls, or established workflows. ...
Load the skill even if you think you could handle the task with basic tools ...
Skills also encode the user's preferred approach, conventions, and quality standards ...
Only proceed without loading a skill if genuinely none are relevant.
```

**强制、宁滥勿缺、明确"技能定义了该怎么做"**。差距明显。

## 3. ③ 技能内容结构：这是读稿犯错的主因

### 小桔 `novel-review.md`（416 行）

- 20+ 个章节（`写作节奏与指标管理`/`情节卡壳`/`人物动机`/`填坑`/`史实考据`…）**平铺**，每节若干 `- 当...时...` 的建议。
- "读与抠分开"那条埋在 `整体读后反馈` 章节里（第 27 行附近），是一条并列建议，没有优先级、没有门禁。
- 技能 description 是"检查官称/关系/风格"——**校对导向**，把模型往逐字找错引。
- 末尾（277 行、328 行）有几段超长"当用户说 X 时加载此技能；若...若...若..."的巨型条目，关键信息被淹没。

### Hermes `systematic-debugging/SKILL.md`（对照样本）

```
## The Iron Law
NO FIXES WITHOUT ROOT CAUSE INVESTIGATION FIRST
If you haven't completed Phase 1, you cannot propose fixes.
## The Four Phases
## Phase 1: Root Cause Investigation
  ### Phase 1 Completion Checklist
## Phase 2: Pattern Analysis
...
```

**铁律（一句不可违反的话）+ 分阶段 + 每阶段完成检查清单 + 明确禁止跳步。**
模型读完就知道"必须先做完 Phase 1 才能进 Phase 2"，不存在"边读边改"。

**这正是 Hermes 读稿条理清晰的原因：它把"先理解后抠字"做成了带门禁的流程，而不是一条建议。**

---

## 4. ④ 加载时副作用：Hermes 把"加载"做成"激活"

### 小桔 `load_skill`（`coworker/skills/base.py:164`）

```python
return {"name":..., "instructions": skill.instructions, "resources_path": skill.path}
```

只返回文本，无副作用。模型"加载了技能"但没有进入任何状态。

### Hermes `skill_view`（`tools/skills_tool.py:634`）

加载技能时同时做：
- `_preprocess_skill(content, skill_dir, task_id, ...)`：模板渲染 / inline shell 渲染
- `_skill_readiness()`：就绪状态检查
- `deps` frontmatter：pm 依赖安装（"Loading the skill IS the activation moment"）
- `linked_files` / `related_skills`：关联资源
- 平台检查、disabled 检查、安全告警

**加载即激活**——技能不只是"被读到的文字"，而是"被执行的流程入口"。

---

## 5. 记忆层（用户提到"记忆也借鉴了"）：结构对齐，但喂给技能的方式不同

- 小桔 `deskmate/skills/curator.py` 明确对标 Hermes `agent/curator.py`：7 天周期、只报告不删除、受保护技能、fail-open——**机制对齐**。
- 但 Hermes 的纠正/偏好会进 `§纠正` 这类 Core 层，且技能里能用 `related_skills` 把记忆和技能连起来；小桔的 Core 记忆每轮注入，但**技能和记忆之间没有"相关技能"的连线**，纠正落在 MEMORY.md，读稿技能不会因这条纠正而被自动强调。
- 所以这次纠正虽然记在 Core（每轮注入），但没有和 `novel-review` 技能形成"加载该技能时先显眼提醒这条纠正"的连接——这是记忆 vs 技能的衔接缺口。

## 6. 打磨后的方案

> 目标：不照搬 Hermes 全套（太重），只补对读稿真正起作用的三处。

### 第一步：改注入引导（②，零风险）

把 `coworker/skills/base.py:147` 的 catalog 引导改成接近 Hermes 的强制语气：
- "Before replying, scan the skills. If one matches or is even partially relevant, you MUST load it with load_skill(name)."
- "Skills contain established workflows and the user's preferred approach — load even if you think basic tools suffice."
- "Only proceed without loading if genuinely none are relevant."

### 第二步：重写 novel-review 的"读稿"部分为门禁流程（③，核心收益）

不重构 416 行全文，只把**顶部**加一段"读稿铁律 + 两段式门禁"，放在最显眼处：

```
## 读稿铁律（先理解，后抠字）
NO 字词级疑点 BEFORE 通读完成。

Phase 1（必做）：通读 [范围] 全文，先输出「人物动机 + 情节走向」两段理解。
  完成检查：能说清每个关键人物为何说这句话、这段情节把事件推向哪里。
Phase 2（仅在 Phase1 完成后）：逐字抠明显笔误，只标写错的词/字。
禁止：边读边标疑点；用"他在撒谎/贴金"这类真伪框架套人物台词。
```

并把 description/trigger 从"检查/审校"改成"读稿理解优先"。

### 第三步：让纠正和技能连起来（④/记忆衔接，小改动）

在 `novel-review.md` 顶部把 `§纠正` 那条"读与抠分开"作为技能的 **related correction** 显眼引用（而不是只在 MEMORY.md 里），并给技能加 frontmatter 字段（如 `related_corrections`）——让"加载读稿技能"时这条纠正被一并强调。

### 不做

- 不照搬 Hermes 的 deps 安装/readiness/related_skills 全套——对读稿技能没必要。
- 不删 416 行里的其它条目——它们有 305 次使用记录，是积累的正确规则。
- 不再往 MEMORY.md 记一条——已经够多了。
