# 日记灵感机制 + 数据收拢排查

> 2026-09-02 · 萧哥提的两个问题：
> ① 小桔日记不要定时触发写废话，改成"素材攒够才动笔"；
> ② 数据库迁移收拢后，有没有受影响的组件。

---

## 一、小桔日记：从"定时/手动"改为"灵感阈值驱动"

### 1.1 原来的问题

`DiaryWriter.ensure_today()` 只有一条调用链：

```
DiaryPanel 两个按钮的 onClick → POST /v1/deskmate/diary/today → ensure_today()
```

**没有任何后台任务会触发它。** 硬证据：09-01 当天产生 **28 条事件**（15 记忆 + 11 技能进化 + 2 纠正），
素材爆棚，结果一篇日记都没写；现存只有 2 篇（08-29、08-31），都是 08-31 15:22 一次性生成的。

但**不能简单地加个定时任务**——萧哥的判断是对的：没东西可写时定时触发，产出的就是
"今天没有太多动静"这种流水账，写一百遍不如不写。

### 1.2 新机制：素材攒够才动笔

新模块 `deskmate/growth/diary_inspiration.py`，与深度访谈
（`maybe_trigger_interview`）同一范式：**纯规则、零 LLM、条件满足才发生**。

差异在于——日记**不需要用户在场**，她是自己动笔，不是来打断你。所以挂在
`tick.py` 的 idle 判断**之前**：素材攒够就安静写下来，返回里带一句轻提示；
没攒够则什么都不做。

#### 三个关键点

**① 素材账本（`diary/materials/YYYY-MM-DD.jsonl`）**

为什么不能直接读 `GrowthState.recent_events`？因为它落盘时被截断到最后
`EVENT_LOG_CAP`(50) 条，是**易失窗口**。实测现在就已经满了 50 条，
09-01 一天产生 28 条——两天就能把前一天的素材整体挤出去。
等到晚上再写，素材早没了。账本增量落盘，持久保存，不受窗口挤压。

**② 加权评分**

| 档位 | 权重 | 事件 |
|---|---|---|
| 里程碑 | 4.0 | `skill_created` `creation_approved` |
| | 3.5 | `badge_unlocked` |
| 反思 | 3.0 | `user_corrected` `creation_rework` |
| 协作 | 3.0 | `roundtable` |
| | 2.0 | `suggestion_accepted` `skill_evolved` `writing` `report` |
| 日常 | 1.5 | `skill_used` |
| | 1.0 | `suggestion_ignored` |
| 痕迹 | 0.5 | `chat` `memory_learned` |
| 非素材 | 0.0 | `depth_backfilled`（系统补录，不是当天真实发生的事） |

**③ 单类封顶（6.0 分/类）——这条很关键**

一次导入 15 条记忆、或 11 个技能同时进化，那是**一次批处理**的副产品，
不是 11 件值得写的事。不封顶的话，任何批量操作都会瞬间刷满灵感分。
实测 09-01 的 11 条 `skill_evolved` 被压到 6 分（否则会是 22 分，一个人霸占整篇）。

### 1.3 阈值标定（用真实数据回测）

阈值 `5.0`，用 `~/.deskmate` 的真实事件回测：

| 日期 | 素材 | 灵感分 | 判定 | 对照现实 |
|---|---|---|---|---|
| 08-24 / 25 / 27 | 各 1 条 | 0.5 | 不写 | 确实没素材 ✅ |
| 08-26 | 8 条 memory | 4.0 | 不写 | 只是学了些小事 ✅ |
| 08-29 | 1 skill + 1 memory | 2.0 | 不写 | 那天是**手动点的** ✅ |
| 08-30 | 3 次纠正 | 6.0 | **写** | "你纠正了我三次"值得一篇 ✅ |
| 08-31 | 5 次纠正 | 6.0 | **写** | 与现存那篇吻合 ✅ |
| 09-01 | 28 条 | 18.0 | **写** | 素材爆棚却没写——正是要修的病 ✅ |

08-29 判定"不写"但现实有日记，是因为那天用户**手动点了按钮**——那是明确的
用户意愿，走 `ensure_today()`（force 语义），与自动触发是两条路径，不冲突。

### 1.4 顺便修掉：死幂等

原 `ensure_today()` 是死幂等——当天生成过就不再重写。后果是早上点一次，
当天剩下的事永远进不去那篇。现存 08-31 那篇至今写着"累计对话 190 轮 · Lv.7"，
而库里已经是 **203 轮 · Lv.9**。

新机制：当天已写过、但新增素材 ≥ `4.0` 分时**重写**（账本累积，正文包含全部素材）。

### 1.5 改动清单

| 文件 | 改动 |
|---|---|
| `deskmate/growth/diary_inspiration.py` | **新增**：素材账本 + 加权评分 + `maybe_write_diary()` 钩子 |
| `deskmate/growth/diary.py` | 新增 `write(date, events, badges)`（可指定素材源 + 原子落盘）；`ensure_today()` 收敛为"用户主动才用" |
| `deskmate/proactivity/tick.py` | `TickResult` 加 `diary` 字段；tick 开头调用钩子（idle 判断之前） |
| `coworker/server/app.py` | 新增 `GET /v1/deskmate/diary/inspiration`（灵感进度，供前端显示"3.5/5"） |
| `deskmate/growth/test_diary_inspiration.py` | **新增** 13 项测试 |

> ⚠ 路由顺序：`/diary/inspiration` 必须注册在 `/diary/{date}` 之前，否则被通配吃掉。已实测验证。

### 1.6 验证

- 13 项新测试全过；`deskmate/` 全量 **45 passed / 2 skipped**，无回归
- 端到端实测（隔离目录）：
  - 平淡的一天（2 条记忆）= 1.0 分 → **返回 None，安静等着**
  - 有料的一天（3 纠正 + 拍板定稿 + 5 记忆）= 12.5 分 → **动笔**，正文为
    「你拍板定稿了一份创作（第三章）／我又记住了你 5 件小事／你纠正了我 3 次」
- 路由实测：`/diary/inspiration` → 200；真实数据下今天 0 分 → `素材还不够（0.0 < 5.0），今天先不写`

**后端改动，重启 app 即生效，无需打包。** 前端"今日灵感 3.5/5"的进度条
与轻提示下次打包时再接。

### 2.2 ⚠ growth.json 空壳——定时炸弹

文件停在 **09-01 20:28**，内容是空壳（`intimacy 0 / level 1 / 对话 0`）；
而 DB 里是真数据 **intimacy 100 / Lv.9 / 203 轮 / 11 徽章**，08:37 仍在更新。

**当前不影响显示**——`load_state()` 默认走 DB，只有 DB 无 key 时才读 legacy 文件。

但 `BlobStore.get(key, legacy_path=...)` 的契约是：**DB 无此 key 且 legacy 文件存在，
就自动迁移导入**。也就是说，万一 DB 的 growth blob 因故丢失，下次启动会自动
把这个空壳导入 → **桌宠瞬间从 Lv.9 退回 Lv.1，203 轮对话和 11 枚徽章全没了**。

**建议**：把这个空壳改名 `.bak`（DB 有数据时它永远不会被读，改名零风险）。
需要你点头我再动。

### 2.3 🔴 两个可以清掉的孤儿文件

- **`activity.db`**：369MB，最后写入 **07-28**。全仓 grep **无任何代码引用**。
- **`memory/vectors.json`**：24MB，最后写入 07-26。`docs/向量检索审计` 结论明确
  ——"仓库当前无任何向量索引"，只有审计脚本会 glob 它做检测，运行时代码不读。

两个都是历史遗留，不影响功能，但占空间（合计约 393MB）。
要不要归档由你定，我没动。

### 2.4 其余数据的判定依据

- `behavior_log.jsonl`（132.9KB，活跃）：`memory/sync.py` 把它列在
  **排除同步**清单里 —— 属于"设备本地关系留本机"，设计如此，不是遗漏。
- `digest_cache.json`、`traces/*.jsonl`：缓存与追踪日志，本就该是文件。
- `sessions/*.md`、`projects/`：内容型文件，不入 DB 合理。
