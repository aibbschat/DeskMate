## 三、验收方法（本次有效，可复用）

### 1. 静态验证前端改动是否真打进产物

**关键点：minify 会改函数名/变量名，但字符串字面量、CSS 类名、正则字面量会保留。**
所以特征串要挑这三类，别去 grep 标识符（踩过：`parseTs` 未命中，其实是 minify 改名了）。

```bash
cd surfaces/gui/dist/assets
grep -F "再记一笔"          index-*.js    # 中文文案 → 保留
grep -F "dm-diary-entry-time" index-*.css # CSS 类名 → 保留
grep -F "limit=500"         index-*.js    # URL query → 保留
grep -F '\d{1,2}:\d{2}'     index-*.js    # 正则字面量 → 保留（可用 Grep 工具）
```

### 2. 内嵌一致性

```bash
strings /Applications/OpenWorker.app/Contents/MacOS/openworker-desktop \
  | grep -oE 'index-[A-Za-z0-9_-]{8}\.js' | sort -u
```
输出含当前 dist 主块哈希即说明装的是新包。

### 3. 后端是否新代码在跑

后端没有 token 可用的 HTTP 通道（见下），改用**行为证据**：
启动时 `learned_history.jsonl` 被自动归档为 `.bak-<ts>` → 说明新迁移代码执行了。

## 四、坑（重要）

### 1. `safety-card` 警告是**误报**，别被吓到

脚本第 95 行校验 `strings <binary> | grep safety-card`，但 Tauri 把前端资源**压缩**进
二进制，`strings` 对压缩内容漏检。核实方法：

```
源码 SettingsView.tsx  → 有 safety-card
dist/assets/*.js       → 有 safety-card
app 二进制 strings     → 检不出（压缩）
```

脚本注释本身也标注了"非阻断、可能漏检"。**属误报。**

### 2. app 启动的后端拿不到 token，curl 做不了 smoke test

`coworker/server/run.py:69-70`：
```python
if os.environ.get("COWORKER_API_TOKEN"):
    return None  # Tauri supplied an in-memory token; never persist it
```
即 Tauri 用内存 token 启动后端，**不落盘** `sidecar-<port>.token`。
目录里那些 `sidecar-8765/58197/8799…token` 都是历史手动跑服务留下的，跟当前端口无关。

→ 想验证接口，要么自己起一个固定端口的服务，要么用 TestClient（见 `tests/`），
  要么改用行为证据（日志 / 文件副作用）。

### 3. 旧进程与新代码的时序（learned_history 专项）

旧进程读 jsonl、新代码读 DB。若在 app 运行期间改了名，旧进程 `open("a")` 会重建空文件
→ 前端记忆面板显示 0 条。

本次处理：改完名后立刻把文件复制回原位，让旧进程继续正常工作；
**迁移挂在 `create_app` 启动时幂等执行**，下次重启自动收口。
实测：启动后 jsonl 归档为 `.bak-20260902-103613`，DB 保持 211 条（期间无新增，**未翻倍**）。
