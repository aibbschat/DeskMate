# LLM 通道熔断与双通道路由 · 系统设计（2026-10-06）

> 触发：萧哥 2026-10-06 20:00 提出「似乎绑死火山，火山一到限额整条链瘫了，这个债以后会越来越重」。
> 20:40–21:00 实测确认成立，且挖出比"没有备用钥匙"更本质的问题（见 §一）。
> 拍板方案：**两个总开关**（付费组 / 免费组），组内自动切 + 手动切，本地与云端同一套。

## 一、实测证据（20:40–21:00，非推测）

### 1.1 你的实况 > 我的探测（两次纠正，值得记）

我先后两次用**裸请求**（urllib/httpx 直打 `/chat/completions`）探测 opencode 免费通道，得出"只有
`fledge-alpha-free` 可用、其余全 429/403"的结论。**萧哥实际在 GUI 里连续切换
`Nemotron 3 Ultra` / `Space Bunny` / `Fledge Alpha` 均正常对话**，与我的结论矛盾。

⇒ **教训**：探测 opencode 免费通道**不能手搓 HTTP**，必须走生产代码路径
（`coworker/providers/opencode_provider.py`）。但注意：**即使走 `OpencodeProvider.complete()`，
我仍测出 `space-bunny-free` 429**——而 app 里同模型可用。差异只剩一处：**长会话 vs 一次性请求**
（额度可能与 `x-opencode-session` 派生 id / 已消耗量相关，非模型级静态配额）。
⇒ **设计含义**：熔断粒度不能停在"模型级"，必须**记在真实调用维度**（见 §三）。

### 1.2 三条付费/免费通道的真实状态（20:40）

| 通道 | 状态 | 证据 |
|---|---|---|
| 火山 `ark-agent-plan-cn` | ❌ `AccountQuotaExceeded` | body 明写 **今晚 23:59:59 重置**（月度配额耗尽，非 5h 滚动） |
| 小米 `xiaomi` | ❌ `429 quota exhausted` | 与火山**同时**满 ⇒ 超额是后台任务总量问题，不是一家的事 |
| 腾讯 `tencent-tokenplan`（hy Token Plan） | ✅ **200** | `hy3` 实测可用，**付费组唯一没趴的一把钥匙** |
| opencode 免费组 | 部分可用 | 见 §1.1；8 个模型均 256K 上下文、均支持 tools/streaming |

### 1.3 真正的债：撞墙之后还在一直撞（**核心发现**）

`~/.config/coworker/logs/openworker-server.log`（608 行）中：

- **`AccountQuotaExceeded` 出现 28 次**，全部来自**同一个** `ai_circle_column`
- 从第 60 行一路刷到第 597 行，横跨整个日志周期
- **28 次全部打同一条已死的火山路，零次尝试切换**

⇒ **债的本质不是"缺备用钥匙"，是"撞墙后不收手"**。缺备用是设计问题，不收手是**行为缺陷**——
它把一次配额耗尽放大成 28 次无效重试（浪费额度、刷爆日志、拖慢 tick）。
⇒ **因此熔断的第一优先级不是"加 fallback"，是"撞 429 立刻停手并记账"**。

### 1.4 附带发现：`caps` 元数据缺"是否推理模型"

8 个免费模型的 `ModelCapabilities` 只有 `tools / vision / pdf / parallel_tool_calls / streaming`
五项，**没有"是否推理模型"**。实测 `fledge-alpha-free` 是推理模型（先吐 `reasoning_content`、
14.3s 才出 `content`），但 `caps` 里看不出 ⇒ **免费组要按速度排序，必须先补这一格元数据**。

### 1.5 动态侦探**没有**移植过来（萧哥 21:10 指出，实测确认）

>萧哥原话：「免费模型中文很稳，不稳的是**模型是动态更换的，某个下架又有新上架**。
> 这个不稳定因素，本地安装的 deepseek harness 插件解决了（它会动态侦探），
> 但小桔身上这套是从 harness 移植过来的，**我不知道有没有同时移植动态侦探**。」

**实测结论：没有移植。** 三条证据：

| 证据 | 内容 |
|---|---|
| **① 远端有列表端点，本地没接** | `GET https://opencode.ai/zen/v1/models` → **200**，返回 **86 个模型**，其中 `*-free` **13 个**。而本地无任何 catalog 机制（`~/.config/coworker/` 下只有 `openrouter_catalog.json`，**没有 zen/opencode 对应物**） |
| **② 对照 OpenRouter 已有完整机制** | `coworker/providers/openrouter_catalog.py` 是深证 harness 同款模式：远端 `/api/v1/models` 权威源 → 6h TTL 缓存（`openrouter_catalog.json`）→ 后台线程定时刷新 → 冷启动用内置 seed 兜底。**这套只给 OpenRouter 做了，opencode 完全没有** |
| **③ 静态清单的注释自证** | `matrix.py:279-284` 自述：「2026-10-06 重新铺货……**上游已下架（deepseek-v4-flash-free、jev-1.13）未入选**」——手工维护的痕迹 |

**已经漂移了**（21:10 实测对比，本地 8 个 vs 远端 13 个）：

- 本地有、远端已下架：**无**
- **远端新上架、本地没有（5 个）**：
  - `deepseek-v4-flash-free` —— **注释里明确写"已下架"的那个，现在又有了**
  - `jev-1.13-free` —— **同上**
  - `ling-3.0-flash-fin-free`
  - `muse-spark-1.2-contributor-free` / `muse-spark-1.3-contributor-free`
    （`matrix.py:283` 判为「区域封锁」而排除）

⇒ 手工铺货的保鲜期 = **几天**。下架的模型会一直留在 picker 里（用户切过去才发现），
新上架的要用手动改代码才能出现。**这正是深证 harness 的动态侦探要解决的问题，必须补上。**

## 二、方案总纲（萧哥 2026-06 21:04 拍板）

**两个总开关，组内自动切 + 手动切，本地与云端同一套。**

```
┌─ 付费组（默认）─────────────────────────────┐
│  1. 火山 ark-agent-plan-cn  （主）           │
│  2. 小米 xiaomi:mimo                        │
│  3. 腾讯 tencent-tokenplan:hy3              │
│  qwen ❌ 不进链（早期测试配置）              │
└──────────────────────────────────────────────┘
┌─ 免费组（后台通道）───────────────────────────┐
│  opencode *-free（动态清单 + 探活 + 自动轮替）   │
│  · 清单来源：远端 /zen/v1/models（§1.5，非硬编码）│
│  · 走伪装协议（_lane_headers + 门面工具 + 仅流式）│
│  · 排序：非推理优先（后台批量活要速度）           │
└──────────────────────────────────────────────┘
```

**手动切粒度 = A**：切「付费组 / 免费组」两个总开关，**组内自动排**。
（不提供"手动指定具体模型"——粒度 A 已够用，UI 更简单；需要时再加。）

**分工**：
- 她对你说的话（对话、主动递卡片）→ **付费组优先**
- 后台加工（理解加工 / 发帖草稿）→ **免费组优先**

**云端/本地同一份熔断表**：走 `~/.deskmate`（进 `SYNC_TABLES` 的那套），**不走各自本地**。
> 理由：记忆里"48 条身份分裂"的教训就是两套状态不一致的产物。本地熔断了、云端还在撞，
> 是同一类事故的另一种形态。

## 三、熔断表设计（§1.1 + §1.3 的直接结论）

### 3.1 粒度：`(通道, 模型)` + 调用维度

不是"模型级静态配额"，因为实测证明**同模型在长会话里可用、一次性请求里429**。
⇒ 熔断键：`(provider, model)`；**冷却时间由响应头/响应体解析，不写死**：

| 来源 | 解析字段 | 实测样例 |
|---|---|---|
| 火山 | `error.message` 内 `It will reset at <ts> +0800 CST` | `2026-10-06 23:59:59` |
| 小米 | `message: "quota exhausted"` | 无到期时间 → 走**默认退避** |
| opencode | 响应头 `retry-after`（秒） | `40332` ≈ 11.2h |
| 上游过载 | `503 Upstream error from Nvidia` | → 短退避（分钟级），非长熔断 |

### 3.2 停手而非重试（§1.3 的直接产物）

- 撞 429/配额类错误 → **记熔断 + 立即跳到下一条**，**禁止原地重试**
- 撞 5xx/网络类 → 允许**一次**短退避重试（不是无限重试）
- 每次熔断/跳通道都**留审计记录**（谁、什么时候、为什么跳、跳到哪）
  ⇒ 萧哥能一眼看出「今晚 20:40 因为火山+小米双超，后台 7 个任务未执行」，而不是
  各自 fail-open 成"今天没产出"（这就是 §1.3 那 28 次日志掩盖掉的信息）

### 3.3 落库位置

- 熔断表：`deskmate/llm_circuit_breaker`（**新表，进 `SYNC_TABLES`**）
  - 字段：`key(provider:model)` / `state(closed|open|half_open)` / `opened_at` /
    `cooldown_until` / `last_error_kind` / `last_error_detail` / `strike_count` / `source_node`
  - 触发器自动进 oplog → 两端自动收敛（§二 云端/本地同一份）
- 审计日志：本地 `~/.deskmate/llm_channel_audit.jsonl`（**不同步**，各端本地簿记）
  - 理由：审计是"本端发生过什么"，跨端同步会互相污染

### 3.4 免费模型动态清单（补移植深证 harness 的「动态侦探」，§1.5）

**完全复刻 `openrouter_catalog.py` 的模式**，只为 opencode 再做一份
（新模块 `coworker/providers/zen_catalog.py`，**不改动 openrouter_catalog.py**）：

| 机制 | 做法 |
|---|---|
| **权威源** | `GET https://opencode.ai/zen/v1/models`（实测 200/86 个）→ 过滤 `id.endswith("-free")`（实测 13 个） |
| **缓存** | `<state_dir>/zen_catalog.json`，TTL **6h**（与 openrouter 一致） |
| **刷新** | 后台线程每 6h 拉一次；设置页请求**永不阻塞网络**（读缓存即返回） |
| **冷启动** | 缓存缺失时后台一次性拉取 + 立即返回内置 seed（**seed 沿用 `matrix.py` 现有 8 个**，仅作离线兜底，永不作为真相源） |
| **兜底** | 网络不可达且无缓存 → 用 seed，保持 picker 不空 |
| **与熔断联动** | 清单刷新时**顺带清理**熔断表里已下架模型的记录（否则熔断表会无限膨胀；且下架模型不该再参与轮替） |

**关键：免费组从「硬编码 8 个」变成「远端清单驱动」。**
新增模型自动出现、下架模型自动消失 —— 这才是深证 harness 解决的那个不稳定因素。

>⚠️ **一处要照抄一处不要照抄**：openrouter 的免费档是**白名单制**
> （`FREE_TIER_ALLOWLIST_EXACT`，因官方 `pricing=0` 的模型大量不可用）。
> opencode 不用白名单 —— 远端 `*-free` 列表本身已足够干净（13 个里 5 个是区域/上游问题），
> 用「远端清单 + 探活」代替白名单更简单，且新模型能自动进来。

## 四、免费组的特殊约束（踩过的坑，逐条写死）

来自 §1.1 的三次失败探测：

1. **不能手搓 HTTP**：必须经 `coworker/providers/opencode_provider.py` 的伪装协议
   （`_lane_headers(_derive_ids(msgs))` + `_apply_free_lane_gate(tools)`）
   否则 403 `FreeTierError: "free tier can only be used from within OpenCode"`
2. **必须 `stream: True`**：免费通道只收流式（`complete()` 内部聚合流）
3. **门面工具 + `tool_choice`**：`had_real_tools=True` 时**不能**设 `tool_choice:"none"`，
   否则可能不通
4. **推理模型先吐 `reasoning_content`**：只读 `content` 会误判「200 但空」
   （`fledge-alpha-free` 实测14.3s；UI 上表现为"思考过程"）
5. **403 与 429 语义不同**：`FreeTierError`(403) = 该模型对匿名免费层不可用（长期）；
   `FreeUsageLimitError`(429) + `retry-after` = 额度窗口（会恢复）⇒ **熔断时长区别对待**
6. **模型会下架/上架子**（§1.5）：清单硬编码会漂移（实测已漂 5 个）⇒ 走 §3.4 动态清单

## 五、实施顺序（等 2026-06-06 23:59 火山重置后一次性做）

> **今晚不实施**：三条通道里两条趴着（21:00 时只有 hy3 通），改完也验证不了自动切换效果。
> 与萧哥约定：今晚只定设计 + 留结构，23:59 后实施 + 验收。

| # | 步骤 | 验收 |
|---|---|---|
| 1 | **`zen_catalog.py`（§3.4 动态清单：远端拉取 + 6h 缓存 + 后台刷新 + seed 兜底）** + 单测 | 拉到 13 个 `*-free`；缓存命中不阻塞；网络不可达退回 seed；**清单刷新时清理已下架模型的熔断记录** |
| 2 | `llm_circuit_breaker.py`（熔断表 + 错误解析 + 停手逻辑）+ 单测 | 错误解析覆盖 4 类（火山 reset / 小米 exhausted / opencode retry-after / 503）；**撞墙不重试** |
| 3 | `llm_circuit_breaker` 进 `SYNC_TABLES` | 两端建表 + 触发器 + md5 对齐 |
| 4 | 通道组配置（付费组 3 把/ 免费组**远端清单驱动**）+ 组内自动排 | 火山熔断 → 自动切小米 → 切 hy3；全熔断 → 落审计不静默 |
| 5 | 两个总开关接进设置面板（手动切） | 切组即时生效；组内自动排不受影响 |
| 6 | 后台任务改走免费组（`llm.py` 的 `memory_llm_available` 路径） | 理解加工在免费组可用时走免费；不可用时记审计而非标 failed |
| 7 | **§1.3 验证（验收锚点）** | 人为让火山 429 → 日志**不再出现重复重试**，而是熔断 + 切通道 + 一行审计 |
| 8 | **§1.5 验证（保鲜期验证）** | 下架一个远端模型 → 清单刷新后自动从 picker 消失；新上架一个 → 自动出现。**不用改代码** |
| 9 | 云端对齐 + 双端重启 | 云端全部文件 md5 一致；云端同样具备熔断表 + 动态清单 |

**两条验收锚点**：
- **§1.3**（第7 步）：日志里若还出现 28 次同路重试，说明熔断没生效，方案失败。
- **§1.5**（第 8 步）：若下架模型仍留在 picker、或新模型要改代码才出现，说明动态侦探没生效，方案失败。
