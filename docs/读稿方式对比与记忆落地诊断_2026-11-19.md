# 读稿方式对比与记忆落地诊断（2026-11-19）

> 两个问题：① 小桔说"记住了"，下次还会犯吗？② 小桔 vs Hermes 读稿的差距在哪？
> 只读检查，不改代码。

---

## 0. 结论先行

1. **会记住，但"记住"不等于"下次按它做"——这是差距的核心。**
   规矩已经写进三处，而且其中一处（`MEMORY.md §纠正`）是**每轮无条件注入**的。所以下次对话模型一定能"看到"这条规矩。但这次它也看到了（规矩在 11-19 之前就存在于技能里，本次是二次纠正），仍然犯——说明问题不在"记没记住"，而在**执行链路**：技能按需加载、规矩是散落的文字而非强制流程。

2. **小桔 vs Hermes 的差距不在"模型能力"，而在"读稿是不是一条强制、结构化的流程"。**
   Hermes 那边读稿有明确的 step（先通读建人物/情节模型 → 再抠字），而小桔这边，读稿行为由模型在通用 agent loop 里**自由发挥**，规矩只是"注入的文本"，没有一个结构把它们变成不可跳过的流程。

## 1. 问题一：记住了，下次还会犯吗？

### 1.1 规矩确实记下了（实证）

`~/.deskmate/MEMORY.md` 的 `§ 纠正` 段（2026-11-19 当日二次修正）明确写了：

> 读与抠分开两件事做——先通读、把人物动机和情节走向吃透；若需要抠字句细节，是读完之后另一回事，绝不边读边逐字细抠，那是死读书。此为 11-16「小说第一是人、第二是事、最后核史实」同一病根的再次纠正。

并且 `behavior_log.jsonl` 有 `correction` 事件记录。

### 1.2 这条会被每轮注入（实证）

源码：`deskmate/memory/manager.py:181` `CORE_TAGS = {"preference", "correction"}`；`:599 _get_core_memory()` 把 correction 段**每轮无条件注入**。

实测：调用 `_get_core_memory()`，这条"读与抠分开"确实出现在输出里（Core 注入 860 字）。

**所以下次对话，模型眼前一定有这条规矩。**

### 1.3 但为什么这次还是犯了？——三个执行层原因

| 原因 | 证据 | 后果 |
|---|---|---|
| **① 技能是"按需加载"，正文不在每轮上下文里** | `coworker/skills/base.py:3-6`：会话开始只注入 name+description（progressive disclosure），正文要模型自己 `load_skill` 才看到 | 规矩全文（`novel-review.md` 里那段）模型这轮**未必加载**；只注入了 Core 里那一条浓缩版 |
| **② 技能 description 把读稿引向"检查"而非"理解"** | `novel-review.md` description：「**检查**历史官称准确性、人物关系一致性、对话风格…」；trigger：「审校章节、检查小说、帮我看看这段」 | 模型一看到"审校/检查"就进入**校对模式**（逐字找错），正好是要避免的"死读书" |
| **③ 规矩是文字，不是流程闸门** | `engine.py` 的 agent loop 没有任何"读稿必须先通读后抠字"的结构性约束 | 模型可以一边读一边抠，没人拦得住；规矩只是"建议"，不是"必须按顺序执行的步骤" |

另外还有一个反向指引：`writing_context.py:261` 原本写"读 docx 用 officecli view"（本会话已改成优先 perception 工具），这类散落的指引会稀释主规矩。

### 1.4 判断

**下次还会不会犯？**

- 短期：那条 Core 规矩会每轮注入，模型"知道"这条规矩的概率很高，**再犯的概率比没记时低**。
- 但**不能保证不犯**——因为这次就是"知道规矩却仍犯"的实例。只要读稿还是"自由发挥 + 校对导向的技能描述"，模型就可能在长文读稿中途滑回逐字细抠。
- 真正能降低复发的是**结构改造**（见 §3），而不是再记一条。

## 2. 问题二：小桔 vs Hermes 的差距在哪

### 2.1 不是模型能力的差距

两者用的是同类模型（甚至可能同一个）。差距在**任务编排方式**。

### 2.2 具体差距（可从源码推断的部分）

| 维度 | 小桔（本项目） | Hermes（对照，项目里有多处借鉴痕迹） |
|---|---|---|
| 读稿流程 | 通用 agent loop，模型自由决定"读哪段、怎么读、读几遍" | 项目里借鉴了 Hermes 的 compaction/cooldown/learning_graph 设计（`engine.py:46,953`、`compaction.py:418`、`app.py:3663`），说明 Hermes 有**显式的结构化流程** |
| 技能加载 | progressive disclosure，正文按需加载，可能这轮没加载 | 读稿是固定流程，步骤不可跳 |
| 技能描述导向 | "检查/审校"→ 校对模式，逐字找错 | 先建"人物动机/情节走向"的理解，再抠字——**先理解后细节的顺序被固化在流程里** |
| 中间产物 | 读稿结果散落在对话里 | 先形成"人物动机模型"这类结构化中间产物，后续抠字基于它判断 |

### 2.3 一句话差距

**Hermes 把"先理解人、后抠字"做成了流程（do A then B），小桔把它做成了知识（know A before B）。**

知识会被模型"知道但做不到"——这次就是活例子；流程则会强制模型按顺序产出——所以 Hermes 读完条理清晰，既懂动机又能挑错别字。

## 3. 建议（怎么让小桔不再犯，且缩小差距）

> 待 Owner 拍板。核心思路：把"先理解后抠字"从**文字规矩**升级为**结构化流程**。

### A. 改技能导向（最小、零风险）

把 `novel-review.md` 的 `description` 和 `trigger` 从"检查/审校"改成"读稿理解优先"：

```
description: 读萧盛小说章节——第一遍通读建人物动机与情节走向，第二遍才抠字句笔误
trigger: 读稿、读这段小说、帮我看看这段（先理解再抠字）
```

让模型看到技能名就进入"理解模式"而非"校对模式"。

### B. 把"读稿两段式"做成强制流程（中等改动，收益最大）

在读稿相关路径（如 skill 的 SKILL.md 正文、或专属工具）里固化两步：

```
Step 1（必须）：通读 [start,end] 全文，产出「人物动机清单 + 情节走向」两段文字。
Step 2（可选，仅在 Step1 完成后）：逐字抠笔误，且只标明显写错的词/字。
禁止在 Step1 完成前输出任何字词级疑点。
```

这样"先理解后抠字"从建议变成不可跳的顺序。

### C. 复用 Core 规矩的注入位（零风险）

既然 `MEMORY.md §纠正` 已每轮注入，可把那条浓缩规矩补一句"读稿时必须先输出人物动机理解，再抠字"，让它从"知道"更接近"动作"。但这仍是文字，效果弱于 B。

### D. 本次纠正本身要不要再强化？

**不需要再记一条**——同样内容记三遍（MEMORY/技能/USER）已经够了。再记只会稀释。要改的是执行链路（A/B），不是记忆内容。

---

## 4. 复核方法

下次读稿任务后检查：

- 模型是否**先**输出了人物动机/情节走向的理解（Step 1），**再**列笔误（Step 2）；
- 是否还出现"先判断他是不是在撒谎/贴金"这类校对框；
- 若仍逐字细抠开场，说明流程未生效，需回到 B。
