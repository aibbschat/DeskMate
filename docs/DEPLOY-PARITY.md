# 部署一致性铁律（最高优先级）

> 记于 2026-10-05，源于 xj.aibbs.chat 个人中心全 0 事故。

## 规则

**本地和云端使用同一份代码、同一个构建流程、同一个构建产物来源。**

1. **一份源码** — 仓库里只有一份。本地不得持有云端专属补丁，云端也不得持有只有它改过的副本。
2. **一条构建命令** — 两边跑同一个构建，用同一个配置文件，不允许任何一边有专属改动。
3. **无构建期注入** — 禁止把环境值（token、URL、端口）用 VITE_ 前缀变量烤进 bundle。环境差异必须在**运行时**解析，而不是在**构建时**烧死。
4. **同一个产物** — 云端部署的就是本地构建出来的 dist/，字节一致。不是在云端重新构建一次。
5. **双向同步** — 本地改了同步到云端；云端改了（配置、数据）也同步回本地。不允许单向漂移。

## 为什么

烤进 bundle 的环境值会让云端产物和本地产物**不可复现**：

- 下次本地更新代码，构建出来的包 ≠ 云端正在跑的包，两者无法互相生成。
- 差异只增不减，最终没人说得清云端跑的是哪版代码。
- 环境值只能靠重新打包才能改——一个本该几秒的运维动作变成一次发布。

2026-10-05 就是这么坏的：云端 bundle 里 token 被写死，本地构建却是空的（生产构建的 DEV token 恒为空字符串）。两边天生对不上。

## 正确做法

环境差异只允许在**运行时**解析，按优先级：

1. window.__COWORKER_* 全局变量 — 运行时注入，桌面壳（Tauri）用这个
2. 页面同源路径 — Web 部署走这个，由反向代理（Caddy/nginx）转发到 sidecar
3. 构建期值 — **只用于纯本地开发**（npm run dev 的 127.0.0.1:8765），绝不允许出现在部署产物里

token 属于运行时环境，不是构建参数。

## env 文件规约（2026-10-09 事故补充）

本地 dev 需要的构建期值（如 `VITE_COWORKER_HTTP=http://127.0.0.1:8765`）**只允许写在
`.env.development.local`**（mode=development 才加载，`vite build` 不碰它）。

🔴 **禁止创建 `.env.local` / `.env` / `.env.production*`**。Vite 的 `.local` 后缀语义是
"本地私有、不入库"（gitignore），**不是"只在 dev 生效"**——它对**所有 mode（含 production
build）都加载**。2026-10-09 事故：有人把 dev 值写进 `.env.local`，`vite build` 照样加载它，
define 成字面量烘进 bundle，httpBase 的浏览器同源分支被 minifier 当死代码删除 → 云端所有
HTTP API 打到访客本机 127.0.0.1:8765 → 全息屏/个人中心/信箱全空，且构建、部署全程无任何报错。

Vite env 加载矩阵（build 时全加载 ≠ dev 时全加载，方向恰恰相反）：

| 文件 | dev 模式 | build 模式 |
|---|---|---|
| `.env` | ✅ | ✅ |
| `.env.local` | ✅ | ✅ ← 毒点 |
| `.env.development` / `.env.development.local` | ✅ | ❌ 唯一安全位 |
| `.env.production` / `.env.production.local` | ❌ | ✅ 禁用 |

双保险（`vite.config.ts`）：env-guard 插件在 build 时发现上述禁用文件定义了
`VITE_COWORKER_HTTP` 直接构建失败；closeBundle 断言产物 httpBase 必须保留 `?"":` 同源
分支特征。两道都已实测能拦截复发，**不要删除**。

## 落地约束

- 云端 /etc/openworker/env 里的 token 与本地配置必须一致，改一处就要改另一处。
- 部署脚本保证「云端跑的就是本地 dist/」，**不允许在云端构建**。
- 任何「只在云端生效」的 hack（改 bundle、注入脚本、改产物）都视为事故隐患。

## 自查清单

- [ ] 本地和云端的差异只有配置和数据，没有逻辑差异吗？
