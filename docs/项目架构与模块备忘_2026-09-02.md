## 小桔日记（灵感阈值驱动 + 一天可多则）

模块 `deskmate/growth/diary_inspiration.py`，纯规则零 LLM，挂在 tick 的 **idle 判断之前**
（她自己动笔，不需用户在场）。萧哥定调：**不能定时触发写废话**、**不要限死每天一条**。

- **素材账本** `diary/materials/YYYY-MM-DD.jsonl`（指纹 `ts|kind|subject` 去重增量 sync）。
  存在理由：`recent_events` 落盘截断到 **50 条**是易失窗口，一天 28 条、两天就能挤没。
- **加权 + 单类封顶 6.0**：里程碑 4.0 / badge 3.5 / 反思 3.0 / 协作 2.0-3.0 / 日常 1.0-1.5 /
  痕迹 0.5 / depth_backfilled 0。封顶是关键——批量导入 15 条记忆或 11 个技能进化只是
  **一次批处理**，不该当成 15 件值得写的事。
- **门槛**：第一则 5.0，后续各则 4.0；**60 分钟冷却**防集中涌入连刷；**不设单日上限**。
- **素材按则消费**：写进第 N 则的素材打 `entry=N`（`consume`），只有未消费素材才计分与渲染
  → 第二则只讲后来的事。**手动路径 `ensure_today()` 写完也必须 consume+mark_entry**，否则
  自动路径会把同批素材再写一则（日记里出现两遍一样的话）。
- **多则形态**：同文件多个 `## HH:MM` 小节（`append_entry` 追加，绝不覆盖）；时间戳取
  **素材里最晚事件的时间**（不是落笔时间，否则补记全挤成一个点）；开场白按时段
  （上午/下午/入夜）；落款与「我更懂你了」只在第一则；`entry_count` 兼容旧格式——
  **首个小节标题之前有正文就另算一则**（旧日记追加后序号错乱，实测踩到）。
- tick 返回加 `diary` 负载；`GET /v1/deskmate/diary/inspiration` **必须注册在
  `/diary/{date}` 之前**，否则被通配吃掉。返回 entries_today/pending_score/threshold。
- **两套「日记」别混**：A「小桔日记」= `~/.deskmate/diary/YYYY-MM-DD.md`，DiaryWriter 零 LLM
  渲染；B「我们的日记/MomentFeed」= DB `user_posts`（萧哥写，小桔留言，🩷落 loved_entries）。

## 创作流水线（deskmate/creation/）

`pipeline.py` 编排（大纲→剧本→定稿，PipelineGuard 串行门禁）+ `executor.py` 双执行器
（Stub 零 LLM / LLM 真调用）+ `service.py` 注册表恢复 + `final_review.py` 圆桌终审 +
`novel_index.py`。HTTP 在 `deskmate/roundtable/web.py`（`/api/creation/*`）。

- 分集模式（episodes>1）：每集独立建项/撰写/审核/拍板/导出（docx 键「第X集」）；
  `_next_episode`=最小未定稿集；跨集前情摘要 `_episode_summaries` 随草稿原子落盘可恢复。
  episodes<=1 走全本单文件。
- **坑**：注册表 JSON 落盘把分集 dict 的 int 集号键变字符串，`_restore_pipeline` 必须
  归一化回 int，否则重启后按集操作 KeyError。
- 制作要求强约束：style/pacing/episodes/episode_range 全链透传 + `_requirement_block`。
  MCP 用逗号分隔字符串传 style/episode_range。
- 打回闭环：打回→重写→重审→拍板（产出项非 review 直接定稿须中文报错）。终审=知情批准：
  proposal 四要素→选专家→SSE 研讨→synthesis→apply 回灌。
- 加集续写 `extend_episodes`（9a3a12c + b682963）：新增集号建项、既有集不动；守卫=大纲已
  定稿 + 仅分集模式。前情档位 `prior_context`：summary / summary_recent（默认，摘要+紧邻
  上集定稿全文）/ include_review_notes（默认开）。圆桌研判全文只存 200 字截断。

## 史料检索（coworker/history/）

- 数据 `~/.deskmate/history/`：`duan-dai-shi.db` 1.2G / 211 篇（正史+演义+文总集）；
  `shibu-shi.db` 583M / 史部 30 篇。
- 服务器 `ssh ai-circle-server`（root@212.64.18.62，库在 `/root/data/disk/ai-experts-data/`）。
  **仅 1G 可用内存，不可在服务器端重建 FTS5（会 OOM）**；带宽 4-5Mbps，大文件必须流式 gzip 传。
- 更新流程：服务器导出裸表（剥 `articles.content` / `chunks.fts_content`）→ `ssh "gzip -1 -c"`
  流式传 → 本机 `scripts/build_history_index.py <db>` 重建 FTS5（复刻灌库侧 tokenizeCJK
  字间插空格）。
- 结构：普通 FTS5（`fts5(content,heading,tokenize='unicode61')`），`rowid == chunks.id`。
  四级降级：exact → trigram → bigram → char AND；排序键 `(非精确, 档位, 覆盖率, sourceOrder)`；
  返回体带 `exact`/`matchTier`。
- 简繁变体（1d2a0bc）：语料简繁混排，每档都把查询词简/繁两形**各自成短语 OR**（绝不串接，
  串接会造出「项 羽 項」）；char_and 档=变体内 AND、变体间 OR；`exact` 与 coverage 排序
  **逐变体取最优**；返回体 `matchedForm`，要求模型照录原文不得自行转简/转繁。用
  `coworker/history/vendor/opencc/`（Apache-2.0，纯 Python）。**zhconv 禁用**：字典
  `zhcdict.json` 衍生自 MediaWiki 按 GPLv2 授权，传染性，进不了 MIT 仓库。必须用**词组字典**
  而非单字查表（一简对多繁）：万历→萬曆、历法→曆法、头发→頭髮。
- 待办（待确认）：按 `articles.category` 做可靠度分层排序，演义打「非史料·小说家言」标记。
