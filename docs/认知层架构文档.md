# 认知层（Cognitive Layer）架构文档

> 从"懂我"到"像我"的关键跃迁。
> MVP 版本：认知画像数据结构 + 增量更新 + 认知提取管线 + 冷启动 + 后端 API + 前端展示 + auto_tasks 集成。
> 第二期（接口已留好）：深度访谈引擎、认知验证引擎（认知 Turing test）、隐性知识提取器、记忆注入器。

## 一、设计哲学

### 从"懂我"到"像我"

"越用越懂你"是基础——AI 学习你的偏好、习惯、风格，更好地服务你。
"越来越像我"是跃迁——AI 理解你的思想、立场、价值观、思维方式，能在新情境下像你一样思考和决策。

认知层就是这个跃迁的核心技术。

### 三阶段框架

1. **懂我（Understand）**：知道你的偏好、习惯、风格（现有能力）
2. **像我（Embody）**：理解你的思想、立场、价值观、思维方式（认知层 MVP）
3. **成为我（Inherit）**：继承你的意志，做你未竟之事（第二期+，深度访谈+验证+记忆注入）

### 五个维度

认知画像不是一堆文本，而是五个结构化的维度：

| 维度 | 说明 | 例子 |
|---|---|---|
| **立场图谱** | 你对各类问题的明确观点 | "历史小说必须有主题内核" |
| **论证模式** | 你习惯怎么分析、怎么说服 | "用历史类比+制度推演，拒绝自媒体单源" |
| **价值观排序** | 冲突情境下你的优先级 | "史料真实 > 叙事流畅 > 戏剧效果" |
| **思维框架** | 你分析问题的习惯性路径 | "制度背景 → 权力结构 → 人物选择 → 后果" |
| **认知盲区** | 你还没明确表达过的领域 | "对 AI 创作的立场（待访谈澄清）" |

每个维度的条目都有：唯一 ID、内容、来源（可追溯）、置信度、变化历史、状态（active/superseded/questioned）、标签。

## 二、模块架构

```
deskmate/cognitive/
├── __init__.py          # 公共接口导出
├── models.py            # 数据模型（五个维度 + 来源 + 历史）
├── profile.py           # 画像管理（加载/保存/增量更新/变化检测/矛盾检测/用户校准）
├── extractor.py         # 认知提取管线（LLM 驱动，多层解析，结构化输出）
├── cold_start.py        # 冷启动（从已有 vault/MEMORY/style_profile 快速提取初始画像）
└── interfaces.py        # 扩展接口（第二期：访谈/验证/隐性知识/记忆注入）
```

### 数据持久化

```
~/.deskmate/cognitive_profile.json
```

单个 JSON 文件，包含五个维度的所有条目 + 元数据（提取次数、校准次数、摘要）。

## 三、核心机制

### 1. 增量更新

新提取的认知特征不会直接覆盖旧的，而是和已有画像对比：

- **新立场** → 添加
- **已有立场的补充** → 更新来源和置信度（多来源支持提高置信度）
- **立场变化** → 旧立场标记为 superseded，保留历史，添加新立场
- **立场矛盾** → 两者都标记为 questioned，生成认知盲区（待访谈澄清）

### 2. 变化留痕

每次更新都记录历史（created/updated/superseded/questioned/calibrated），支持回溯。这意味着你可以看到"它什么时候开始理解这个观点的""什么时候因为你的校准而改变的"。

### 3. 用户校准

用户可以直接纠正认知画像中的错误。校准是最有价值的认知数据——因为它是用户直接表达的，置信度最高（+0.2，上限 0.95）。

### 4. 认知提取管线

从文本中提取认知特征，用 LLM 做多层解析：
- 输入：文本 + 元数据（来源/类型/日期）
- LLM prompt：要求从文本中提取五个维度的认知特征，每个特征附原文证据
- 输出：结构化 JSON
- 增量更新：通过 profile manager 写入画像

### 5. 冷启动

不需要重新读所有书，从已有结构化数据中快速提取初始画像：
- vault/preferences → 创作立场和价值观
- vault/corrections → 思维框架（用户纠正 AI 的方式反映思维方式）
- MEMORY.md → 论证模式和历史细节要求
- style_profile → 表达习惯和语言风格

冷启动的置信度较低（0.5-0.6），需要后续每日读书的认知提取和用户校准来提高。

## 四、后端 API

| 端点 | 方法 | 说明 |
|---|---|---|
| `/v1/deskmate/cognitive/profile` | GET | 获取完整认知画像 |
| `/v1/deskmate/cognitive/stats` | GET | 获取统计摘要（前端栏目用） |
| `/v1/deskmate/cognitive/extract` | POST | 从文本中提取认知特征，增量更新 |
| `/v1/deskmate/cognitive/calibrate` | POST | 用户校准（纠正错误） |
| `/v1/deskmate/cognitive/gaps` | GET | 获取认知盲区（第二期访谈引擎输入） |
| `/v1/deskmate/cognitive/cold-start` | POST | 触发冷启动 |

## 五、前端展示

「它眼中的我」第 8 个栏目「🧠 它理解的我」：

- 顶部统计：已理解 N 条认知特征（立场 X 条、论证 X 条、价值观 X 条、思维框架 X 条）
- 文章列表：每个认知特征一条朋友圈式文章，展示内容 + 置信度 + 来源
- 可展开查看：变化历史、所有来源、原文证据
- 用户校准：点击"不对"可以直接纠正（调用 calibrate API）

## 六、与 auto_tasks 集成

每日读书任务读完一本书后，调用 auto_tasks record API 时传 `extract_cognitive: true`，自动触发认知提取：

```json
POST /v1/deskmate/auto-tasks/record
{
  "task_type": "daily_reading",
  "target": "17-明朝的裂变",
  "action": "finish",
  "summary": "...",
  "detail_content": "完整的读书心得...",
  "extract_cognitive": true
}
```

recorder 会在保存记录后，自动调用认知提取管线，从 detail_content 中提取认知特征，增量更新认知画像。

这意味着：**每日读书任务不只是沉淀摘要，还在持续深化它对你的理解。** 读的书越多，认知画像越厚，它越像你。

## 七、第二期扩展（接口已留好）

### 深度访谈引擎（InterviewEngine）

基于认知盲区和 questioned 状态的条目，生成有结构的深度访谈问题，通过苏格拉底式追问挖掘用户的深层认知。访谈结果是最高质量的认知数据。

### 认知验证引擎（ValidationEngine）——认知 Turing test

生成用户没遇到过的具体情境，让 AI 以用户身份回答，然后和用户的实际回答对比，评估"像我"的程度。验证结果反过来更新认知画像。

### 隐性知识提取器（TacitKnowledgeExtractor）

提取显性知识之外的隐性知识：语感、节奏、叙事直觉、人物塑造的微妙手法。这是另一条技术路径，和认知提取并行。

### 记忆注入器（MemoryInjector）

当前 MVP 阶段，认知画像只做展示和后台积累，不注入对话上下文。第二期实现注入器，在合适的时机将相关认知条目注入 LLM 上下文，让 AI 在对话中真正"像你一样思考"。

注入策略：基于当前话题检索相关认知条目，高置信度优先，标注"这是用户的认知"避免混淆为通用知识。

## 八、诚实边界

1. **冷启动的质量有限**：从已有数据中规则提取的认知特征比较浅，需要后续 LLM 驱动的认知提取和用户校准来深化。
2. **认知提取依赖 LLM 质量**：LLM 可能过度解读或提取错误，需要用户校准机制来修正。
3. **"像我"是渐进的**：不是非黑即白，它会在某些方面像你，在某些方面不像。置信度反映了这种不确定性。
4. **MVP 不注入对话**：当前认知画像只做展示和后台积累，不影响对话行为。第二期实现记忆注入后，才会真正在对话中"像你"。
5. **隐私**：认知画像是最核心的个人数据，本地存储，不上传云端。
