## 一、一句话结论与战略定位

**墨灵的「懂你」地基已经比国内外绝大多数同类产品都深**——分层记忆（SOUL/USER/MEMORY/longterm/vault/圣经）、成长调制（亲密度/信任/默契度真实改变行为）、反思落盘、主动层、学习图谱、徽章体系一应俱全。但打磨的关键不在「再搭一层记忆」，而在 **三条断链 + 多处半截**：

1. **写入→生效断链**：`DESKMATE_AUTO_INJECT` 是 opt-in，记忆很可能根本没被注入（写了但没用上）；`DESKMATE_PROACTIVE_BACKGROUND` 因 `run.py` 的 env 注入死结，连设了都 off（后台主动性根本没活）。
2. **反馈→成长断链**：`trust` 恒为 0.5（默认值），用户对主动建议的接受/拒绝没回流成「信任感」，「越用越懂」的反馈闭环没闭合。
3. **懂你→被看见断链**：用户很难直观看到「你记住了我什么、改变了什么」，也没有「因为你说过 X，所以……」的引用回显，「懂」没有体感。

**战略护城河定位**：`长期记忆 × 主动陪伴 × 桌面常驻 × 合规轻陪伴`。
**弯道超车空白位**：① 桌面常驻 + 跨应用「看见你在做什么」的主动陪伴；② 长期记忆 × 连续情感关怀；③ 统一本地优先「数字分身」记忆层；④ 合规框架下的轻陪伴桌宠。

把这三条断链补上，再把几处半截（curator 只报告不清理、learning_graph 静态、无云同步、无密钥兜底、表情/感知层未真做）补完，对齐竞品已验证的「时间感知记忆、记忆即时间线、自动提炼、打扰分寸」四机制，就是本轮打磨的全部重点。

## 三、国内外同类产品对标

### 3.1 国外：四大已验证范式

- **① ChatGPT Memory（双层 + Dreaming 后台提炼）**：显式 saved memories（可见可编辑可删）+ 隐式从历史学模式；2026-06 Dreaming V3 异步后台综合对话、自动合成/更新记忆、**时间感知重写**（「7 月去新加坡」到点重写）、自动解决矛盾。启发：后台自动提炼、时间感知、记忆可见可编辑。
- **② Claude + MCP 记忆生态**：事实层 Global/Project/Personality 与 SOUL/USER/项目记忆同构；知识图谱式记忆与「圣经实体库」同源；**规则强制注入**（hook 每轮注入 mandatory/forbidden）防 context 压缩遗忘 → 我们 SOUL 护栏可借鉴强注入。
- **③ Mem0（记什么标准 + 四操作）**：只记偏好/领域约束/过去决策/反复挫败/身份事实；写入用 **ADD/UPDATE/DELETE/NOOP**——语义等价→更新旧条（治重复病根）、矛盾→删旧立新、无价值→NOOP；**记忆是时间线不是单一画像**。
- **④ Zep / Graphiti（时序知识图谱）**：每条事实带时间，「从伦敦搬到东京」是状态变化非矛盾；专门解决记忆过时/自相矛盾。
- 旁证：Sudowrite Story Bible + 2 万字记忆，与「圣经」同构，验证「书有自己的记忆」是行业共识。

### 3.2 国内：机会大于威胁

- **豆包/Kimi**：豆包记忆可逐条查看/删除、自然语言管理（「请记住我喜欢甜品」）；Kimi 记忆空间单独训练模型判断「什么值得记」、「更正：我搬到纽约了」替换旧记忆。
- **关键结论**：国内大厂「放弃全局个性化」——个性化停留在换形象/声音/主题的表层，**没把记忆做进系统级行为调制**。这恰是墨灵差异化空档：我们已有亲密度→语气、默契度→记忆预算、信任→主动阈值的真实调制。

### 3.3 桌宠赛道（最直接竞品，也在做「越用越懂你」）

- **Doki**：打怪升级 Lv.12，摸摸头/喂饭/专心工作涨经验——与成长/徽章同思路。
- **OpenDesktop-Pet**：主动互动前先判「现在适合打扰吗」（专注/空闲）+ 长期记忆——**打扰分寸 + 记忆**两件套。
- **星尘 Stardust**：三层记忆（短→中→长）+ Mem0 云端持久化 + RAG + Live2D 六维情感——「记忆 + 情感表达」与我们最近。
- **Sion**：三层记忆 L0 会话缓冲 / L1 情感日记(每 4h) / L2 原子事实(每轮提取 + 艾宾浩斯遗忘)——带遗忘曲线。
- **QQ 宠物复活**：接混元 Hy3，性格可选、主动回应、**以第一人称写日记留存日常**——「桌宠有自己的日记」增强伙伴感，我们 daily/ 已有雏形。
- 结论：桌宠赛道整体补「记忆+成长+主动+情感」，但**没一家把「创作专业度」做进去**——这正是我们（圣经考据+圆桌专家+创作流水线）的护城河。

### 3.4 写作赛道

- 长篇 AI 小说工具普遍做：人设一致性、风格学习（`/style-learn` 风格实验室）、Story Bible——验证创作场景需「越写越懂你的书」。

### 3.5 我们的弯道超车空白位

1. **桌面常驻 + 跨应用「看见你在做什么」的主动陪伴**——Limitless 因合规退场，国内几乎空白。
2. **长期记忆 × 连续情感关怀**——有记忆的偏被动、有主动的记忆浅。
3. **统一本地优先「数字分身」记忆层**——各产品记忆孤岛。
4. **合规框架下的「轻陪伴桌宠」**——官方智能体下线、用户仍要桌宠 → 机会点。

## 四、精细化打磨建议（整合分层 + 落地）

> 原则：**不新增体系，只补断链、补半截**。每条标注：现状 → 问题 → 借鉴 → 落地。

### P0 · 让「懂你」真正生效（止血，1 周内）

**P0-1 记忆注入默认开启 + 状态可见** 【断链#1】
- 现状/问题：`DESKMATE_AUTO_INJECT=1` 才注入，否则返回空串；91 条记忆很可能每轮没用上。
- 借鉴：ChatGPT 96% 记忆自动触发；国内大厂记忆默认开。
- 落地：① 启动自动注入改为默认开（加设置开关 UI，不再依赖环境变量）；② StatusPanel/MemorySection 显示「记忆注入已开启」状态。

**P0-2 修 `run.py` env 死结，让后台主动性真正活** 【断链#2，A 独有】
- 现状/问题：`PROACTIVE_BACKGROUND` 靠 `os.environ.get` 运行时读，`run.py` 的 loader 未把 `.env` 灌进 `os.environ` → 设了也 off。
- 落地：① 在 `run.py` 启动期从 `.env`/配置可靠载入该 flag；② 默认开启并加「防睡死」心跳（无前端轮询也常驻感知）。*预期：主动环首次真正闭合。*

**P0-3 打通「反馈 → 信任/成长」闭环** 【断链#3】
- 现状/问题：`trust` 恒 0.5；`record_suggestion_feedback` 有接口没接全。
- 借鉴：Mem0 UPDATE/DELETE 冲突解决；ChatGPT 记忆随纠正自动更新。
- 落地：① 把「主动建议接受/忽略」「打回重做」「明确纠正」三类事件统一记入 trust 计算（正负加权）；② trust 变动前端可见（原因+数值）；③ 对话里说「不对/别这样」时除写 correction 记忆，同时触发 trust/默契微调。

**P0-4 让「懂你」被看见——记忆引用回显 + 记忆面板** 【断链#9】
- 现状/问题：记忆在注入、成长在涨，但回复无「因为你说过……所以……」引用，用户无体感。
- 借鉴：ChatGPT「根据你的记忆」提示；豆包记忆面板逐条查看。
- 落地：① 当某条记忆被实际引用时回显「（因为你 8/1 说过只查正史，所以排除了自媒体来源）」；② 做「记忆面板」：列出 AI 记住了什么（分类/可编辑/可删/可导出），把 USER.md/MEMORY.md 可读性产品化。

**P0-5 记忆去重/更新：按 Mem0 四操作重构 + USER.md 清洗** 【断链#4】
- 现状/问题：`_try_merge_similar`/`_is_duplicate` 靠字符串/相似度，USER.md 已 3+ 次重复。
- 借鉴：Mem0 ADD/UPDATE/DELETE/NOOP——语义等价更新旧条、矛盾删旧立新。
- 落地：写前先 LLM 判「等价/矛盾/新增」→ 等价 UPDATE、矛盾 DELETE+ADD、无价值 NOOP；并入 `decay_memory`/`_llm_compress_user` 同管道。**落地后立刻跑一次 USER.md 清洗。**

**P0-6 记忆分层净化 + 时间感知** 【断链#5】
- 现状/问题：MEMORY.md 混入「第二章设定/制度考证」；记忆无时间线概念，旧事实仍当当前事实注入。
- 借鉴：ChatGPT Dreaming 时间感知重写；Zep 时序事实；Mem0「记忆是时间线」。
- 落地：① 创作内容从 MEMORY.md 迁到 novel_memory/圣经/项目记忆，全局记忆只留「关于你」；② 每条记忆带时间戳，区分「当前状态」与「历史事实」，过期自动归档/弱化（decay 补齐时间线语义）。

**P0-7 curator 真正清理（可控）** 【断链#6，A 独有】
- 现状/问题：`after_action.py:518` 强制 `auto_archive=False`，永远只报告不归档。
- 落地：改为「可控开启」首版——仅归档 `uses==0` 且 Jaccard 高重叠的严格低价值技能，保留一键还原。*预期：学习闭环「抽取→清理」两端闭合。*

### P1 · 让「懂你」更细更暖（闭环 + 陪伴，2–3 周）

**P1-1 打扰分寸接入专注度（感知层升级）**
- 现状：`disturb` 有管理，但感知层是 osascript 轮询，无专注度判断。
- 借鉴：OpenDesktop-Pet「先判适不适合打扰」。
- 落地：把「活跃窗口（编辑器/浏览器/全屏）+ 近期键盘活动 + 剪贴板动作」合成轻量「专注度」信号喂给 judge/disturb——专注时只静默记录、不弹建议。

**P1-2 主动建议的事后反馈闭环**
- 补充：主动建议「被接受后」要形成记忆（「他喜欢周一早上要进度摘要」），让主动本身也「越用越懂」；强化 `_maybe_proactive_close_loop` 为长期行为模式学习。

**P1-3 桌宠日记产品化 + 每周回忆**
- 现状：`memory/daily/*.md` 已逐日记，但用户看不到、无第一人称。
- 借鉴：QQ 宠物复活「第一人称写日记」；Sion L1 情感日记。
- 落地：① daily 转墨灵视角「今日小结」（陪你做了什么/学到什么/你夸了它什么），DeskHome 可翻；② 每周/每月自动「我们的回忆」（对话数/创作进度/解锁徽章/学到偏好）——「伙伴」感最强抓手，投入小。

**P1-4 表情系统按设计稿落地**
- 现状：`docs/emote-system-design.md` 已成规划稿（Manifest + 语义标注）。
- 落地：P0 止血（语义标注+词表+few-shot）→ P1 Manifest 化。表情是陪伴产品的「情绪接口」。

**P1-5 写作风格画像「量化 + 自动更新」** 【B + A 萧哥杀手锏】 ✅ 已实施（2026-08-29）
- 现状：`style_profile.json` + vault `preferences/萧盛写作风格.md` 已存在，但静态。
- 借鉴：写作工具「风格实验室」/`/style-learn`；Mem0 自动提取。
- 落地：① 每次创作/审稿后自动抽取风格信号（句长分布/文言比例/叙事视角/考据密度）增量更新；② 注入创作流水线让圆桌专家输出自动对齐文风。*这是别人没有、萧哥每天用得上的差异化标杆。*
- **实施记录**：新增 `deskmate/style_metrics.py`（纯统计风格信号，零 LLM）+ `deskmate/style_profile_store.py`（增量合并 + CLI：`python -m deskmate.style_profile_store <文本> --source "来源"`）；`~/.deskmate/style_profile.json` 已增量更新（备份 `.bak-20260829192953`）；单测 `tests/test_deskmate_style_profile.py` 14 项通过。量化层向后兼容：保留定性 profile，新增 metrics（句长/段落/四字格/文言虚词/对话占比/标点节奏）+ samples + updates；顶层冗余 summary/features，兼容 `_auto_load_style_profile` 的读取姿势。注：半成品——「注入创作流水线让圆桌专家自动对齐文风」尚未接入（避免与在改的创作流水线冲突）。

**P1-6 圣经回流 + 版本化闭环强化**
- 落地：把「一次创作产出的设定/人物/史料自动 upsert 进圣经」做成可见可回滚（面板显示「圣经新增 3 条实体，来自《国子监秘闻录》第 4 章」）——让「越写越懂你的书」成可感知卖点。

### P2 · 弯道超车（差异化，1 月+）

- **P2-1 后台自动提炼（对标 Dreaming）**：空闲时对近 N 天对话做「记忆综合/矛盾消解/过时更新」静默任务（decay_memory 已在此方向）。

- **P2-3 长期模式学习**：从「记住你说的话」升级到「从行为推断偏好」（「连续 3 周把周四审稿推到周五 → 周四别排审稿」）——「越用越懂」最高阶。
- **P2-4 桌面常驻「看见你在做什么」主动陪伴**【A】：合规前提下轻量主动陪伴（只感知窗口/活动态，感知层已具备，不录全量）。
- **P2-5 连续情感关怀**【A】：「记得你上周赶稿压力大 → 今天主动问进度」，把亲密度变成连续情感智能。
- **P2-6 个人 AI 分身（墨灵）**【A】：跨文档连续学写作/决策风格，成为「另一个我」而非工具。
- **P2-7 云端记忆同步（跨设备）**【断链#10，A 独有】：本地优先 + 可选云同步，多端「懂你」延续。
- **P2-8 合规轻陪伴桌宠定位卡位**【A】：以「工具属性 + 可爱外形 + 可控记忆」避开虚拟伴侣红线。

## 八、补充：盲区与盲点（2026-08-29 二次评审）

> 整合版定稿后二次评审新增：一条贯穿性设计原则（萧哥提出）+ 六条盲区（代码复核所得）。
> 这 7 条与正文 P0–P2 不冲突，是正文未覆盖的增量，作为后续实施的**额外约束与验收标准**。

### 8.0 贯穿性设计原则（萧哥）：懂你 = 前后端一体，可感可看

> 「要让『越用越懂你』能**感受到、看得到**，这就决定了在设计时，不只是后端做到了，**前端视觉化的设计要同步跟上**。只有前后端都做到『越用越懂你』了，用户才能感受得到，才会产生**温暖、被懂得**等感受。」

这条原则对正文计划的含义：

- **P0–P2 每一项都要带"前端可视"验收标准**，不能"后端闭环了就算完成"。P0-4（引用回显+记忆面板）只是这条原则的起点，不是全部。
- **前端视觉化的落地清单**（配套各 P 项）：
  - 了解度可视化：AI 对你的了解，用可量化、可回看的形态呈现（UnderstandingCard 升级版，含"本周新了解了什么"时间线）；
  - 记忆时间线：记住/修正/遗忘的事件流，让"记忆在生长"肉眼可见；
  - 成长轨迹：亲密度/信任/默契度的历史曲线 + 触发事件（"因为 8/3 你接受了我的建议，信任 +2"），数值变动要有因有果；
  - 桌宠情绪反馈：表情/动作与成长状态联动，让"被懂"透过桌宠的微表情传达；
  - 主动建议的"为什么现在提醒"：弹建议时自带一句"看你最近在赶稿，进度摘要提前给你"，让主动也可见。
- 前端看板与后端记忆共用**同一数据源**（复用 `/v1/deskmate/*` 已有接口），不另造一套，避免"后端有数据、前端不展示"的断层。

### 8.1 记忆质量评测集（方向盘）【盲区】

- 现状：`tests/` 已有 `test_deskmate_memory/growth/novel_memory/proactivity` 等**功能测试**（接口能跑通），但无**质量评测**（"问 50 题能答对几题"）。正文第七章的验证指标是运营指标，无法自动验证"是不是真的更懂了"。
- 借鉴：Mem0 用 LongMemEval/LoCoMo 基准评测记忆系统；我们应建自己的轻量评测集。
- 落地：建一份针对萧哥真实场景的**记忆评测集**（≈50–100 题：偏好/项目/写作风格/圣经实体/避讳），每次改记忆逻辑（P0-5 去重、P0-6 分层、P2 提炼）跑一遍，量化召回率/正确率，防回归。**没有它，P0–P2 每个改动都无法证明"更懂了"还是"改坏了"。**

### 8.2 成长数值的"长跑设计"（防半年后死掉）【盲区】 ✅ 已实施（2026-08-29）

- 现状：`intimacy 97.5 / empathy 91 / level 7`——亲密度已近封顶。
- 问题：成长类产品的经典死法——数值通胀后升级越来越慢、封顶后无动力，"越用越懂你"变成"三个月就懂了"。
- 落地：① **深度成长轨道**：数值满后转向"对既有偏好的细分/校准"（如亲密度满 → 追求"默契细分"，懂得更细而非更多）；② **封顶后的长期轨道**（关系深化、历史里程碑），保证数值满了体系仍在进化；③ 数值增长附**触发事件**（供前端 8.0 展示"为什么涨"）。
- **实施记录**：核心机制「封顶不浪费」——关系数值（intimacy/empathy/mood/trust）到上限后，溢出转入新增 `bond_depth`（关系深度），深度推进 `bond_stage`（初识→熟络→默契→知己→灵魂伴侣，阈值 0/30/90/200/400）；阶段升级记录 `bond_stage_up` 事件；`modulate_tone_prompt` 在「知己」及以上追加更懂彼此的提示；`snapshot` 输出 `bond`（depth/stage/progress）。改动仅限 `growth/engine.py` + `growth/state.py`（向后兼容：旧 growth.json 无 bond_depth 加载默认 0）；单测 `tests/test_deskmate_growth_longrun.py` 14 项 + 全量回归 450 项通过。未做：① 前端展示 bond 阶段（避免与 WorkBuddy 前端工作冲突）；② 「默契细分」（per-domain empathy）作为后续深化方向。

### 8.3 记忆全生命周期透明：溯源 + 遗忘可见【盲区】

- 现状：正文 P0-4 有"引用回显"（前瞻式：因为你说过 X 所以我……），但缺后半。
- 溯源：用户质疑某条回复时，能查"这条回复基于哪条记忆"。落地：记忆条目带 id，回复日志记录"本轮注入了哪些记忆 id"，可回溯——信任建设的硬能力。
- 遗忘可见：P0-6 讲"过期自动归档/弱化"，但没讲"忘得被看见"。用户改掉偏好后 AI 还按旧的回，用户会觉得"它根本没懂"。落地：decay/归档发生时前端留痕（"这条旧偏好 8/29 已归档"），**遗忘与记忆一样透明**。

### 8.4 敏感信息分级（合规底线，P2-8 的前置条件）【盲区】

- 现状：USER.md 已存"7 岁儿子""家庭情况"等敏感信息，正文未提隐私治理。
- 落地：记忆条目分级（普通/敏感/隐私），敏感条目标记、不进日志、可选不参与未来云同步；**涉及未成年人信息尤其谨慎**。没有敏感信息治理，"合规轻陪伴"定位（P2-8）是空话。

### 8.5 画像的迁移与扩展：冷启动 + 跨项目【盲区】

- 冷启动：正文全在打磨"越用越久"，未提"第一次用"。落地：onboarding 引导填基本信息 + 导入已有 vault/项目资料，把"从零开始懂你"压缩成"几天内开始懂你"。
- 跨项目迁移：`projects/` 已有 30 个项目（含 uuid 临时项目），萧哥真实路径是明朝→宋朝→新题材。落地：换新书时，全局偏好/写作风格/查史料铁律**自动注入新项目**——决定"开新书后 AI 还懂不懂你"。

### 8.6 记忆写入节流与成本（工程侧，间接决定质量）【盲区】

- 现状：每轮 `sync` 暂存 + LLM 提取 + after_action 一路后台 LLM 调用，无节流/失败监控。
- 问题：写得太多=噪音（污染注入预算）、写得太少=漏，且 token 成本不可控。
- 落地：同主题合并写入（参考 Mem0 四操作的 UPDATE 收敛）、批量处理、失败率/成本监控。
