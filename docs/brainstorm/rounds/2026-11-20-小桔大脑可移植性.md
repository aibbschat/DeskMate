## 缘起

## 核心判断：大脑 ≠ 一个程序，是三层东西

一句本质：**一份资产（她记得什么）+ 一套规则（她怎么想）+ 一层器官（她怎么感知和行动）。** 资产和规则属于她本人，可整体搬走；器官长在底座身上，换底座=换身体，不是换灵魂。

| 层 | 内容 | 搬运判定 | 证据（实测代码） |
|---|---|---|---|
| ① 数据资产 | `~/.deskmate/deskmate.db`（119MB / 49 表）+ 散文件（MEMORY/USER/SOUL.md、diary/、vault/、agency/、auto_tasks/、consult_runs.json、will/l2/alter_ego 三个 settings）+ 每本书 `<小说目录>/.deskmate/entities.db` + fts5.db | **可整体搬** | `paths.py:19-27` 统一根解析（DESKMATE_DIR 调用时解析）；`sqlite3 .backup` 一致拷贝（严禁 cp，WAL 会丢数据） |
| ② 纯逻辑 | persona.py / alter_ego / cognitive store·profile / will settings·digest / constants.emotion / feeling_store / diary 主体 / ledger / writing_context / file_reader | **原样搬** | 多为零 LLM、只认 DESKMATE_DIR；`persona.py:62` XIAOJU_SYSTEM 就是字符串；`will/digest.py:12` 零 LLM fail-open |
| ③ 接口层 | LLM 调用 / ProviderRouter / build_engine / persona 注入 / skill 白名单 / scheduler·tick / session·WS / 多副本同步 | **重写适配** | `bots/runtime.py:272` ProviderRouter、`manifest.py:253` persona_base importlib 抓取、`automation/store.py:91` scheduled_tasks、`manager.py:6767` deliver_to_session |

## 两个关键发现

**好消息——LLM 只有一个咽喉。** 几十处模型调用几乎都收敛到 `deskmate/memory/llm.py`（绑定 `coworker.secrets` + `prefs.json:default_model` + httpx，且多处裸 `OpenAI(...)` 调）。所有调用方 fail-open：拿不到模型即降级规则路径。最经济迁移路线：先搬①②，塞一个 `llm_available()=False` 桩适配器，小桔当场能跑（只是变笨），再逐步接真模型。

**坏消息——不是"挂在底座上的插件"，是双向长进去的。** `coworker/` 至少 6 处反向 import `deskmate.*`：
- `coworker/providers/router.py:88` ← `deskmate.llm_channels.PAID_GROUP`
- `coworker/personas/manifest.py:274` ← `importlib.import_module("deskmate.persona")`
- `coworker/agent.py:356/451/471` ← `build_full_context_for_turn` / `deskmate.skills.manager` / `deskmate.chat.mention_router`
- `coworker/server/app.py:7276` ← `build_full_context_for_turn`
- `coworker/automation/store.py:82` ← `deskmate.memory._sqlite.connect`

换底座不光改 deskmate 引用，还要从底座摘掉这些钩子，否则"小桔搬走后底座自己 import 失败"。

## 三个陷阱（红线）

1. **`profile_items` 是共享表**：`layer` 列同装 cognitive / emotional / feeling / worldview。只搬一半会数据断层。
2. **意志层肌肉在 growth**：`will/` 只有 settings + digest 两个只读文件；真正改行为的 5 个 `modulate_*` 在 `growth/engine.py:309-435`。漏搬只剩空壳。
3. **向量禁跨端搬运**：各端本地重算（`sync_store_sqlite.py:290-304` 启动护栏）；密钥 `secrets.json`/`.env`/sidecar token/`mcp.json` 绝不打包；`consult.py:192` 写死 `~/.deskmate` 不认 DESKMATE_DIR，须单独改。

## 为什么现在做（值不值得 / 什么信号）

- 成本最低：数据集中（一个 49 表库）、路径统一（`DESKMATE_DIR`）、LLM 单咽喉（一个适配器救几十个调用点）——这三点本身就是半个移植边界。
- 缺的只是最后一块：没有一键 export/import CLI。现有只有表级同步（双端收敛用）和两个画像 blob 导出，没有带 manifest + sha256 的整体打包。
- 现在补 = 把"未来能搬"从口头判断变成保底能力；不补 = 每次搬家都靠手工考古。
