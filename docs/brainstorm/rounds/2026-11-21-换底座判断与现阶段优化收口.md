# 换底座判断与现阶段优化收口

> 项目：/Users/xiaocheng/workspace/openworker
> 生成时间：2026-11-21
> 状态：观察 / 暂不施工（当前阶段只做优化，不加新能力）

## 缘起

萧哥说明当初提出“换底座”有两个动因：

1. 认为当前 OpenWorker 底座已不够先进；
2. 考虑过 Pi Agent，因为它足够轻。

这次明确：**现阶段不再加新能力，主要做优化。** 因此本轮不启动换底座，只把判断记入研究脑，避免以后重复提同一个方向。

## 当前判断

### 不立刻换底座

理由不是“底座足够先进”，而是：

- 当前用户痛点主要来自任务组织方式与可观测性：工具往返次数、工具空转可见性、scene 缺失、长任务归因困难；
- 这些问题的收益与底座无关，换底座不会自动消除；
- 研究脑 D5 已确认：Hermes 快，主要来自单次生成吞吐和“少往返地一次读全文”，不是底座本身；
- 研究脑 D4 已确认大脑可搬、身体要重造，当前反向耦合仍在，搬家是一次重写适配，不是配置切换。

### Pi Agent 的吸引力与边界

吸引点：轻量、启动快、心智负担小，适合作为“任务执行器”方向的参照。

边界：

- 小桔的差异化在“大脑”（记忆/人格/意志/写作语境/读稿纪律），不在执行器外壳；
- 若换执行器，①+② 大脑资产可搬，③ 接口层必须重写（D4）；
- Pi 能解决“轻”，但不能解决模型 decode 速度、工具往返次数和提示词纪律；
- 因此 Pi Agent 应作为“未来底座候选/适配器目标”，不是本轮优化项。

## 什么时候升级为真正的换底座决策

满足以下任一条件再立项：

1. 同一任务在 Pi Agent 或更轻底座上，完成时间 < 当前 1/2，且产出质量可用；
2. 当前底座持续出现无法根治的结构性阻塞（WS/session/provider 架构级缺陷），而非可通过优化收口的问题；
3. 一键 export/import CLI（D4 配套任务 #1）完成，数据迁移与校验可控后，搬家成本显著下降。

## 本轮已收口的优化（与换底座无关）

- scene 标签：engine.run 统一给 foreground/automation 打默认标签，不覆盖 expert_consult / bot_group；
- 只读任务耗时报表：scripts/task_latency_report.py；
- 工具空转进度：首轮提示 + 每 5 工具轮更新步数与耗时；
- shell 30s 默认超时：已有超时恢复测试，长命令需显式 timeout；
- 压缩失败提示：默认主模型兼任摘要器，失败不再暗示用户漏配专用模型；
- 读稿多章工具已 pin 并进入 persona/skill 指引。

## 一句话

**底座可以换，但现在不该换；先把“同样底座下本来能吃到的收益”吃完。** Pi Agent 记为一个有依据的未来候选，不并入当前优化轮。
