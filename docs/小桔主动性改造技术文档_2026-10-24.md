# 小桔主动性改造技术文档（2026-10-24）

目标只有一句话：**让小桔更主动、更有灵性，像一个真正懂萧盛的写作搭档，而不是一个等指令的工具。**

本文档是实施的唯一依据。改动按阶段顺序落地，不跳阶段、不并行改同一条链路；每阶段结束都要能通过本阶段的验收，才进入下一阶段。

---

## 一、什么叫“更主动、更有灵性”

不是“话更多、弹得更勤”。灵性要能被观察到，定义为以下五条可验收行为：

1. **不等问就发现**：手稿停笔、新章节更新、人物或时间线可能冲突时，她自己先发现，而不是等萧盛问“帮我看看”。
2. **把事推到可批状态**：不只给一句建议，而是把“要不要做、做什么、依据是什么”整理成一条可点头、可否决的待办；可逆的准备工作先做成草稿，改稿和外发永远等萧盛点头。
3. **记得上次的纠正**：被纠正过一次的事，下次不再犯；被接受过的建议类型，下次更敢提；被连续否决的类型，自动收敛。
4. **在合适时机说话**：深专注时不打断，但事后补递；离开电脑时不空转，回来开聊时把攒下的事一次性说清，不追着 nag。
5. **有自己的判断**：意见不合时凭依据讲清楚，不只迎合；不确定的事直说不确定，不编一个看似合理的结论。

## 二、非目标（红线，改造不碰）

- 不自动改稿件正文、不自动外发消息、不自动删东西。
- 不降低 `coworker` 的审批门槛：写文件、发消息、删除仍走原有审批。
- 不为了“显得活跃”而增加情绪卡片频次；情绪关怀保持原有门槛和冷却。
- 不读、不存密码与密钥；写作状态只读文件名与修改时间，不把正文全文塞进日志。

## 三、现状基线（2026-10-24 实测，不是推测）

- 后台调度器每 30 秒跑一次主动 tick：`coworker/server/manager.py` 的 `_combined_extra_tick`，默认开启（`DESKMATE_PROACTIVE_BACKGROUND` 仅 `=0` 时关闭）；后台 tick 还会连带跑 L2（`deskmate/proactivity/background.py` 的 `make_extra_tick`）。
- 但后台 tick 创建 `ProactiveEngine` 时**没有传 workspace**，`memory_context` / `project_context` 也是空。`deskmate/proactivity/context_builder.py` 里“最近文件变更”和“小说圣经”都依赖 workspace，没传就是空。
- 结果：judge 每轮稳定拿到的只有情绪、行为模式、世界观察。`~/.deskmate/memory/disturb_state.json` 最近 200 条（上限 200 条，2026-10-21 至 10-24）中，166 条是 `emotional_care` / `self_expression`，写作类只有 20 条，还散在 16 种不同的 `suggestion_type` 里。
- 建议漏斗（`deskmate/proactivity/tick.py` + `confidence.py`）：直接弹出要置信度 ≥ 0.8；0.5–0.8 走 PREPARE，但 PREPARE 既不进台账、不广播，前端也不处理，等于丢了；深专注时 SUGGEST 直接变 NO_ACTION 且不暂存；用户离开电脑时 tick 直接 return。
- 写入门槛（`deskmate/proactivity/ledger.py` 的 `record_proactive`）：置信度 < 0.75 或证据为空不落台账；开聊递送（`build_handoff_opening`）只递 understanding 已加工好的 pending 项，受每日交付上限约束。
- 写作健康生产者已存在且可用：`deskmate/proactivity/health_producers.py` 的 `writing` 生产者扫 `~/Documents/已出版`（见 `~/.deskmate/ingest_dirs.json`），停笔 ≥ 3 天且 < 45 天报 `stall_flag`，每天至多扫一次，锚点按书名合并。
- L2 白名单（`deskmate/agency/settings.py` + `registry.py`）全是世界搜索、观察日记、AI 圈类动作，没有写作动作；`close_loop` 降级提案写进 `~/.deskmate/memory/close_loop_pending.jsonl`，但没有任何递送入口，2026-09 至 10-21 的 5 条一直躺在那里。
- 对话主提示词（`coworker/personas/builtin/deskmate.md`）的“主动性”一节仍写着“有把握才主动开口”，等于在对话层也把主动性压住。

结论：不是缺模块，是**眼睛瞎（没上下文）、漏斗漏（PREPARE 与深专注丢件）、类型散（学不到偏好）、动作缺（没有写作自主动作）、提案没人清账**。改造按这个顺序修。

## 四、总体架构（改造后）

```text
调度器 30s / 前端 tick
  → ProactiveEngine.tick()
      → 感知：活动窗口 + 前台文本 + 写作状态（新，见阶段一）
      → 思考：judge（类型收敛后，见阶段三）
      → 行动：SUGGEST 直接递 / PREPARE 与深专注拦截 → 暂存待递（新，见阶段二）
      → 递送：浮层（SUGGEST）+ 开聊开场白（台账 pending，含暂存项）+ close_loop 旧提案附带递送（见阶段四）
      → 学习：规范化类型 → 偏好沉淀（见阶段三）
写作信号生产者（每 tick 调 run_producers_all）：stall_flag（已有）+ chapter_updated（新，见阶段四）
对话层：主提示词主动性守则（见阶段五）+ 轮次收尾 close_loop（已有）
```

所有新代码遵循项目已有范式：fail-open（任何一步异常都不阻断 tick）、确定性 id / 锚点合并（同一问题不重复刷屏）、不改已有公开函数签名（只加可选参数与可选字段）。

## 五、分阶段实施

### 阶段一：先喂眼睛——后台 tick 看到写作状态

文件：

- 新增 `deskmate/proactivity/writing_context.py`：
  - `resolve_writing_workspace(explicit=None, base_dir=None)`：优先级为环境变量 `DESKMATE_WRITING_WORKSPACE` → `base_dir/ingest_dirs.json` 里的第一个已存在目录 → `~/Documents/已出版`；都不存在返回 None。
  - `build_writing_status(workspace, *, limit=6)`：只读目录与文件 mtime / 后缀（`.docx` / `.md`，跳过 `~$` 锁文件与隐藏文件），按书名目录扫描，返回形如“《国子监秘闻录》最近动笔 2 天前；《X》停笔 5 天”的短文本，总长 ≤ 800 字；任何异常返回空串。
- 改 `deskmate/proactivity/tick.py` 的 `tick()`：在组装 judge 上下文前算 `effective_workspace = self.workspace or resolve_writing_workspace(...)`，把 `effective_workspace` 传给 `build_proactive_context`（于是最近文件变更与工作区 `.deskmate/` 下的圣经文件自动生效），并把 `build_writing_status(effective_workspace)` 以“## 写作状态（手稿文件 mtime，只读统计）”追加进 judge 上下文。
- 不改：judge 提示词、阈值、递送逻辑。

验收：

- `writing_context` 单测：临时目录里放两本书目录，停笔天数与最近动笔计算正确；目录不存在时返回空串不抛异常。
- 手工验证：重启应用后一次前端 tick 的 judge 上下文里出现“写作状态”一节（可通过 tick 返回的 reason / 行为日志间接确认，不直接打印正文）。

### 阶段二：再修漏斗——PREPARE 与深专注建议暂存待递

文件：

- 新增 `deskmate/proactivity/deferred.py`：`defer_judgment(base_dir, judgment, reason)`。
  - 只对非情绪类（排除 `emotional_care` / `self_expression`）、内容非空的判断暂存；情绪类有时效性，过期再递没有意义，仍按原逻辑丢弃。
  - 经 `ledger.record_proactive(source="cloud_audit", bypass_threshold=True, payload={"deferred": True, "deferred_reason": reason, "original_action": ...})` 落台账，kind 用规范化后的类型，anchor 用 `_finding_anchor(judgment)`（无 key 时由 `record_proactive` 按内容指纹兜底合并）。
  - 用 `bypass_threshold=True` 是有意的：暂存项不是“已确认的高置信结论”，而是“待萧盛开聊时裁决的候选”，递送时仍受 `build_handoff_opening` 的 understanding 守卫与每日上限约束，不会绕过递送门。
- 改 `tick.py`：
  - `TickResult` 增加可选字段 `deferred: bool = False` 与 `deferred_id: str = ""`，并在 `to_dict()` 里透出（前端忽略未知字段，兼容）。
  - 决策为 PREPARE 时：调用 `defer_judgment`，返回 action 仍为 PREPARE，但 `skipped_reason` 写明“中置信已暂存，待开聊时递”，且 `deferred=True`。
  - 决策为 SUGGEST 但专注度为 deep 时：先 `defer_judgment` 再返回 NO_ACTION，`skipped_reason` 写明“深专注不打扰，已暂存待递”。
  - 不暂存的情况保持原样：judge 明确 `should_act=False`；防打扰拦截（连续忽略 / 同 key 30 分钟冷却 / 静默模式）——那是用户信号，暂存会绕过防打扰。
- 不改：递送入口。暂存项走已有开聊开场白（`GET /v1/deskmate/proactive/handoff` → `build_handoff_opening`），前端无需改动。

验收：

- 单测：构造一个 PREPARE 判断（置信度 0.6、非情绪类），调用暂存后能在临时库的 `proactive_ledger` 里查到 pending 行，且同一 anchor 第二次调用不新增行。
- 单测：情绪类判断调用暂存返回空，不落库。
- 回归：已有 `tests/test_proactive_ledger.py` 与 `test_proactive_background_default_on.py` 通过。

### 阶段三：类型收敛与分类型阈值——让偏好学习能跑起来

文件：

- 新增 `deskmate/proactivity/suggestion_types.py`：
  - 规范类型集合：`plot_contradiction`、`character_inconsistency`、`timeline_error`、`missing_foreshadow`、`writing_stall`、`chapter_updated`、`writing_review`、`research_gap`、`emotional_care`、`self_expression`、`task_reminder`、`generic`。
  - `normalize_suggestion_type(raw)`：精确命中直接用；别名映射（如 `writing_block_*`、`review_writing_*`、`user_requested_writing_review` → `writing_review`；`writing_breakpoint_*` → `writing_review`；`character_consistency_check` → `character_inconsistency`）；含关键词兜底（plot / character / timeline / foreshadow / stall / chapter）；其余 → `generic`。
  - `thresholds_for(suggestion_type)`：写作类（plot / character / timeline / foreshadow / writing_stall / chapter_updated / writing_review）SUGGEST 0.65、PREPARE 0.45；其余通用类沿用 0.8 / 0.5；`emotional_care`（0.6）与 `self_expression`（0.55）仍走 `confidence.py` 里的专属分支，不被覆盖。
- 改 `deskmate/proactivity/judge.py`：提示词里把“suggestion_type 用英文 snake_case（如 …）”改为“只能从下列类型里选一个：plot_contradiction、character_inconsistency、timeline_error、missing_foreshadow、writing_stall、chapter_updated、writing_review、research_gap、emotional_care、self_expression、task_reminder、generic；不要自造新类型”。
- 改 `tick.py`：judge 返回后、决策前，先做 `judgment.suggestion_type = normalize_suggestion_type(...)`，再把 `thresholds_for(...)` 的结果作为 `suggest_threshold` / `prepare_threshold` 传给 `evaluate_action`。于是 `disturb.record_suggestion` 与 `record_feedback` → `PreferenceStore.record_accepted` 拿到的都是规范类型，同类型被接受 2 次即可沉淀偏好（`preferences.py` 的 `ACCEPT_THRESHOLD = 2` 不变）。
- 不改：`confidence.py` 的专属分支与 `DisturbManager` 的冷却规则。

验收：

- 单测：20 个历史散落类型全部映射到规范类型，且写作类不再出现 16 种并存；`thresholds_for("writing_review") == (0.65, 0.45)`。
- 单测：同一规范类型被接受 2 次后 `PreferenceStore.active_preferences()` 里出现该类型。

### 阶段四：写作自主动作与旧提案清账

文件：

- 改 `deskmate/proactivity/health_producers.py`，新增生产者 `writing_activity`（注册进已有 `run_producers_all`，无需改调度）：
  - 每小时至多扫一次（复用 `_throttled`，meta key 独立）；扫描根与 `writing` 生产者一致（`SCRIBE_ROOTS` 环境变量优先，否则 `~/Documents/已出版`）。
  - 首次扫描只记基线（每本书最新手稿文件的 mtime + 大小，存 `proactivity_meta`），不产出，避免把旧稿全报一遍。
  - 之后扫描发现某本书最新文件 mtime 或大小变了，产出一条 `chapter_updated`：content 为“《书名》有新改动（文件 X，最近修改于 …），要不要我核对人物 / 时间线？”，evidence 带文件名与修改时间，confidence 0.8，anchor 按书名固定（同一本书反复改动合并回同一行，不刷屏）。
  - 只产出“信号 + 提议”，不读正文、不改稿件；真正的核对仍由萧盛点头后在对话里用 `novel_memory` 工具做。
- 改 `deskmate/proactivity/ledger.py`，新增 `close_loop_pending_text(base_dir, limit=3)`：读 `base_dir/memory/close_loop_pending.jsonl`，只取最近 30 天内、status 为 proposed 的行，拼成一段附带文本；并在 `build_handoff_opening` 返回的 text 末尾追加该段（items 列表不变，ack 流程不变）。
  - 这样旧提案不再静默躺着：开聊时萧盛能看到，点头就做、否决就由对话主助手把对应行从文件里清掉（见阶段五提示词规则）；超过 30 天的旧提案不再附带递送，避免对着过期事项 nag。
- 不改：L2 白名单与风险分级。本阶段不新增 L2 动作——写作自主动作先以生产者 + 提案形态跑通一个闭环，确认递送与清账都正常后，再考虑是否把某一项升为 L2 低风险动作。

验收：

- 单测：临时书目下，首次扫描无产出；改动文件后第二次扫描产出一条 `chapter_updated`；再次扫描无改动时无新增。
- 单测：`close_loop_pending_text` 能读出最近提案、跳过 30 天外的旧提案。
- 手工验证：DeskHome 开聊时，台账开场白末尾出现 close_loop 附带段（若有 30 天内提案）。

### 阶段五：对话内主动性与灵性层（提示词层，代码不动主回路）

文件：只改 `coworker/personas/builtin/deskmate.md`，人格（`deskmate/persona.py`）不动。

- “主动性”一节改写为：
  - 回答完一个任务后，先想一步“显而易见的下一步”：如果下一步是可逆的准备工作（起草、整理、列清单、查证），直接做成草稿递出来，不要只问“要不要”；如果下一步会改稿或外发，先把可批的草稿与依据摆出来，等点头。
  - 对话里用户说“以后要主动提 / 下次记得”，当场用 `proactive_capture` 写台账或用 `memory_append` 写记忆，不要只口头答应。
  - 每轮开聊先看开场白里的台账与 close_loop 附带段：有未完成事项先递、让萧盛选，不要假装没看见；萧盛对某条表态（做 / 不要 / 稍后）后，把对应台账项 ack / dismiss / snooze，把 close_loop_pending 里的对应行清掉。
  - “有把握才开口”改为分层：高置信直接做 / 中置信先做成可批草稿 / 低置信直说不确定并说明缺什么证据。
- “主动推理（4A 循环）”一节同步更新：中置信度不再是“只在用户问起时说”，而是“已暂存待递，开聊时由开场白递出”。
- 不改：写作铁律、阅读与汇报底线、史料查证规则、审批规则。

验收：

- 人工验收（无法单测）：连续三轮对话里，小桔在任务完成后主动给出下一步草稿或清单，而不是以反问收尾；开聊时主动递出台账事项。

## 六、回滚与安全

- 每个阶段都是独立提交：新文件可整文件删除，`tick.py` 的改动集中在三处（写作状态注入、暂存分支、类型归一），回滚时恢复这三处即可回到改造前行为。
- 环境变量兜底：`DESKMATE_WRITING_WORKSPACE` 可随时指定或清空；`DESKMATE_PROACTIVE_BACKGROUND=0` 仍可一键关闭后台 tick。
- 任何新代码异常都 fail-open：`writing_context`、`deferred`、`suggestion_types`、`writing_activity`、`close_loop_pending_text` 内部全部捕获异常并返回空，绝不阻断 tick 与对话。
- 台账膨胀控制：暂存项靠 anchor 合并；递送靠每日上限；close_loop 附带段只取 3 条、只取 30 天内。

## 八、实施顺序（不再二选一，按此顺序）

1. 阶段一：喂眼睛。2. 阶段二：暂存待递。3. 阶段三：类型收敛。4. 阶段四：写作信号与清账。5. 阶段五：提示词灵性层。6. 阶段六：任务直达与跟进状态。7. 回归测试与手工验证。

每阶段做完先自测再进入下一阶段；任何一阶段验收不通过，停在该阶段修，不带着问题往后堆。

## 九、阶段六：建议直达可执行任务 + 未完成事项真实跟进状态（2026-10-24 晚补）

上一阶段的问题：建议能暂存、开聊时能递出来，但递出来还是一句问话，主对话要再等一轮“做哪个、是哪本书、从哪儿开始”才能开工。本阶段把那一轮对话省掉。

文件：

- 新增 `deskmate/proactivity/next_steps.py`：按台账 kind 预置下一步。`chapter_updated` → 核对人物/时间线、续写提纲、排抖音选题；`stall_flag` → 续写提纲、复盘卡点、换一本；情节/人物/时间线/伏笔/审校类 → 对应核对或提纲；其他 → 列清单、起草草稿。每条下一步都是一份任务指令（含事项原文、依据、工具、不改稿/不外发），不是正文。
