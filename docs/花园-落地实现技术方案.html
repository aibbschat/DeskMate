OPENWORKER × 小桔 · 落地实现技术方案

「花园」私密花园 · 个人中心升级

把个人中心升级成一块私密花园：四季流转、花开记录、花园时钟。方案基于现有 deskmate 体系真实代码结构撰写，可直接按阶段推进。
2026-09-02基于现有 ProfileCenter / BlobStore / tick / 日记 / 徽章体系P0 可先行

1定位与落地目标

花园不是新应用，是现有个人中心（ProfileCenter）的「视觉 + 互动」升级层

现有个人中心已是暖橘色调、五 Tab（概览/长期记忆/小桔日记/勋章/设置），hero 文案已是「这是你的小桔园」。因此花园落地的正确姿势是在现有骨架上叠加花园层，不推倒重来：

  • 保留信息架构：五 Tab 全部保留，花园只是让它们「长在花园里」——概览升级为花园全景，其余 Tab 保留但共享四季/昼夜主题皮肤。
  • 三个可验证的落地目标（每个都能被用户看见，呼应「细节要真正落地可见」）：
    • ① 四季流转：花园背景随本地季节/昼夜变化（春樱 / 夏茂 / 秋枫 / 冬雪 + 晨 / 昼 / 黄昏 / 深夜），是确定性、无需 LLM 的视觉层。
    • ② 花开记录：每次值得记的事（学到记忆、写下日记、解锁勋章、里程碑）在花园里开出一朵花，花圃按类别分格，花朵带日期与原文摘录。
    • ③ 花园时钟：把互动挂在确定发生的时刻上（晨间首进、黄昏入夜、深夜亮灯、间隔归来、节日），一切互动沉淀为可回看的痕迹，检测失败由确定性事件兜底。
  • 一条不打扰底线：所有花园互动都是轻提示（toast 级），可一键关闭，复用现有防打扰语义（disturb / settings）。
方案原则：确定性 > 检测。花园的一切都挂在「确定发生」的事件上（本地时间、进入花园、产生素材），不依赖任何场景识别的偶然性——这正是用户强调的「建起来不难，难的是真正落地可见」。

3总体架构：三层，各自独立可验

数据层（后端 garden 模块）→ 时钟层（确定性事件调度）→ 视觉层（前端花园组件）
前端 GardenProfileCenter→ GET/POST /v1/deskmate/garden/*→ deskmate/garden/（新模块）→ BlobStore KEY_GARDEN + 既有 growth/emotion/diary

数据层 deskmate/garden/

  • state.py：GardenState dataclass，BlobStore 持久化，字段级容错（复刻 growth 的 _num 安全取值）。
  • season.py：四季/昼夜计算，纯本地时间，确定性无 LLM。
  • flowers.py：花开记录（事件→花映射、幂等、零 LLM 短句）。
  • clock.py：花园时钟事件调度（幂等键 + 痕迹库）。

时钟层 确定性事件表

  • 晨间首进 / 黄昏入夜 / 深夜亮灯 / 间隔归来 / 节日 / 花开。
  • 每个事件带幂等键（如 morning:2026-09-03），同一天不重复触发。
  • 触发以「进入花园 visit + 本地时间」为主，后台 tick 结算花开为兜底。

视觉层 surfaces/gui/src/components/garden/

  • GardenProfileCenter.tsx：升级版个人中心（花园全景 + 五 Tab 皮肤共享）。
  • GardenScene.tsx：四季/昼夜 SVG 背景场景 + SeasonTheme.ts 主题变量。
  • GardenFlowers.tsx + GardenBeds.tsx：花圃与花开渲染（tooltip 带日期/原文）。
  • GardenClockOverlay.tsx + useGardenClock.ts：花园时钟轻提示 + visit 上报。

4后端设计：deskmate/garden/ 新模块

全部复刻既有模式（BlobStore 持久化 / 声明式注册表 / 零 LLM / 字段级容错 / fail-open）

4.1 GardenState 数据模型

存储：BlobStore.KEY_GARDEN = "garden"（与 growth 同域，物理同一 deskmate.db，不随跨端同步——隐私叙事护城河）。

@dataclass
class GardenState:
    version: int = 1
    # —— 花园成长 ——
    last_visit_date: str = ""              # YYYY-MM-DD（归来计算：距此 >=3 天）
    visit_count: int = 0                   # 累计来访（花园「归园」统计）
    season_started_at: str = ""            # 当前季节起始（前端也可本地算，后端存证据）
    # —— 花开记录：flower_id -> FlowerRecord ——
    flowers: dict[str, FlowerRecord] = field(default_factory=dict)
    # —— 花园痕迹 / 时钟日志（可回看，最近 N 条）——
    garden_log: list[dict] = field(default_factory=list)   # cap 200
    # —— 花园时钟幂等表：event_key -> last_trigger_iso ——
    clock_log: dict[str, str] = field(default_factory=dict)
    updated_at: str = ""

@dataclass
class FlowerRecord:
    flower_id: str        # f"{kind}:{fingerprint}"，指纹 ts|kind|subject 幂等
    kind: str             # 花种 id（勿忘草/向日葵/蒲公英/铃兰…）
    bed: str              # 花圃：memory/diary/badge/milestone
    title: str            # 零 LLM 渲染的短标题
    quote: str            # 事件原文摘录（真实数据，禁止编造）
    date: str             # 开花日期 YYYY-MM-DD
    source_ts: str        # 原始事件时间戳
    mood_tint: str = ""   # 情绪倾向（从 emotion_timeline 派生，可选）

4.2 花园时钟：确定性事件表

核心是事件表 + 幂等键 + 痕迹库。所有触发都是「进入花园（visit）时的本地时间判定」为主、后台 tick 结算为兜底：

事件触发条件（确定性）动作（视觉层）幂等键
晨间首进进入花园且本地 05:00–10:00晨间问候 toast + 花园晨光主题morning:YYYY-MM-DD
黄昏入夜进入花园且本地 17:00–19:00黄昏氛围 + 「入夜了，点盏灯吧」dusk:YYYY-MM-DD
深夜亮灯进入花园且本地 23:00–04:00树屋亮灯 + Goodnight toast（对应 UI 稿 03）night:YYYY-MM-DD
间隔归来距 last_visit_date ≥ 3 天「好久不见」+ 归来花开（COUNTER_COMEBACK 已存在）comeback:YYYY-MM-DD
节日本地日期命中节日表（新年/中秋等）节日氛围 + 专属祝福festival:YYYY-{节日}
花开结算后台 tick：新素材（记忆/日记/徽章/里程碑）花园新增花朵 + 图鉴更新（不打扰，进园可见）flower:{指纹}

4.3 tick 集成（后台兜底）

在 proactivity/tick.py 的 diary_payload 同位置新增 garden_payload：

# tick.py —— 与日记灵感同一范式：后台结算，不占 SUGGEST 通道
garden_payload = None
try:
    from deskmate.garden.clock import maybe_settle_garden
    garden_payload = maybe_settle_garden(base_dir=self.base_dir)
except Exception:
    garden_payload = None   # 失败绝不阻断主动推理主流程

TickResult 加 garden 字段并在 to_dict() 输出；前端 useProactiveTick 收到后仅作后台更新（不弹窗），真正的一次性互动由「进入花园 visit」触发。

4.4 花开记录（记录开花）

  • 事件源：GrowthState.recent_events + 日记素材账本（diary/materials/*.jsonl）+ badges_unlocked + 认知画像更新。
  • 映射表（声明式，复刻 badges.BADGES 模式）：
    事件 kind花种花圃情绪倾向
    memory_learned勿忘草memory 记忆圃平静/温暖
    diary_written木槿diary 日记圃平静
    badge_unlocked勋章花（按稀有度变色）badge 勋章圃顺利
    creation_approved向日葵milestone 里程碑圃顺利
    user_corrected蒲公英milestone压力/成长
    suggestion_accepted风信子milestone顺利
  • 幂等：flower_id = f"{kind}:{ts|kind|subject 指纹}"，重复事件只算一次。
  • 零 LLM：title 由模板渲染（如「记住：{subject 前 12 字}」），quote 直接摘真实原文，禁止模型编造。

4.5 API 端点（挂在 coworker/server/app.py，deskmate 段）

方法路径说明
GET/v1/deskmate/garden花园整体状态：season/beds/flowers/recent_log/visit_count。
POST/v1/deskmate/garden/visit前端上报进入花园；后端按本地时间判定晨间/黄昏/深夜/归来/节日，返回本次应触发的一次性互动。
GET/v1/deskmate/garden/flowers花开列表，支持 ?bed=&limit=（分页，防花朵无限增长拖垮前端）。
GET/v1/deskmate/garden/log花园痕迹/时钟日志（可回看的互动记录）。
POST/v1/deskmate/garden/flowers/{id}/water（P2）浇水/点亮一朵花的互动，沉淀回 garden_log。
坑（沿既有教训）：具体路由（/garden/flowers、/garden/log）必须注册在通配路由之前；所有端点 fail-open，失败静默降级，不阻断个人中心显示。

5.3 花园时钟互动（关键：落地可见）

  • 进园 visit：useGardenClock 在 GardenProfileCenter 挂载时 POST /garden/visit，后端按本地时间返回本次应触发事件（晨间/黄昏/深夜/归来/节日之一），前端以 GardenClockOverlay 轻提示呈现。
  • 互动文案：模板 + 少量真实变量（如归来「好久不见，你走了 N 天，花园里开了 X 朵花」——N 和 X 都是真实数据，不编造）。
  • 可回看：每次互动写入 garden_log，花园里提供「最近痕迹」小面板（对应「一切互动沉淀为可回看痕迹」）。
  • 可关闭：设置里新增「花园互动」开关（复用 settings 面板 + disturb 语义），关闭后 visit 只结算花开、不弹提示。
