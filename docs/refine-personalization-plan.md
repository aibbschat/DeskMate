# 墨灵桌搭「越用越懂你」精细化打磨建议

> 缘起：产品功能基本齐备（尤其办公/创作侧），下一步进入细节打磨，方向是「越用越懂你」。
> 本文 = 产品现状盘点（读代码所得，含真实运行数据证据）＋ 国内外同类产品机制对标 ＋ 分优先级打磨建议。
> 研究日期：2026-08-29

---

## 一、一句话结论

**墨灵的「懂你」地基已经比国内外绝大多数同类产品都深**——分层记忆（SOUL/USER/MEMORY/longterm/vault/圣经）、成长调制（亲密度/信任/默契度真实改变行为）、反思落盘、主动层、学习图谱、徽章体系一应俱全。但打磨的关键不在「再搭一层记忆」，而在 **三条断链**：

1. **记忆写入→生效的断链**：`DESKMATE_AUTO_INJECT` 是 opt-in 环境变量，记忆很可能根本没被自动注入（写了但没用上）；
2. **反馈→成长数值的断链**：`trust` 恒为 0.5（默认值），用户对主动建议的接受/拒绝没有回流成「信任感」，「越用越懂」的反馈闭环没闭合；
3. **懂你→被看见的断链**：用户很难直观看到「你记住了我什么、改变了什么」，「懂」没有被感知，就没有「越用越懂」的体感。

把这三条断链补上，再对齐竞品里「时间感知记忆、记忆即时间线、自动提炼、打扰分寸」这四个已被验证的机制，就是本轮打磨的全部重点。

## 三、国内外同类产品机制对标

### 3.1 国外：四大已验证范式

**① ChatGPT Memory（双层 + Dreaming 后台提炼）**
- 双层：显式「saved memories」（可见、可编辑、可删）＋ 隐式「reference chat history」（从历史聊天学模式，只能开关）。你在设置里能逐条看到 AI 记住了你什么。
- 2026-06 推出 **Dreaming V3**：一个异步后台进程在用户不用时综合几十段对话、自动合成/更新记忆状态；**时间感知**——「7 月去新加坡」到点自动重写成「7 月去过新加坡」；自动解决矛盾；算力降 5 倍后才铺到免费用户。
- 启发：**后台自动提炼、时间感知重写、记忆可见可编辑**。

**② Claude + MCP 记忆生态（分层 + 知识图谱 + 规则强注入）**
- 事实层分 Global（跨项目偏好）/ Project（项目决策）/ Personality（跨项目大脑），与我们 SOUL/USER/项目记忆几乎同构，说明方向正确。
- 知识图谱式记忆（实体-关系-观察）与我们的「圣经实体库」同源。
- 规则强制注入：mandatory/forbidden rules 通过 hook 每轮注入，防止被 context 压缩遗忘——**我们 SOUL 护栏可借鉴这个强注入思路**。

**③ Mem0（记忆提取的「记什么」标准 + 四操作）**
- 提取标准：像资深助理记笔记——**只记**陈述的偏好、领域约束、过去决策、反复出现的挫败、身份事实；**不记**客套、确认、无答案的问题。
- 写入用 LLM 四选一：**ADD / UPDATE / DELETE / NOOP**。语义等价→更新旧条而非新建（治我们 USER.md 重复的病根）；矛盾→删旧立新；无价值→不动。
- 核心观念：**记忆是时间线，不是单一可变画像**——用户换工作、搬家后旧事实仍有历史价值（对应我们 decay/archive 的方向）。

**④ Zep / Graphiti（时序知识图谱）**
- 每条事实带时间，**「从伦敦搬到东京」是状态变化而非两条矛盾事实**；专门解决「记忆随时间过时/自相矛盾」的问题，时间敏感召回准确率提升明显。

> 旁证：Sudowrite 的 Story Bible + 2 万字记忆——与我们的「圣经」体系同构，验证了创作场景「书有自己的记忆」是行业共识。

### 3.2 国内：机会大于威胁

**豆包 / Kimi**
- 豆包记忆：从对话保存画像/偏好/兴趣/习惯，宣称「越用越懂你」，设置面板可逐条查看/删除，支持自然语言管理（「请记住我喜欢吃甜品」）。
- Kimi 记忆空间：单独训练了一个模型判断「什么值得记」，自然语言命令增/改（「更正：我搬到纽约了」→ 替换旧记忆）。
- **关键结论（媒体共识）**：国内大厂「放弃全局个性化」——个性化停留在换形象/声音/主题的表层，**没有把记忆做进系统级行为调制**。这正是墨灵的差异化空档：我们已有亲密度→语气、默契度→记忆预算、信任→主动阈值这些**真实调制**，国内大厂没有。

**桌宠赛道（最直接的竞品，也在做「越用越懂你」）**
- Doki：打怪升级 Lv.12，摸摸头/喂饭/专心工作涨经验——与我们的成长/徽章体系同思路。
- OpenDesktop-Pet：主动互动前先判断「现在适合打扰吗」（专注/空闲），长期记忆记偏好/习惯/项目——**打扰分寸 + 记忆**两件套。
- 星尘 Stradust：三层记忆（短期→中期→长期）+ Mem0 云端持久化 + RAG + Live2D 六维情感——「记忆 + 情感表达」与我们最近。
- Sion：三层记忆 L0 会话缓冲 / L1 情感日记（每 4h）/ L2 原子事实（每轮提取 + 艾宾浩斯遗忘）——**带遗忘曲线的记忆**。
- QQ 宠物复活：接入混元 Hy3，性格可自由选择、主动回应、**以第一人称写日记留存日常**——「桌宠有自己的日记」是增强伙伴感的有效手段，我们 daily/ 已有雏形。
- 结论：桌宠赛道整体都在补「记忆 + 成长 + 主动 + 情感表达」，但**没有一家把「创作专业度」做进去**——这正是我们（圣经考据 + 圆桌专家 + 创作流水线）的护城河。

**写作赛道**
- 长篇 AI 小说工具普遍在做：人设一致性、风格学习（`/style-learn` 风格实验室）、Story Bible——验证创作场景需要「越写越懂你的书」。

## 四、精细化打磨建议（按优先级）

> 原则：**不新增体系，只补断链**。每一条都标注：现状 → 问题 → 借鉴谁 → 落地动作。

### P0 · 先把「懂你」真正用起来（3 条断链优先补）

**P0-1 记忆注入默认开启，让「写了的记忆」被用上**
- 现状：`deskmate_auto_inject_context` 需 `DESKMATE_AUTO_INJECT=1` 或已配 LLM 才注入。
- 问题：环境变量是 opt-in，用户没设就白搭；已有 91 条记忆、亲密度 97.5，但很可能每轮根本没喂给模型。
- 借鉴：ChatGPT 96% 的记忆由系统自动触发；国内大厂记忆功能默认开启。
- 落地：① 启动时自动注入改为默认开（加设置开关 UI，不靠环境变量）；② 在 StatusPanel/MemorySection 显示「记忆注入已开启」状态，让用户一眼知道这条链路是通的。

**P0-2 打通「反馈 → 信任/成长」闭环，让 trust 真的动起来**
- 现状：`trust` 恒 0.5；`record_suggestion_feedback(accepted)` 有接口但没接全。
- 问题：用户点掉/接受主动建议、打回产物、说「不对」，这些最真实的信号没有回流成信任感 → 「越用越懂」没有反馈驱动。
- 借鉴：Mem0 的 UPDATE/DELETE 冲突解决；ChatGPT 记忆随用户纠正自动更新。
- 落地：① 把「主动建议被接受/忽略」「打回重做」「明确纠正」三类事件统一记入 trust 计算（正负反馈加权）；② trust 变动要可见（前端徽章/面板显示「信任度」变化及原因）；③ 用户在对话里说「不对/别这样」时，除了写 correction 记忆，同时触发 trust/默契度微调。

**P0-3 让「懂你」被看见——记忆引用回显**
- 现状：记忆在注入、成长在涨，但回复里没有「因为你说过……所以……」的显式引用，用户无体感。
- 问题：「越用越懂」是感受，不是数字；看不见，就以为没发生。
- 借鉴：ChatGPT 会在记忆生效时提示「根据你的记忆」；豆包记忆面板可逐条查看。
- 落地：① 在回复尾部/气泡内，当某条记忆被实际引用时回显「（因为你 8/1 说过只查正史，所以这里排除了自媒体来源）」；② 借鉴豆包，做「记忆面板」：列出 AI 记住了什么（分类、可编辑、可删除、可导出），把 USER.md/MEMORY.md 的可读性产品化。

### P0 · 记忆质量治理（让「懂你」的原料干净）

**P0-4 按 Mem0 四操作重构记忆去重/更新**
- 现状：`_try_merge_similar`/`_is_duplicate` 靠字符串/相似度，USER.md 已出现 3+ 次重复条目。
- 问题：画像在注水，注入预算被重复内容浪费，模型看到的画像质量下降。
- 借鉴：Mem0 的 ADD/UPDATE/DELETE/NOOP 四操作——语义等价则更新旧条，矛盾则删旧立新。
- 落地：写记忆前先做一次 LLM 判定「等价/矛盾/新增」→ 等价走 UPDATE、矛盾走 DELETE+ADD、无价值走 NOOP；`decay_memory`/`_llm_compress_user` 已有地基，把去重并入同一管道。**落地后立刻跑一次 USER.md 清洗**（现已有重复可立即清）。

**P0-5 记忆分层净化 + 时间感知**
- 现状：MEMORY.md 混入「第二章设定/制度考证」等创作内容；记忆没有「时间线」概念。
- 问题：书的记忆和你的记忆混在一起，注入时互相干扰；旧事实（如「用户周末不写小说」）可能已过时却仍被当当前事实注入。
- 借鉴：ChatGPT Dreaming 的时间感知重写；Zep 的时序事实；Mem0「记忆是时间线」。
- 落地：① 把创作类内容从 MEMORY.md 迁到 novel_memory/圣经/项目记忆，全局记忆只留「关于你」的；② 每条记忆带时间戳，注入时区分「当前状态」与「历史事实」，过期自动归档/弱化（decay 已有雏形，补齐时间线语义）。

### P1 · 让「主动」更懂分寸、更有反馈

**P1-1 打扰分寸接入感知（专注度推断）**
- 现状：disturb 有打扰管理，但感知层是 osascript 轮询，无专注度判断。
- 借鉴：OpenDesktop-Pet「先判断适不适合打扰」；OpenWorker 自家 automation 有安静时段。
- 落地：把「当前活跃窗口（编辑器/浏览器/全屏）+ 近期键盘活动 + 剪贴板动作」合成一个轻量「专注度」信号，喂给 judge/disturb——专注时只静默记录、不弹建议。

**P1-2 主动建议的「事后反馈」闭环**
- 现状：SuggestionToast 有接受/忽略，但没回流到 trust（与 P0-2 合并解决）。
- 补充：主动建议在「被接受后」要形成记忆（「他喜欢在周一早上要进度摘要」），让主动本身也「越用越懂」——当前 `_maybe_proactive_close_loop` 已有雏形，强化为长期行为模式学习。

### P1 · 陪伴的温度（把「伙伴」做出来）

**P1-3 桌宠日记产品化（第一人称的一天总结）**
- 现状：`memory/daily/*.md` 已在逐日记，但用户看不到，也没有「第一人称」表达。
- 借鉴：QQ 宠物复活「以第一人称写日记留存日常」；Sion 的 L1 情感日记。
- 落地：① 把 daily 日记转成墨灵视角的「今日小结」（今天陪你做了什么、学到什么、你夸了它什么），可在 DeskHome 翻开；② 每周/每月自动生成「我们的回忆」（对话数、一起完成的创作进度、解锁的徽章、学到的偏好）——这是「伙伴」感最强的抓手，投入小。

**P1-4 表情系统按既有设计稿落地（Manifest + 语义标注）**
- 现状：规划稿已成（`docs/emote-system-design.md`），三招：系统侧语义标注 + 结构化词表注入 + few-shot。
- 借鉴：sticker-reply-skill 的清单标准；Tuya closed-vocabulary。
- 落地：按 P0 止血（语义标注+词表+few-shot）→ P1 Manifest 化。表情是陪伴产品的「情绪接口」，值得这轮做。

### P1 · 创作场景深度个性化（护城河加固）

**P1-5 写作风格画像「量化 + 自动更新」**
- 现状：`style_profile.json` + vault `preferences/萧盛写作风格.md` 已存在，但风格是静态文档。
- 借鉴：写作工具的「风格实验室」/`/style-learn`；Mem0 的自动提取。
- 落地：① 每次创作/审稿后自动抽取风格信号（句长分布、文言比例、叙事视角、考据密度）增量更新风格画像，让「风格懂你」随作品演进；② 在创作流水线里注入「当前风格画像」，让圆桌专家输出自动对齐文风。

**P1-6 圣经回流 + 版本化闭环强化**
- 现状：after_action 已做创作→圣经回流；novel_memory 有 SQLite 快照。
- 落地：把「一次创作产出的设定/人物/史料自动 upsert 进圣经」链路做成可见可回滚的（用户可在面板看到「圣经新增了 3 条实体，来自《国子监秘闻录》第 4 章」）——让「越写越懂你的书」成为可感知卖点。

### P2 · 更远的「懂你」（可选，作为路线储备）

- **后台自动提炼（对标 Dreaming）**：在空闲时对近 N 天对话做一次「记忆综合/矛盾消解/过时更新」的静默任务（decay_memory 已在此方向），让记忆自我进化。
- **记忆向量检索真正用起来**：`vectors.json` 已 1.1MB，但检索链路是否真正用于 prefetch 待确认——若已用，做质量审计；若未接，接入 Recall/Archival 层。
- **长期模式学习**：从「记住了你说过的话」升级到「从行为模式推断偏好」（如「你连续 3 周把周四的审稿推到了周五 → 周四别排审稿」），这是「越用越懂」的最高阶形态。

## 五、优先级总表

| 优先级 | 动作 | 一句话理由 | 投入 |
|---|---|---|---|
| **P0-1** | 记忆注入默认开启 + 状态可见 | 写了记忆没用上 = 白写 | 小 |
| **P0-2** | 反馈→信任/成长闭环 | trust 恒 0.5，反馈闭环没闭合 | 中 |
| **P0-3** | 记忆引用回显 + 记忆面板 | 让「懂你」被看见、可管理 | 中 |
| **P0-4** | Mem0 四操作去重 + USER.md 清洗 | 画像在注水，原料不干净 | 中 |
| **P0-5** | 记忆分层净化 + 时间感知 | 书的记忆和你的记忆要分开 | 中 |
| **P1-1** | 打扰分寸接入专注度 | 主动要懂「时机」 | 中 |
| **P1-2** | 主动建议事后反馈 | 主动本身也要越用越懂 | 小 |
| **P1-3** | 桌宠日记产品化 + 每周回忆 | 「伙伴」感最强抓手 | 中 |
| **P1-4** | 表情系统落地 | 陪伴产品的情绪接口 | 中 |
| **P1-5** | 写作风格画像量化 | 护城河：越写越懂你的文风 | 中 |
| **P1-6** | 圣经回流可见可回滚 | 越写越懂你的书 | 小 |
| **P2** | 后台自动提炼/向量/模式学习 | 长期路线储备 | 大 |

## 六、落地节奏建议

1. **第一批（1 周内，止血）**：P0-1 + P0-4 + P0-3 的记忆引用回显。这三条分别解决「没用上、不干净、看不见」——是「越用越懂你」体感的三个最短缺项，投入小、见效快。
2. **第二批（2-3 周，闭环）**：P0-2 反馈闭环 + P0-5 分层净化 + P1-3 日记产品化。让成长数值真正动起来、让伙伴感出来。
3. **第三批（1 个月，差异化）**：P1-1/P1-2 主动分寸 + P1-5/P1-6 创作深度个性化。把「会主动、懂时机、懂创作」做成墨灵独有的标签。
4. **第四批（储备）**：P2 后台自动提炼——这是对标 ChatGPT Dreaming 的远期形态，等前三批跑稳再做。

> 一个建议的验证方式：每批上线后，观察 growth.json 里 trust/默契度的真实波动、USER.md 的重复率、以及「用户主动说'它居然记得'」的频次——这三个就是「越用越懂你」的硬指标。

## 八、补充：盲区与盲点（二次评审）

> 底稿整合后二次评审新增：一条贯穿性设计原则（萧哥提出）+ 六条盲区（代码复核所得）。
> 这 7 条与正文 P0–P2 不冲突，是正文未覆盖的增量，作为后续实施的**额外约束与验收标准**。

### 8.0 贯穿性设计原则（萧哥）：懂你 = 前后端一体，可感可看

> 「要让『越用越懂你』能**感受到、看得到**，这就决定了在设计时，不只是后端做到了，**前端视觉化的设计要同步跟上**。只有前后端都做到『越用越懂你』了，用户才能感受得到，才会产生**温暖、被懂得**等感受。」

这条原则对正文计划的含义：

- **P0–P2 每一项都要带"前端可视"验收标准**，不能"后端闭环了就算完成"。P0-4（引用回显+记忆面板）只是这条原则的起点，不是全部。
- **前端视觉化的落地清单**（配套各 P 项）：
  - 了解度可视化：AI 对你的了解，用可量化、可回看的形态呈现（UnderstandingCard 升级版，含"本周新了解了什么"时间线）；
  - 记忆时间线：记住/修正/遗忘的事件流，让"记忆在生长"肉眼可见；
  - 成长轨迹：亲密度/信任/默契度的历史曲线 + 触发事件（"因为 8/3 你接受了我的建议，信任 +2"），数值变动要有因有果；
  - 桌宠情绪反馈：表情/动作与成长状态联动，让"被懂"透过桌宠的微表情传达；
  - 主动建议的"为什么现在提醒"：弹建议时自带一句"看你最近在赶稿，进度摘要提前给你"，让主动也可见。
- 前端看板与后端记忆共用**同一数据源**（复用 `/v1/deskmate/*` 已有接口），不另造一套，避免"后端有数据、前端不展示"的断层。

### 8.1 记忆质量评测集（方向盘）【盲区】

- 现状：`tests/` 已有 `test_deskmate_memory/growth/novel_memory/proactivity` 等**功能测试**（接口能跑通），但无**质量评测**（"问 50 题能答对几题"）。正文第七章的验证指标是运营指标，无法自动验证"是不是真的更懂了"。
- 借鉴：Mem0 用 LongMemEval/LoCoMo 基准评测记忆系统；我们应建自己的轻量评测集。
- 落地：建一份针对萧哥真实场景的**记忆评测集**（≈50–100 题：偏好/项目/写作风格/圣经实体/避讳），每次改记忆逻辑（P0-5 去重、P0-6 分层、P2 提炼）跑一遍，量化召回率/正确率，防回归。**没有它，P0–P2 每个改动都无法证明"更懂了"还是"改坏了"。**

### 8.2 成长数值的"长跑设计"（防半年后死掉）【盲区】

- 现状：`intimacy 97.5 / empathy 91 / level 7`——亲密度已近封顶。
- 问题：成长类产品的经典死法——数值通胀后升级越来越慢、封顶后无动力，"越用越懂你"变成"三个月就懂了"。
- 落地：① **深度成长轨道**：数值满后转向"对既有偏好的细分/校准"（如亲密度满 → 追求"默契细分"，懂得更细而非更多）；② **封顶后的长期轨道**（关系深化、历史里程碑），保证数值满了体系仍在进化；③ 数值增长附**触发事件**（供前端 8.0 展示"为什么涨"）。

### 8.3 记忆全生命周期透明：溯源 + 遗忘可见【盲区】

- 现状：正文 P0-4 有"引用回显"（前瞻式：因为你说过 X 所以我……），但缺后半。
- 溯源：用户质疑某条回复时，能查"这条回复基于哪条记忆"。落地：记忆条目带 id，回复日志记录"本轮注入了哪些记忆 id"，可回溯——信任建设的硬能力。
- 遗忘可见：P0-6 讲"过期自动归档/弱化"，但没讲"忘得被看见"。用户改掉偏好后 AI 还按旧的回，用户会觉得"它根本没懂"。落地：decay/归档发生时前端留痕（"这条旧偏好 8/29 已归档"），**遗忘与记忆一样透明**。

### 8.4 敏感信息分级（合规底线，P2-8 的前置条件）【盲区】

- 现状：USER.md 已存"7 岁儿子""家庭情况"等敏感信息，正文未提隐私治理。
- 落地：记忆条目分级（普通/敏感/隐私），敏感条目标记、不进日志、可选不参与未来云同步；**涉及未成年人信息尤其谨慎**。没有敏感信息治理，"合规轻陪伴"定位（P2-8）是空话。

### 8.5 画像的迁移与扩展：冷启动 + 跨项目【盲区】

- 冷启动：正文全在打磨"越用越久"，未提"第一次用"。落地：onboarding 引导填基本信息 + 导入已有 vault/项目资料，把"从零开始懂你"压缩成"几天内开始懂你"。
- 跨项目迁移：`projects/` 已有 30 个项目（含 uuid 临时项目），萧哥真实路径是明朝→宋朝→新题材。落地：换新书时，全局偏好/写作风格/查史料铁律**自动注入新项目**——决定"开新书后 AI 还懂不懂你"。

### 8.6 记忆写入节流与成本（工程侧，间接决定质量）【盲区】

- 现状：每轮 `sync` 暂存 + LLM 提取 + after_action 一路后台 LLM 调用，无节流/失败监控。
- 问题：写得太多=噪音（污染注入预算）、写得太少=漏，且 token 成本不可控。
- 落地：同主题合并写入（参考 Mem0 四操作的 UPDATE 收敛）、批量处理、失败率/成本监控。
