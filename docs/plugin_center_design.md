# 插件中心（Plugin Center）架构设计

> 演进自 `docs/qwenpaw_benchmark.md` 第五节。
> 核心判断：**MCP 已是国内外大厂共识标准**（OpenAI / Anthropic / Google + 通义 / 腾讯混元 / 字节 / 百度 全部支持）。
> **MCP 兼容 = 同时兼容所有大厂 = 天然拿到数千现成 MCP Server。**
> 据此把「专家中心」升级为「插件中心」：聚合大厂 + 社区 MCP 插件，一键接入即用。

---

## 一、一句话定位

**专家中心 → 插件中心：内置专家（创作大脑）保留为垂直深度，外部 MCP 插件（手脚/工具）聚合大厂与社区，用户一键接入，圆桌/专家/对话即时可用。**

---

## 二、为什么是 MCP，而不是逐个对接大厂

- **国内大厂已全部押注 MCP**：
  - 阿里百炼 **One Key MCP**（2026-08-05 上线）—— 一个 API Key 调全部 MCP 服务，首批 14 家伙伴（高德、东方财富、恒生聚源、得理法律、e签宝…）；Qwen3 原生支持 MCP。
  - 腾讯元器 —— 把 Agent / 插件直接**转成 MCP Server**（`tcb.cloud.tencent.com/mcp-server/...`，含 OCR、PDF 解析、搜狗搜索、文生图、微信支付…）。
  - 字节扣子空间集成 60+ MCP 扩展；百度千帆平台上线 MCP（全球首个电商交易类 MCP）。
- **国际**：OpenAI、Google 均已支持 MCP；MCP.so 收录 11000+ MCP Server，魔搭社区 2900+。
- **结论**：做一层 **MCP Host**，吃下所有大厂 + 社区插件，一层适配 = 原生支持全部生态，不用逐个对接、不用自建市场。

---

## 三、插件中心的两类插件（同一套 UI，两种性质）

### 类别 1：内置专家（创作能力，**非 MCP，是咱们的魂**）
- 编辑专家 / 大纲专家 / 人物专家 / 润色专家 / 设定一致性专家。
- 护城河：人物圣经 v2、逐章编校、修订回顾、after-action 记忆、勋章陪伴——这些通用助手填不满。
- **不退化、不外卖**。改造项 A/B 落地后，从硬编码 `experts.ts` 数组改为文件清单（`EXPERT.md` + manifest 路由），即"内置插件化"。

### 类别 2：MCP 插件（外部能力，手脚/工具）
- **国内大厂官方**：阿里百炼 One Key MCP、腾讯元器、字节扣子、百度千帆。
- **垂直领域**：金融（东方财富/恒生聚源/盈米）、法律（得理/e签宝）、地图（高德）、搜索（搜狗）、效率（OCR/PDF/文生图）。
- **国外精选**：GitHub、Brave Search、Fetch、Sequential Thinking 等优秀独立 server（cherry-pick，不铺量）。
- **社区**：MCP.so 11000+、魔搭 2900+ 中筛选。

> 解读（待萧哥确认）：国内走「大厂官方打包」；国外不铺大厂量、而是 cherry-pick 优秀独立 server。若想"国内外大厂都进"也行，只是国外大厂 MCP 暴露度参差，策展策略不同。

## 四、接入即用流程（build-before-swap，对标 QwenPaw `reload_driver`）

```
用户在插件中心看到卡片（图标/描述/能力标签/安全评级/来源）
   ↓ 点击「添加」
填 Key / endpoint（大厂 One Key 只需一个 API Key；标准 MCP 填 endpoint+key 或导入配置）
   ↓ 后端写 drivers/<protocol>/<name>.yaml
DriverManager 热插拔：先建新连接成功再原子替换，失败保留旧连接（不断服务）
   ↓
圆桌 / 专家 / 对话 立即可用，无需重启
```

## 五、策展与安全（关键，不能裸接几千个）

- **不 dump 全量**：分类导航（厂商 / 领域 / 权限等级）+ 精选置顶（官方认证 + 安全扫描通过）+ 搜索 + 标签。
- **安全评级**：只读 / 写入 / 需凭据 / 是否经安全扫描。
- **默认 `ask` 策略**：写操作需用户确认；只读检索类可 `allow`。
- **护栏沿用**：CRITICAL 拒杀 + 写入路径作用域；借鉴 QwenPaw 技能安全扫描，对插件做静态检查（危险 shell、反向 shell、越权路径）。

---

## 六、专家与 MCP 插件的协作模型（重要，避免"专家被插件吞掉"）

- **内置专家 = 创作大脑**：规划、角色扮演、垂直判断（如编校、圣经核验）。
- **MCP 插件 = 手脚**：查实时数据、调外部服务、执行操作。
- **圆桌里协作**：专家规划 → 按需调用 MCP 工具查证/取数。例：编辑专家要核实某历史官职/地名，调用搜索/百科/高德 MCP 取证；设定一致性专家要查时间线，调用检索类 MCP。
- **效果**：专家不退化，反而因有了"手脚"能落地查证，幻觉护栏（圣经 + MCP 实测）双保险。

## 七、分阶段落地（与 `qwenpaw_benchmark.md` 改造项对应）

| 阶段 | 改造项 | 内容 | 工期 |
|---|---|---|---|
| P1 | A + B | 专家文件化 + manifest 路由（专家中心先统一成"插件清单"数据结构） | ~1 天 |
| P2 | E | 圆桌 MCP Host（真正能接 MCP，把"插件中心"从概念变可跑） | ~2 天 |
| P3 | — | 插件中心 UI：聚合大厂目录 + 一键添加 + 安全评级 + 策展分类 | ~3 天 |
| P4 | — | 策展本地化：预置中文场景精选列表（历史考据/创作/效率） | ~1 天 |

> 优先 P2：它是"接入即用"的引擎，最有说服力；P1 是前置（统一数据结构）。

---

## 八、与 QwenPaw 的本质区别（咱们的定位）

- QwenPaw 是**通用个人助手**，插件广度优先，无垂直深度。
- 咱们是**历史小说创作伴侣**：内置专家（创作大脑）是差异化内核，MCP 插件是"借来的手脚"。
- 插件中心不追求"插件数量最多"，而追求"创作场景最顺"——精选 + 策展 + 与专家/圆桌深度协作。
