# 小云雀 AI 短剧 · 剧本生产机制 vs 我们创作流水线：借鉴分析

> 调研日期：2026-09-09
> 目的：研究小云雀的剧本生产流程，对照我们（OpenWorker / 桌搭 `deskmate/creation/`）的创作流水线，找出可借鉴点，同时划清不可照搬的红线。
> 结论基调：**小云雀是「流量驱动的短剧剧本工厂」，我们是「史料严谨的个人作者声口创作台」——它值得学的不是题材/爆款逻辑，而是「剧本质量的工艺化评测」与「对话式共创体验」**。

---

## 0. TL;DR（关键结论）

- **最值得学的一点**：小云雀把"什么叫好剧本"拆解成 **结构 / 角色 / 节奏** 三维度 + **六大评测维度**（剧本内容、开篇亮点、主线架构、节奏把控、角色塑造、剧本可用率），并让评测回灌生成。**我们终审目前只有 4 个定性维度 + 二元 verdict，缺"量化评分卡"和"可用率"指标。**
- **我们已经比它强的部分**（不必学）：改编圣经 + 创作回流、文风指纹（萧哥声口量化）、史料检索与版权红线、圆桌多专家知情批准。
- **它有的体验我们可以尝试**：① 对话流共创（我们的 `chat_flow.py` 已在做，可对齐"选中段落精修"）；② 版本对比/回退（我们的 docx 已带时间戳留痕，缺的是应用内对比 UI）。
- **绝对不能学**：流量/爆款驱动逻辑、热点追投、把"AI 腔"当卖点——这与萧哥"重考证、反对正史一元论、去 AI 腔"的创作观直接冲突。

## 1. 小云雀剧本生产机制拆解（基于公开资料）

来源：小云雀官网 `xyq.jianying.com`、百度百科词条、多篇实测报道（搜狐/今日头条/APPSO）。

### 1.1 自研剧本模型 ScriptBird + "好剧本公式"
小云雀把剧本生成定义为围绕三个条件的工程，而非"文字生成"：
- **好结构**：开篇快速建立核心矛盾；主线清晰、冲突持续升级；阶段目标明确、前后因果成立。
- **好角色**：人物目标/动机/阻力明确；关系有张力与变化空间；行为符合人设、推动剧情。
- **好节奏**：信息释放紧凑、减少无效铺垫；每集有推进/反转/情绪回报；集尾留悬念驱动持续观看。

### 1.2 六大维度评测体系（层层校准 AI 创作质量）
剧本内容、开篇亮点、主线架构、节奏把控、角色塑造、**剧本可用率**。横向测评显示其综合效果领先同类产品。
> 关键点：评测不是"写完给人看"，而是**生成回路的校准器**——先定义好剧本的标准，再让模型朝标准收敛。

### 1.3 三阶段创作流
**故事设定 → 分集大纲 → 剧本正文**，阶段清晰、层层推进，全程支持编辑调整。

### 1.4 对话流共创
从"一张图/一句话/一种情绪"开始，AI 沿想法追问、延展、补足；用户可**选中具体段落引用到对话框做精细修改**（"像和编剧讨论一样")。

### 1.5 版本管理
保存不同阶段创作结果，查看并比较不同版本区别，新方向不如预期可回退。

### 1.6 多场景覆盖
- **小说改编**：上传小说原文 → 提炼主线/人物/高价值情节 → 改成分集剧本。
- **出海改编**：保留核心冲突/动机/情绪，对语言/关系/文化/节奏做本土化改写。
- **连载剧**：围绕已有故事/角色/世界观续写。
- **解说剧**：剧本正文阶段切"旁白型剧本"。

### 1.7 编辑部式全链路（超出剧本生产，但构成其体验）
自由画布（串联角色/服化道/场景）+ 3D 导演台（白模调试运镜机位）+ AnyCook（角色形象/场景氛围）+ 后期剪映打通。长剧本上限 10 万字 / 100 集。

## 2. 我们的创作流水线拆解（`deskmate/creation/`）

代码事实（非设想）：
- **编排** `pipeline.py`：7 阶段状态机（创建→写大纲→审大纲→主编拍板→写剧本→审剧本→主编拍板→done）+ `PipelineGuard` 串行门禁（"大纲定稿才开写剧本"）。
- **执行器** `executor.py`：双执行器（Stub 零 LLM / LLM 真调用），`_requirement_block` 把风格/节奏/集数/文风指纹拼成"必须严格遵守"的硬约束注入 prompt。
- **终审** `final_review.py`：圆桌 7 专家按 **4 维度** 研讨——**史实核验 / 文笔修辞 / 结构节奏 / 市场适配**；混合式"知情批准"（四要素提案 → 选专家 → SSE 研讨 → synthesis → `VERDICT: APPROVE/REJECT` 回灌）。
- **改编圣经** `novel_index.py` + `bible_feedback.py`：原著索引 + 章节目录 + 创作回流（定稿后把新出现的关键词候选回流进 `bible.md`，幂等、带回流日志、可回滚）。
- **文风指纹** `style_profile_store.py`：量化萧哥声口（句长节奏/四字格/文白比例/对话占比/标点节奏），终审时强制评判"是否贴合"。
- **分集模式**：每集独立建项/撰写/审核/拍板/导出 docx；`extend_episodes` 加集续写 + 前情档位（`prior_context`）。
- **版本留痕** `docx_export.py`：文件名带时间戳（`{title}_{kind}_{ts}.docx`），"永不覆盖历史定稿"。
- **对话流化重构** `docs/creation-chat-redesign.md` + `chat_flow.py`（37KB，已落地雏形）：把状态机降级为数据层，用户是导演、专家是可召唤顾问，创作即对话。

## 3. 逐项对比表

| 维度 | 小云雀 | 我们（OpenWorker） | 差距 / 可借鉴点 |
|---|---|---|---|
| **好剧本定义** | 结构/角色/节奏三维度显式公式 | 隐含在 prompt + 4 终审维度 | 我们没把"好剧本公式"当显式约束，可借鉴其结构化 |
| **质量评测** | 六大维度评分 + 可用率指标 | 4 维度定性研讨 + APPROVE/REJECT 二元 | **缺量化评分卡 & 可用率** → 借鉴重点 |
| **创作阶段** | 故事设定→分集大纲→剧本正文 | 大纲→剧本→定稿（分集模式对位） | 结构对位，基本一致 |
| **对话共创** | 一句话起聊、选中段落精修 | chat_flow 已做雏形 | 对齐"段落引用精修"体验 |
| **版本管理** | 版本对比 + 回退 UI | docx 已带时间戳留痕，但无应用内对比 UI | 补"对比/回退"交互层 |
| **小说改编** | 上传小说一键转分集剧本 | 已有 novel_index + 圣经（更扎实） | 包装成"上传→建圣经→一键出大纲"向导 |
| **热点/受众** | 红果/抖音热点库、爆剧元素 | 市场维度靠专家经验，无数据 | **不能照搬流量逻辑**，可换为"史料稀缺性/选题价值" |
| **史料严谨** | 无 | 史料库 + 正史/演义分层 + 简繁变体 + 版权红线 | 我们强项，不必学 |
| **作者声口** | 通用模型，无个人对齐 | 文风指纹量化对齐萧哥 | 我们强项 |
| **多专家终审** | 剧本助手（单模型） | 圆桌 7 专家 + 知情批准 | 我们更深 |
| **成片链路** | 画布/3D导演台/剪映直出 | 仅文字创作，落到 docx | 超出我们范围，不动 |

## 4. 可借鉴点（按优先级）

### P0 — 直接补我们短板

**A. 在终审引入"结构化评分卡 + 可用率"**
- 现状：终审是 7 专家写定性意见 + 二元 verdict，萧哥难以一眼判断"这版离定稿还差多远"。
- 借鉴：在 `final_review.py` 的 `REVIEW_DIMENSIONS`（史实/文笔/结构/市场）基础上，要求每位专家按维度打 **0–3 分或 0–100 分**，并额外产出 **"剧本可用率"** 综合分（对齐小云雀第六维）。
- 价值：把"主观研讨"变成"可量化、可对比、可迭代"的质量基线；多次定稿能看出趋势。
- 风险可控：评分只作参考，最终拍板仍是萧哥（知情批准不变）。

**B. 把"改编圣经 + novel_index"包装成向导式入口**
- 现状：我们有比小云雀更扎实的圣经机制（`bible.md` + 创作回流 + 幂等日志），但入口分散在后端，用户体验是"上传原著→手动跑索引"。
- 借鉴：对齐小云雀"上传小说一键转剧本"的流畅 UX——做成 **「上传原著 → 自动建圣经 → 一键出分集大纲」** 向导，前端一步走完。
- 价值：降低严肃改编的起步门槛，同时保留我们的史料严谨性（这是小云雀没有的护城河）。

### P1 — 体验对齐

**C. 应用内版本对比 / 回退 UI**
- 现状：docx 已带时间戳留痕（`docx_export.py` 确认"永不覆盖"），但用户要在 `output/` 文件夹里翻文件才能比较。
- 借鉴：小云雀的"版本对比 + 回退"交互——在创作界面内列出历史版本，支持并排 diff / 一键回退。
- 价值："试错更安全"，呼应萧哥"可见可回滚"红线。

**D. 对话流"选中段落精修"体验对齐**
- 现状：`chat_flow.py` 已在做对话流化，但"选中具体段落引用到对话框做精细修改"这一交互是否完整待确认。
- 借鉴：对齐小云雀——用户在产出卡里选中某段，直接拖入对话框要求局部修改，而非整篇重写。

**E. 短剧/章节特有的显式检查项**
- 借鉴：把小云雀的"开篇亮点 / 集尾悬念钩子"显式做成终审核查清单项（即便我们写小说不追求"集"，也可对应"章首钩子 / 章尾留悬"）。
- 价值：把"节奏把控"从抽象维度变成可勾选的具象检查。

### P2 — 视情况（需警惕）

**F. "热点库"概念 → 改造为"选题价值库"**
- ⚠️ **不能照搬**：小云雀的热点库是抖音/红果流量逻辑，与萧哥"重考证、反对正史一元论、不追流量"的创作观冲突。
- 可行改造：把"热点"换成 **"史料稀缺性 / 选题新颖度 / 可考据支撑度"** 的轻量参考库——帮萧哥判断"这个历史切口是否值写、史料是否撑得住"，而非"是否容易爆"。

## 5. 红线：哪些绝对不能学

1. **流量/爆款驱动逻辑**：小云雀一切为"命中用户兴趣、提升播放/留存"。萧哥的创作是史料驱动的严肃历史小说，**冒然引入"爆款元素""钩子密度优化"会污染创作意图**。
2. **把"AI 腔"当效率卖点**：小云雀追求"快速成片"。我们专门用文风指纹**去 AI 腔、对齐萧哥声口**，这是差异化优势，不能丢。
3. **一键直出成片 / 视频生成链路**：那是短剧工具的主场，超出我们（文字创作台）范围，且涉及真人素材版权等萧哥红线，不参与。
4. **弱化作者主体地位**：小云雀是"AI 编剧替你写"。我们的定位是"AI 是顾问，萧哥是导演/终审"——知情批准、打回闭环不能简化成全自动。

## 6. 落地建议（下一步，待萧哥拍板）

| 序号 | 动作 | 对应借鉴 | 预估工作量 | 备注 |
|---|---|---|---|---|
| 1 | 在 `final_review.py` 加 `scorecard`：4 维度打分 + 可用率 | A | 中（需改圆桌 synthesis prompt + 解析） | 评分仅参考，拍板权不变 |
| 2 | 前端创作视图加"历史版本"列表 + 并排对比/回退 | C | 中 | 数据已有（时间戳 docx），只补交互 |
| 3 | 包装 novel_index 为"上传→建圣经→出大纲"向导 | B | 中 | 复用现有 `NovelIndex` + `bible_feedback` |
| 4 | 对齐 chat_flow 的"段落选中精修"交互 | D | 小 | 先确认 chat_flow 现状再补 |
| 5 | 终审核查清单加"章首钩子/章尾留悬"显式项 | E | 小 | 纯 prompt/UI 增强 |
| 6 | 评估"选题价值库"（非热点库）可行性 | F | 待定 | 需先确认萧哥是否有此需求 |

**建议顺序**：先 1（评分卡，直接补质量基线短板）→ 3（圣经向导，放大我们已有优势）→ 2（版本 UI，低成本高感知）。4/5/6 视资源推进。
