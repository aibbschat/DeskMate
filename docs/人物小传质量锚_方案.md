# 人物小传质量锚 · 实施方案

> 借鉴小云雀 AI 短剧「喂原著 → 出分集大纲 + 人物小传」思路：分集大纲 + 人物小传是
> 保证「质量不掉、前后不矛盾、人物不漂移」的核心锚。本方案只取「质量锚」这一层，
> 不引入其流量/爆款驱动逻辑（与萧哥「重考证、去 AI 腔」创作观冲突，红线不改）。

## 现状（已查清）
- 分集大纲 ✅ 已实现并每集重注入（`pipeline.py:644` `_outline_text()`）。
- 前情衔接 ✅ 已实现（`_prior_context_block` 注入前集摘要 + 上集全文 + 审改意见）。
- 加集续写 ✅ 已实现（`extend_episodes` 链同一大纲、继承风格）。
- **人物小传 ❌ 无独立 artifact**：全 `deskmate/creation/` 搜 `人物小传/character_profile`
  零命中；人物一致性靠大纲文本 + 圣经 `novel_text` 间接锚定，不能「改一次小传、全剧生效」。

## 目标产物
新增一个**独立持久化「人物小传」文档**（`char_profiles`，单份 markdown），作为
每集剧本创作的「防人物漂移硬锚点」。设计对齐既有 `_episode_summaries` / 圣经 的
持久化范式（落盘进 `<base>/creation/<space>.drafts.json`，重启/跨生成复用）。

## 改动清单
### 1. `deskmate/creation/pipeline.py`
- `__init__`：新增 `self._char_profiles: str = ""`（与 `_episode_summaries` 同区）。
- `_save_drafts()` / `_load_drafts()`：增 `_chars` 键的落盘与恢复。
- 新增 `extract_characters(*, force=False)`：
  - 源：有原著取 `_novel_context("bible")`（圣经最全），否则取大纲文本；
  - LLM 可用 → `_extract_chars_llm(source)` 产出结构化小传；
  - LLM 不可用 → `_chars_from_bible_stub(source)` 从圣经 markdown 抽「人物」段降级；
  - 幂等：已有且不 force 直接返回；结果落盘。
- `draft_outline()`：调 executor 时多传 `character_profiles=self._char_profiles`。
- `draft_screenplay()`：写剧本前若尚无小传且有关联原著，`extract_characters()` 自动生成；
  调 executor 时多传 `character_profiles=self._char_profiles`。

### 2. `deskmate/creation/executor.py`
- `CreativeExecutor.draft_outline` / `draft_screenplay` 协议签名加 `character_profiles: str = ""`。
- `StubExecutor` 两法加参（标签带字数，便于验证注入）。
- `LLMExecutor.draft_outline` / `draft_screenplay`：拼 `character_block`
  （防漂移硬锚点段，铁律：动机/性格/弧光/关系须一致，禁 OOC），非空才注入。

### 3. `deskmate/creation/service.py`
- `extract_characters(pid, *, force=False)`：调用并返回 `char_profiles` + ready。
- `set_char_profiles(pid, text)`：用户手改入口，落盘。
- `snapshot(pid)`：增 `char_profiles` / `char_profiles_ready` 字段（前端可预览/编辑）。

### 4. `tests/test_char_profiles.py`（新增）
- 抽取：monkeypatch `llm_available`/`chat` 验证 LLM 路径产出结构化小传；
  不配 LLM 时验证降级抽取非空。
- 注入：monkeypatch executor 捕获 kwargs，验证 `draft_screenplay`/`draft_outline`
  把 `char_profiles` 透传给 executor。
- 持久化：`_save_drafts` → 重建 pipeline → `_char_profiles` 恢复。

## 不动的红线
- 不碰神圣稿件；不改圣经/史料机制；不引入流量/爆款逻辑。
- 不新增 LLM 调用于创建路径（抽取延迟到「首次写剧本/手动触发」，避免创建时烧 token）。
- docx 导出、门禁、终审链路均不受影响（小传只是多一段注入上下文）。

## 验证
- `pytest tests/test_char_profiles.py -q` 全绿。
- 人工 smoke：stub 模式建分集流水线 → 大纲定稿 → 写第 1 集时自动生成人物小传 →
  snapshot 可见 `char_profiles`；手改后第 2 集小传生效。
