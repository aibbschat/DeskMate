**auto_tasks 统一框架实施记录（2026-08-30，本 Agent）**：

**背景**：用户设定了两项自动化定时任务——①每日读书（已连续读十几天，至少读完六七本）②每日跟进正在写的书。调研发现：

- 进度跟踪的伏笔/人物状态只在 session 里，没有结构化保存
- 完全没有体现在「它眼中的我」或任何"越用越懂你"面板里

**架构设计**：统一的「自动任务沉淀框架」，所有与"我/写作/作品"相关的自动任务都走同一条管道：
- 统一数据模型（TaskRecord/Insight/TaskRegistryEntry）
- 统一沉淀管道（timeline.jsonl + insights/<type>/ + details/<type>/）
- 统一 API（GET stats/timeline/insights + POST record）
- 统一展示（「它眼中的我」第 7 栏目「📖 作品与创作」，按任务类型分组+朋友圈式文章）
- 新任务接入只需两步：登记 + 调用 record API，自动落地/自动分类/自动展示

**实施内容**：
1. **后端框架** `deskmate/auto_tasks/`：models.py（数据模型）+ registry.py（任务注册表）+ recorder.py（统一沉淀 API）

3. **前端栏目** `deskmate/alter_ego/portrait.py`：新增第 7 栏目 `_auto_tasks_section()`，从 auto_tasks 框架聚合数据，自动渲染（前端 AlterEgoPage 零改动，因为栏目是动态渲染的）
4. **数据抢救** `scripts/rescue_auto_tasks.py`：从 session 记录抢救 5 条历史数据（2 条读书 + 3 条进度跟踪），明朝的裂变补充 4 条结构化洞察
5. **接入指南** `docs/auto_tasks-接入指南.md`：定时任务怎么调用 API 沉淀结果

**当前数据**：5 条记录（已读 2 本 / 跟踪 3 次 / 沉淀 4 条洞察 / 持续 3 天）。更早的 session 已被清理无法抢救，建议从现在起所有定时任务接入 auto_tasks 框架。
