# 专职 Bot 形态约定：独立专家优先（不进群聊、不挂共享记忆）

> 固化自 2026-11-08 实测验证。萧哥原话：「把脑洞 bot 从圆桌/预设/资料里捞出来做成独立专家，效果明显比在群聊里好；共享记忆是当年省钱省时的决定，但实测发现所有人都顺着记忆说、记忆还可能过时，还是拔了吧。」

## 结论（结论先行）

专职感强、单一职责的创作 / 分析角色（脑洞、编剧、审稿、主编、史料、类型、读者等），**默认建成「独立专家」形态**：

- **一对一深聊**，不进圆桌、不做群聊成员；
- **不挂 `deskmate-memory` 等共享记忆 MCP**（允许按需保留 `novel-memory` 这类只读素材库，但不是默认）；
- 取材用自带 `files` / `shell` 工具在 `~/.deskmate/vault/` 下**自行定位、按需通读**，不必每轮等用户喂路径（用户直接给路径则优先用那份）。
- **默认只读正文，先读停笔点**（2026-11-08 补）：正文以外的大纲 / 粗纲 / 简报 / 圣典 / 旧记忆默认不看——它们可能过时且会把脑洞锚在旧判断上；要核对作者裁定或史实，先问一句或只查他点名的文件。群聊侧的等价实现见 `deskmate/bots/reading.py`（按章切分 + 开头/停笔点 + 覆盖率诚实 + 经验层只剩作者裁定）。

群聊 / 圆桌只保留**轻量协作与调度**，不再承载「专职深度产出」角色。

## 为什么（已实测验证，非推断）

1. **群聊稀释产出**：群聊里多角色争抢同一段上下文窗口 → 角色冲突 + 注意力稀释 → 输出飘、收不住。
   证据：脑洞 bot 从圆桌捞出做成独立专家后，同一道题质量明显跃升——
   - 圆桌版：~1676 字、3 个方向，且有编造原文没有的物件（银簪 / 谚文 / 密令）；
   - 独立版：313 行、9 层战术 + 前文回收表 + 代价分析，每个动作钉死在正文第几章，连「水缸结冰」都标注「正文没写、你定要不要」。
2. **共享记忆会带偏所有人**：共享记忆是当年省钱省时的权宜；实测发现所有 bot 都「顺着记忆说」，且记忆可能过时 → 输出被陈旧共享状态绑架。拔掉 `deskmate-memory` 后，bot 只吃当轮你给的稿 / 路径，反而更准、更可控。

## 适用边界

- 这是**新建专职 bot 的默认形态**，不是立刻回改所有既有群聊 bot。编剧 / 审稿 / 主编等既有创作流水线角色，按萧哥 11-08 指示**暂先不动**。
- 轻量协作、调度、闲聊类角色仍可用群聊形态。
- 若某专职角色确需跨会话记住用户偏好，用**它自己的局部文件**（写进 vault 的项目目录），而非共享 global 记忆。

## 落地配方（照抄）

frontmatter：

```yaml
id: <role>
name: <角色名>专家
icon: <icon>
tagline: <一句话定位>
family: knowledge
tools: [files, search, shell, todo]
messaging: false
connectors: false
default_permission_mode: interactive
description: 独立<角色>专家，一对一深聊、只干<本职>、不进圆桌、不挂共享记忆。
# 注意：不要写 roundtable: true / roundtable_role；不要写 mcp: [deskmate-memory]
```

正文语气：**纯 1v1**，不写「群里接话轮 / 站队补一刀」这类群聊指令；取材写「用 files / shell 在 `~/.deskmate/vault/` 下自行定位通读」。

## 反例（不要这样）

- ❌ 把专职深度产出角色塞进圆桌 / 群聊当一员（多角色争抢窗口 → 输出飘）。
- ❌ 给专职 bot 挂 `deskmate-memory`（共享 global 记忆 → 顺着过时记忆说）。
