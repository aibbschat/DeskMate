## 0. 调研方法说明（避免"自嗨式对标"）

本报告所有竞品结论均来自 **2026-09-22 / 23 的联网检索**（Meta Muse、ChatGPT Dreaming V3 / Pulse、Claude、Gemini Spark、豆包、千问 / QwenPaw、Replika / Pi、Letta / Mem0 / Zep、Khoj、PAI·LifeOS，以及 Atomic Chat / InnerTalk / OpenHuman / ChatDock 等开源桌面端），并结合本仓库代码核对（见 §1 现状基线）。

**关于基准的可信度警示（重要）**：记忆层目前唯一公开的横向基准是 **LoCoMo**（多会话回忆）与 **LongMemEval**（跨会话知识更新）。但：
- 所有厂商数字 **均为自报**，无中立 2026 榜单；同一数据集上因评测口径不同，分数跨度可达 54 个百分点（如 Mem0 自报 92.5% vs 独立复现 58–66%；Zep 自报 94.7% vs 校正后 58.44–75.14%）。
- 因此本报告把基准当作 **"量级参考"** 而非精确排名，重点看**架构取向**与**产品能力**。
- LongMemEval 的核心结论可信且对我们有用：**商业聊天助手 + 长上下文 LLM 在持续交互中约有 30% 的准确率跌落**——这正是"记忆"这件事的独立验证价值。

## 3. 五层逐项差距分析

### 3.1 记忆层（差距最大、最该投）
- **检索质量**：我们是"关键词 + 中文 2-gram"，长中文句召回弱；语义检索虽已闭环，但**只在 `digested` 且有向量的条目上生效**——`digested` 无向量 = 既搜不到也补不上（已知健康指纹问题）。竞品 Mem0 多信号融合（语义+BM25+实体）、Zep 时序图，在 LoCoMo/LongMemEval 量级上明显更强（即便打折也远超纯 2-gram）。
- **时序/有效性**：我们没有"偏好何时变了"的概念；Zep 的双时态有效期是产品级能力。
- **记忆可控/可解释（信任与合规刚需）**：Replika 有用户可见可编辑的记忆面板，Claude 有按 Topic 否决权。**我们完全没有用户侧的记忆透明度**——而 2026-07 拟人化监管后，这既是合规需要，也是本地优先产品的信任卖点。
- **遗忘/衰减**：我们有 growth 衰减链路，但缺少"用户主动遗忘/纠正"入口。

### 3.2 感知层（中等差距）
- 我们有桌面活动/窗口/专注分 + 语音，但**只限于"当前活跃窗口"**，没有 Khoj/OpenHuman 那种"定时拉取本地 docs/笔记/邮件压缩成记忆树"的**结构化摄入管线**。
- "看世界"日记目前有 **9 条新闻被合并成 1 条**的已知 bug（PITFALLS），分条理解缺失。
- 感知是事件 tick 驱动，非持续富感知。

### 3.3 情感层（强项需守住，且有合规护城河）
- 我们有 emotion_sense 三闸门 + 规则日记 + mood 派生，**情感"内核"已成型**。
- **缺板是表达质量与一致性**：Replika 的"情感羁绊"来自长期一致的人格与日记，我们日记目前偏规则、且有多条合并 / chat 仅 10–20 字截断两个已知 bug 削弱"活人感"。
- **关键护城河**：我们是明确的"桌宠 / 非虚拟伴侣"（`compliance.py` 隔离）。2026-07 拟人化监管让豆包下线智能体、Replika 吃罚单——**维持非虚拟伴侣边界不是缺陷，是我们本地优先 + 合规的最大护城河**，绝不能为了"更像人"而越过。

### 3.4 认知层（从"存储"到"使用"的断层）
- 我们有 profile_items + worldview 层，**但认知目前主要是"存"，缺少"用"**：萧哥明确希望"小桔从观察世界积累 worldview/价值观，并用于判断用户写作（情节/框架/书评）"——这条推理回路还没真正打通。
- 竞品 Qwen 的"全域终身 Context"、LifeOS 的 TELOS（用户人生目标/信念）是更高层的认知建模，我们暂无。

### 3.5 意志/主动层（形态差异最大）
- 我们有 will 5 阈值 + GrowthEngine + InterviewEngine + proactive tick，但**主动性被限制在"app 打开时的 30s tick"内**，没有 Spark 的 24/7 云端执行、没有 PAI 的"当前态→理想态"闭环、没有用户可见的"计划任务/技能"抽象。
- **主动触发有收敛 bug**：访谈冷却 3 天欠账（点"稍后"只关窗不上报白吃冷却），需重打包前端修复。
- 高风险动作（写文件/发消息/删除）我们已有 L2 提议卡雏形，但未产品化为 Spark 式"审批网关"。

## 4. 我们的缺板（明确清单）

1. **记忆检索质量**：2-gram 长句召回弱；语义通道仅覆盖 `digested` 有向量条目；无时序有效性。
2. **记忆透明度/可控性缺失**：无用户可见可编辑的记忆面板（Replika/Claude 都有，且合规刚需）。
3. **感知摄入管线缺失**：无"定时拉取本地写作/笔记压缩成记忆"的结构化管线；"看世界"分条 bug。
4. **情感表达一致性 bug**：日记 9→1 合并、chat 10–20 字截断（已知，削弱活人感）。
5. **认知"存而不用"**：worldview 未真正用于写作判断回路。
6. **主动层形态受限**：app 打开才主动；无用户可见的计划任务/技能抽象；无审批网关；访谈冷却欠账 bug。
7. **（保持）本地优先 + 非虚拟伴侣边界**：这是护城河，不是缺板——列在这里提醒"守住"。

## 6. 风险与红线（贯穿全程）

- **Git 红线**：只推 `backup`（DeskMate fork）；绝不碰 `origin`、绝不 `--force`、绝不 rewrite 历史。
- **神圣稿件红线**：`国子监秘闻录` 等绝对不碰；任何感知摄入管线须显式排除。
- **形象红线**：小桔形象永不被皮肤替换；新视觉字段必须自描述（`hero`/`decorativeStamp`），皮肤图须纯景物且只放边角。
- **非虚拟伴侣边界**：维持 `compliance.py` 隔离——这是合规护城河，任何"更拟人"需求都不得越过。
- **安全策略**：权限 14 红（auto/bypass 报 `full access`）未定性，**禁擅自改安全策略**。
- **构建约束**：前端改动必须重打包；改动前用 `lsappinfo` 比 launch time 判"跑的是不是新代码"。

## 7. 结论

小桔的五层架构骨架（记忆/感知/情感/认知/意志）在同类开源/本地优先产品里**已属前列**——多数竞品仍是"单一记忆桶"。我们的真实缺板集中在三处：**记忆检索质量与可解释性**、**认知"存而不用"**、**主动层形态受限**。而 **本地优先 + 数据自主 + 非虚拟伴侣边界** 恰恰是 2026-07 拟人化监管后最稀缺的合规护城河，应作为核心卖点守住并放大。

建议节奏：**P0 先修正确性（信任）**，**P1 做记忆面板 + 主动任务抽象 + 认知写作回路（产品级跃迁）**，**P2 形态扩展留待拍板**。所有改动沿用阶段一的 trust-but-verify（读代码 → 加单测 → 本地回归 → commit 推 backup）。
