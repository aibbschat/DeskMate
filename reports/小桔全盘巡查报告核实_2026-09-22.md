## 三、确认的真缺陷与修复（7 处）

### 1. `inject.jsonl` 写放大 —— 每轮白烧 2.7MB IO ✅ 已修

```
条件：size > TRACE_MAX_BYTES(512KB)
截断：只保留最后 TRACE_MAX_LINES(2000) 行
→ 2000 行实占 2.72MB ≫ 512KB ⇒ 条件**永远为真**
⇒ 每次 append 都：全量读 2.72MB + 全量重写 2.72MB
```

**修法**（`memory/manager.py::_append_trace`）：
① 以**字节**为截断目标，从头部按整行丢弃直到达标；
② **触发阈值与截断目标分离**（新增 `TRACE_TRUNCATE_FACTOR = 2`）——
这条是第二次修正：只做 ① 的话文件会长期**贴着上限**，几乎每次追加仍触发重写。

| | 修复前 | 修复后 |
|---|---|---|
| 追加 300 次的大文件 | **每次**都重写 2.72MB | **只重写 1 次** |
| 文件体积 | 2.72MB | 512KB ~ 1MB 之间浮动（有硬边界） |

### 2. `_load_global_memory` 轮内重复读 ✅ 已修

一轮对话里 prefetch 三层各调一次（`_get_core_memory` / `_search_recent_memory` /
`_search_global_memory`），外加 system prompt 组装 → 同一份文件读盘 3–4 次并重复拼接。

**修法**：按**文件指纹（路径 + mtime_ns + size）自失效**的 memo。
文件没变就复用，**任何写入都会立刻改变指纹并自动重读** —— 不需要人工判断「何时失效」，
也就不存在读到陈旧记忆的窗口；另在 `_save_global_memory` 末尾主动失效做双保险。

### 3. 纠正信号词过泛 —— 误扣信任 ✅ 已修

`after_action._SIGNALS` 是「本轮用户在纠正 AI 吗」的**唯一**判据，而旧表含
**「不是 / 应该是 / 重新 / 改一下 / 错误」** 这类中文高频歧义词：

- 「**不是**明天，是后天」—— 他在说自己的安排
- 「**改一下**标题」—— 普通指令，不是纠错

这些都会被判成「AI 做错了」→ 自动扣信任。已收紧为**明确指向对方输出**的强信号词。

### 4. `trust` 归零 —— 报告说"通路没找到"，实际是**不对称** ✅ 已修

```
下行（自动）：after_action 每轮跑启发式 → 命中即 record_correction() → trust -0.02
上行（手动）：只有用户点「接受建议 / 定稿通过」才 +0.02 / +0.03
```

真实库铁证：`behavior_log.jsonl` 里 `correction` **85 次**、`suggestion_pushed` 13,177 次，
而 `suggestion_accepted` / `creation_approved` **0 次** → 信任单向归零，**与用户勤快与否无关**。

影响方向核算（报告这点是对的）：`offset = (trust-0.5) × 2 × 0.08`，`result = base - offset`
⇒ `trust=0` → 阈值 **+0.08（更克制）**。

**修法**：① 收紧信号词（见第 3 条）；② `record_correction` **同日去抖**——
信任受损是「今天发生了一件事」级别的事件，一天记一次就够；
默契 / 子域 / 事件计数**不**去抖（每次纠正都是一条独立校准信息）。

### 5. 语义通道静默失效 + 死常量 ✅ 已修

195 条外部信息 embedding 全 NULL，而失败路径只打 `logger.debug` ——
默认日志级别下等于**无人知晓**。fail-open 是**设计**，但**静默不是**。

**修法**：新增 `_note_embed_failure()`（节流 warning，含当前模型名与排查提示）+
`last_embed_error()` 查询口；删除零引用的 `_SEMANTIC_CANDIDATE_LIMIT`。

> ⚠ 注意：**能不能真的用上语义通道，取决于你选哪家 embedding 服务**（见第五节）。

### 6. `ensure_emotional_gaps` 的 meta 永久短路 ✅ 已修

`emotional_gaps_initialized = True` 之后**整个函数第一行就 return []** ——
「初始化过」被当成了「永久完成」：新增的 topic 播不进来，维度变空也补不回。

**修法**：改为**双判据**——`topic 已存在于 cognitive_gaps` ∨ `维度已有 active 条目` → 跳过；
否则播。于是幂等**且可补种**。

### 7. 注册 `deskmate-growth` MCP ✅ 已修

`deskmate/growth/server.py` 早已实现（`growth_stats` / `growth_set_proactive` /
`growth_skill_proficiency` 三个只读+设置类工具），却从未登记进 builtin ——
是唯一「有实现、无出口」的孤儿 MCP。

## 八、embedding 选型落地：本地 BGE 后端已接线（20:40）

### 8.1 决策与实测依据

火山 Agent Plan **不覆盖** `/embeddings`（404 `UnsupportedModel: does not support the
agent plan feature`；换标准 `/api/v3` 又是 401）⇒ 本机没有任何可用的 API 后端。
故按拍板走**本地方案**：`fastembed` + `BAAI/bge-small-zh-v1.5`（512 维）。

**为什么非做不可**（不是"锦上添花"）：关键词兜底对中文自然语言查询实测 **0 命中** ——
`ExternalStore.search_items_keyword()` 按 `re.split(r"\s+")` 拆词，中文长句没空格 →
整句当一个关键词 → `LIKE '%整句%'` 必然落空。4 个中文查询全空，而本地 BGE 的
top-3 相关度 0.47–0.67 且命中准确（112 条 digested 语料）。

### 8.2 改动（`deskmate/memory/{local_embed,semantic_search}.py` + `pyproject.toml`）

| 组件 | 做法 |
|---|---|
| `local_embed.py`（新） | fastembed + BGE；**可选依赖**、懒加载单例、载入失败不缓存失败态、首下走 `hf-mirror.com`（临时设 `HF_ENDPOINT`，结束还原）。`available()` 只 `find_spec`，不拉模型 |
| 后端链 | `DESKMATE_EMBEDDING_BACKEND` = `auto`/`local`/`api`。`auto` **本地优先**（API 在本机是"必然失败 + 可能 60s 超时"，排前面等于每次检索白吃一次超时）；显式指定则**不偷偷兜底** |
| 记账 | `last_backend()` / `active_model()`：写入 `embedding_model` 的必须是**实际**产出该向量的模型，不是配置默认值 |
| 诊断 | `backend_status()` → 并进 `/v1/deskmate/external/status` 的 `embedding_backend` 字段 |
| **指纹护栏**（写入侧） | 库存 `(模型, 维度)` 与新批对不上 → **整批拒绝**并说明原因（见 8.3） |
| **维度告警**（读取侧） | 全量维度不符 → 告警 + 返回空（降级关键词）；部分不符 → 只跳过坏的那几条 + 计数可查 |

### 8.3 ⚠ 本次特意堵的那个坑：**换后端 = 静默失效**

`cosine_similarity` 在维度不一致时**直接返回 0.0** → 检索会"正常地返回空"，
从外部完全看不出异常 —— 这跟本次要根治的"语义通道一直没开"是**同一个病**，
只是病因从"没凭证"换成"向量空间对不上"。所以护栏做在两侧：

- 写入侧不许混源（清空全表后指纹为空，自动放行 → 换后端的正路是"清空重刷"）

### 8.6 ⭐ 顺带挖出并修掉第 8 处真缺陷：**digested 孤儿条目永远补不上向量**

|---|---|
| 状态机是 `raw → summarized → **embedded** → **digested** → archived` | —— |
| `ingestion_pipeline`（自动升格）/ `promote_approved`（人工裁决）走 `mark_digested`，**从不经过 embedded** | 产生"digested 且无向量"的条目 |

**修法（一对，缺一不可）**：

1. `ExternalStore.update_embedding`：状态改为**单调推进**（SQL `CASE`，单语句无读改写竞态）——
   `digested` / `archived` 原地保留。否则给孤儿补向量会把它**降级**回 `embedded`，

2. `SemanticSearcher.embed_pending_items`：待办口径加入 `digested`。

### 8.7 ⚠ 方法论修正：这个仓库**不能**用 worktree 取基线

本以为「`git worktree add` 出 HEAD 副本跑基线」最干净，实测**无效**：
`.venv` 里有 `__editable__.coworker-0.0.0.pth` + `__editable___coworker_0_0_0_finder.py`，
是**meta-path finder**（优先于 `sys.path`），`deskmate` 恒解析到主仓库 ——
在 worktree 里跑，测的仍是主仓库代码，会得出**假对照**。

可用做法（本次采用）：`cp` 备份 → `git show HEAD:<path>` 覆盖 → 跑 → **`trap ... EXIT` 还原**
→ 用 `md5 -q` 核对还原后指纹一致；并先断言 `git diff -- <path>` **无输出**（证明真切到了 HEAD）。
