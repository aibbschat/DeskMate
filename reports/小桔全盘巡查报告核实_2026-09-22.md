## 三、确认的真缺陷与修复（7 处）

### 1. `inject.jsonl` 写放大 —— 每轮白烧 2.7MB IO ✅ 已修

```
条件：size > TRACE_MAX_BYTES(512KB)
截断：只保留最后 TRACE_MAX_LINES(2000) 行
→ 2000 行实占 2.72MB ≫ 512KB ⇒ 条件**永远为真**
⇒ 每次 append 都：全量读 2.72MB + 全量重写 2.72MB
```

**修法**（`memory/manager.py::_append_trace`）：
① 以**字节**为截断目标，从头部按整行丢弃直到达标；
② **触发阈值与截断目标分离**（新增 `TRACE_TRUNCATE_FACTOR = 2`）——
这条是第二次修正：只做 ① 的话文件会长期**贴着上限**，几乎每次追加仍触发重写。

| | 修复前 | 修复后 |
|---|---|---|
| 追加 300 次的大文件 | **每次**都重写 2.72MB | **只重写 1 次** |
| 文件体积 | 2.72MB | 512KB ~ 1MB 之间浮动（有硬边界） |

### 2. `_load_global_memory` 轮内重复读 ✅ 已修

一轮对话里 prefetch 三层各调一次（`_get_core_memory` / `_search_recent_memory` /
`_search_global_memory`），外加 system prompt 组装 → 同一份文件读盘 3–4 次并重复拼接。

**修法**：按**文件指纹（路径 + mtime_ns + size）自失效**的 memo。
文件没变就复用，**任何写入都会立刻改变指纹并自动重读** —— 不需要人工判断「何时失效」，
也就不存在读到陈旧记忆的窗口；另在 `_save_global_memory` 末尾主动失效做双保险。

### 3. 纠正信号词过泛 —— 误扣信任 ✅ 已修

`after_action._SIGNALS` 是「本轮用户在纠正 AI 吗」的**唯一**判据，而旧表含
**「不是 / 应该是 / 重新 / 改一下 / 错误」** 这类中文高频歧义词：

- 「**不是**明天，是后天」—— 他在说自己的安排
- 「**改一下**标题」—— 普通指令，不是纠错

这些都会被判成「AI 做错了」→ 自动扣信任。已收紧为**明确指向对方输出**的强信号词。

### 4. `trust` 归零 —— 报告说"通路没找到"，实际是**不对称** ✅ 已修

```
下行（自动）：after_action 每轮跑启发式 → 命中即 record_correction() → trust -0.02
上行（手动）：只有用户点「接受建议 / 定稿通过」才 +0.02 / +0.03
```

真实库铁证：`behavior_log.jsonl` 里 `correction` **85 次**、`suggestion_pushed` 13,177 次，
而 `suggestion_accepted` / `creation_approved` **0 次** → 信任单向归零，**与用户勤快与否无关**。

影响方向核算（报告这点是对的）：`offset = (trust-0.5) × 2 × 0.08`，`result = base - offset`
⇒ `trust=0` → 阈值 **+0.08（更克制）**。

**修法**：① 收紧信号词（见第 3 条）；② `record_correction` **同日去抖**——
信任受损是「今天发生了一件事」级别的事件，一天记一次就够；
默契 / 子域 / 事件计数**不**去抖（每次纠正都是一条独立校准信息）。

### 5. 语义通道静默失效 + 死常量 ✅ 已修

195 条外部信息 embedding 全 NULL，而失败路径只打 `logger.debug` ——
默认日志级别下等于**无人知晓**。fail-open 是**设计**，但**静默不是**。

**修法**：新增 `_note_embed_failure()`（节流 warning，含当前模型名与排查提示）+
`last_embed_error()` 查询口；删除零引用的 `_SEMANTIC_CANDIDATE_LIMIT`。

> ⚠ 注意：**能不能真的用上语义通道，取决于你选哪家 embedding 服务**（见第五节）。

### 6. `ensure_emotional_gaps` 的 meta 永久短路 ✅ 已修

`emotional_gaps_initialized = True` 之后**整个函数第一行就 return []** ——
「初始化过」被当成了「永久完成」：新增的 topic 播不进来，维度变空也补不回。

**修法**：改为**双判据**——`topic 已存在于 cognitive_gaps` ∨ `维度已有 active 条目` → 跳过；
否则播。于是幂等**且可补种**。

### 7. 注册 `deskmate-growth` MCP ✅ 已修

`deskmate/growth/server.py` 早已实现（`growth_stats` / `growth_set_proactive` /
`growth_skill_proficiency` 三个只读+设置类工具），却从未登记进 builtin ——
是唯一「有实现、无出口」的孤儿 MCP。
