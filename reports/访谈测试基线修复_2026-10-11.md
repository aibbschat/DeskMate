## 结论先行
3 个失败分两类，根因都是测试未做好隔离，**不是小桔访谈逻辑写错**：

| 失败用例 | 类型 | 根因 | 修复 |
|---|---|---|---|
| `test_explore_extracts_and_resolves_gap` | 固有（单跑也红） | 本机有 provider 凭证 → `llm_available()`=True → `extract_cognitive_items` 真调 LLM、落「立场」条目，而非用例要验的规则兜底「访谈」条目 | `_hermetic` 强制 `llm_available()=False` |
| `test_explore_rules_absorb_no_llm` | 固有（单跑也红） | 同上（名字写"no_llm"但靠环境碰运气） | 同上 |
| `test_start_answer_roundtrip` | 套件污染（单跑通过） | `_restore` 把 `pmod._default_managers` 存成**原对象引用**赋回 → 上一用例 manager 实例（指向旧临时库）泄漏 → `start_interview` 写旧库、`answer_interview` 读新库 → `session_done` 永 False | `_hermetic` 对 `_default_managers` 存**快照副本** `dict(...)` |

## 证据链

### Bug A：测试未对 LLM 做 hermetic 隔离
- 诊断脚本实测：环境 `llm_available()`=**True**（凭证来自 `~/.config/coworker`，`SecretStore` 读取不受 `DESKMATE_DIR` 影响）。
- `_absorb_response`（interview.py:331-366）认知层逻辑：调 `extract_cognitive_items`，仅当 `dep.get('error')=='llm_not_available'` 才走 `_absorb_response_rule`（落 `category='访谈'`）。
- 本机 LLM 可用时 `extract_cognitive_items` 真实成功、返回 `{'deposited':3}`，写入 `category='立场'` 条目 → 用例断言 `any(category=='访谈')` 不成立 → 误红。
- 用例注释明写「不依赖 LLM / 降级为规则兜底（只落 stance）」，意图就是验规则路径。**正确修法是让测试确定地走规则兜底**，而非依赖环境无凭证。
- 修复：`_hermetic()` 内 `deskmate.memory.llm.llm_available = lambda: False`，整模块离线。副作用：模块不再真打 LLM，全模块 69s→0.3s。

### Bug B：manager 缓存跨用例泄漏（套件污染）
- `start_interview` / `answer_interview` 内部调**未打补丁**的 `resolve_profile_manager` → 真实 `get_profile_manager`，命中全局 `_default_managers` 缓存。
- 原 `_restore`：`pmod._default_managers = saved["profile_default_managers"]`，而 `saved[...]` 在 `_hermetic` 里取的是 `pmod._default_managers` 的**对象引用**。用例运行期间 `_gpm` 往该 dict 塞了 manager 实例，restore 把（已污染的）同一对象赋回 → 下一用例复用到指向**旧临时库**的 stale manager。
- 结果：`start_interview` 经 stale manager 把 session 写进上一用例的临时库；`answer_interview` 的 `CognitiveStore()` 解析到**当前**临时库 → 查不到 session → `total=0` → `session_done` 永 False。
- 单跑通过：无前序用例污染，manager 缓存干净。
- 修复：`_hermetic` 改为 `saved["profile_default_managers"] = dict(pmod._default_managers)`（快照副本），`_restore` 据此还原 → 每用例起点是干净的 manager 缓存。
