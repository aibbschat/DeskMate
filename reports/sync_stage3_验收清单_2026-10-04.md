## 1. 关键交互（我实测确认，路线图未写明，直接影响排期）

**同步 daemon 与 openworker-server 在云端互斥**：`scripts/sync_daemon_runner.py:85-91,360` 有启动护栏——检测到 `openworker-server.service` 在跑就**拒绝启动同步 daemon**（防双写抢锁）。当前云端实况：**只跑** `xiaoju-sync.service`，openworker-server 停着（今天阶段 2 收敛就是这么跑出来的）。

而阶段 3b 的两件事（`POST /v1/workspaces/open` 开工作区会话、`ingest/dirs` 注册蒸馏）**都要 openworker-server 在跑**。所以：

- 启动后端 → 下次同步 daemon 重启会拒绝启动；且双写窗口内 WAL 锁竞争是护栏存在的原因。
- 护栏是阶段 1 时代写的；阶段 2 已有 WAL + `busy_timeout=5000` + 触发器捕获 app 写（这正是阶段 2 的设计意图：app 写也能进 oplog）。**护栏是否放宽（改告警不拒启）需要一次真实双写压测后由萧哥拍板**——列入 3b 前置，WorkBuddy 出压测报告。
- **3a（纯文件镜像）完全不受此影响**，可以立刻做。

## 2. 红线（每条都要在验收里被实测证明，不是「配置了就算」）

1. **原稿写权只在 Mac**：协议层（Syncthing Mac=`Send Only` / 云=`Receive Only`）+ 权限层（云端原稿镜像目录对 `openworker` 账号 `chmod a-w`，属主给同步账号）**双保险**（互通方案 §9.3）。
2. **批注物理隔离**：云端对原稿的任何产出只写 `_小桔批注/`，与原稿目录方向相反的独立 Syncthing 文件夹（云 Send Only → Mac Receive Only）。**批注永不落原稿目录**（坑 2：Receive Only 里点 Revert Local Changes 会撤销本地改动——所以批注绝不能写在原稿镜像里）。
3. **不搬的东西**：796 个会话目录、3.6G 史料库（`history/` 与 `~/.deskmate.local-archive-20261001/` 已字节级一致，静态参考不进同步）、**已出版内的 `.deskmate*` 全部变体**——10-04 实测有 6 个：`20.国子监秘闻录/.deskmate` + `.deskmate.bak-20261002` + `.deskmate.broken-20261002` + `.deskmate.old-20261002`、`16.夜不收/.deskmate`、`19.大明提塘官/.deskmate`（约 22M，含圣经重建事故残留，红线：圣经只在本地）。
4. **Syncthing GUI(8384) 只走 SSH 隧道**，绝不暴露公网。
5. **密钥不入库不入报告**；设备配对用一次性邀请码，不把 device ID/密钥写进任何文档。
6. **ingest 动库前 `sqlite3 .backup()` 冷备**（3b 项）；文件镜像阶段不碰 deskmate.db，无需冷备。
7. **已出版内的 .db 与大文件**：10-04 实测已出版含 **31 个 .db**（各书研究资料库，非 deskmate.db）、**81M mp4**（`9.刺明/相关资料/`）、37M/15M PDF、zip 等。随整目录镜像会全部上云。属 D2 拍板范围：确认可上云。批注/检索层面注意：mp4/doc(40 个老格式)/pdf 她基本读不了正文（坑 6 延伸），不影响镜像本身。

## 3. 验收清单（A=3a 纯镜像，B=3a 批注通道，C=3b 后端联动）

### A. 镜像完整性与单向性（防假绿：全量校验和，不抽查）

- [ ] **A1 全量对账**：Mac 源目录与云端镜像逐文件 `sha256` 比对，**差集必须为空**（PITFALLS §P1：不抽查几个核心文件名——上次假绿就是抽查漏检）。命令：
  ```bash
  # Mac 侧与云端各跑，diff 两个输出
  find <目录> -type f ! -name '.DS_Store' -exec shasum -a 256 {} + | sed 's|<Mac路径前缀>||' | sort > /tmp/mac.sha
  ssh ubuntu@81.69.163.170 'find /var/lib/openworker/写作/原稿 -type f -exec sha256sum {} + | sed "s|/var/lib/openworker/写作/原稿||"' | sort > /tmp/cloud.sha
  diff /tmp/mac.sha /tmp/cloud.sha   # 必须无输出
  ```
- [ ] **A2 文件数与字节数**：两端 `find -type f | wc -l` 与 `du -sb` 一致（A1 的快速佐证）。
- [ ] **A3 排除项实测**：云端镜像内 **搜不到会话目录特征**（UUID 形目录名）、**搜不到 `.deskmate*` 任何变体**（10-04 实测 6 个：含 `.bak-20261002`/`.broken-20261002`/`.old-20261002`——`find 云端镜像 -name `'.deskmate*'` 必须为空）、搜不到 `history/`、无 `.DS_Store`/`*.tmp`/`*.swp`/`desktop.ini`。
- [ ] **A4 单向性（核心红线）**：在云端镜像内**手工改一个文件 + 手工删一个文件**，跑满一个同步周期后：
  - Mac 侧原文件 **sha256 不变**（改动被 Receive Only 拒绝/不分发）；
  - 云端 Syncthing GUI/REST 显示该目录为 **Receive Only** 且有 local changes 提示（**不点 Revert**，留着当证据，验收后清理）。
- [ ] **A5 Mac→云传播**：Mac 侧新增/修改/删除各一个测试文件，确认云端镜像跟上（双向中允许的方向）；测试文件验收后清理。
- [ ] **A6 文件名规范化**：中文名 NFD(macOS)→NFC(Linux) 已做一轮规范化（互通方案坑 3/4）：两端文件名集合 diff 为空、无仅大小写不同的冲突对（`find . | awk '{print tolower($0)}' | sort | uniq -d` 为空）。
- [ ] **A7 版本策略**：云端 `.stversions` 已配 Staggered（40G 盘防膨胀，坑 5）；磁盘水位有监控（当前 28G 可用）。
- [ ] **A8 网络实测**：大陆 discovery 不通（10-01 实测 000）→ 已配**静态地址** `tcp://81.69.163.170:22000`；腾讯云安全组已放行 22000/tcp+udp（**外部动作，需萧哥在控制台操作**）；两端 `Connected` 状态实测截图/REST 确认。

### B. 批注回传通道（依赖 D4=要）

- [ ] **B1 方向正确**：批注文件夹配置为云端=`Send Only`、Mac=`Receive Only`（与原稿镜像方向**相反**）。
- [ ] **B2 回传可达**：云端 `_小桔批注/` 写测试文件 → Mac 侧出现，内容一致。
- [ ] **B3 隔离可达（反向红线）**：Mac 侧批注目录里改文件 → **云端不回流**（Mac=Receive Only）；且云端改原稿镜像的文件**不会**出现在 Mac 批注目录（两文件夹互不串）。
- [ ] **B4 权限双保险实测**：以 `openworker` 身份写原稿镜像 → `Permission denied`；写批注目录 → 成功。命令：
  ```bash
  ssh ubuntu@81.69.163.170 'sudo -u openworker touch /var/lib/openworker/写作/原稿/PROBE.md'  # 期望 Permission denied
  ssh ubuntu@81.69.163.170 'sudo -u openworker touch /var/lib/openworker/写作/批注/PROBE.md'  # 期望成功，验后删
  ```
- [ ] **B5 批注格式约束**：云端小桔的产出为 `.md`/`.json`，不写 `.docx`（坑 6：zip 容器不可合并）；已写进她的系统提示/工具约束。
