## 一、目标（一句话）

让认知条目之间长出「邻座」：**同锚的两条记忆能互相被召回**，让她的回答从「点」变成「连着的点」。
不动现有 5 张表结构、不建显式边表、不加 LLM 调用（锚从已有抽取产出里顺手派生）。

## 二、范围

**做（P1）**
- 新增 `memory_anchors` 明文锚表（可同步、可回退）。
- 抽取时顺手抽锚（topic / book 为主，person 轻量 best-effort）。
- `recall_items()` FTS 命中后，**顺锚走一跳**召回邻座条目，附 `via_anchor` 与 evidence。
- 锚表进 `SYNC_TABLES`（明文，照 `sync_uuid`，绝不搬向量）。

**不做（明确划界，留给 P2/P3）**
- ❌ 不建 `memory_edges` 显式边表（§八.1 已拍板延后）。
- ❌ 不做反思（P2）。
- ❌ 不做 `intents` / `lessons` / lessons 注入（P3）。
- ❌ 不改 `memory/manager.py` 注入链（那是 P3 的 lessons 落点；P1 只改 `store.recall_items`，由既有注入消费）。
- ❌ P1 锚范围**只限 `profile_items`**（recall_items 实际查询的表）；`learned_fact`/`understanding`/`ledger_item`/`diary` 的锚扩展是后续步。

## 三、数据模型（新增，明文，可同步）

> **【R0 修正 · 据 `bridge-trae/ROUND-00-预检.md` §确认项 3】**
> 原四列复合主键 `(item_kind, item_id, anchor_kind, anchor_value)` **无法直接注册 `SYNC_TABLES`**：
> 触发器只认单列 `sync_key`（`sync_store_sqlite.py:336` `NEW.<sync_key>`、L469/487 `WHERE {pk}=?`）。
> 故加**单列确定性 `row_key` 作主键**，四列唯一性另用 `UNIQUE` 兜底。

```sql
CREATE TABLE IF NOT EXISTS memory_anchors (
  row_key      TEXT PRIMARY KEY,  -- 确定性 = item_kind + '\x1f' + item_id + '\x1f' + anchor_kind + '\x1f' + anchor_value
  item_kind    TEXT NOT NULL,     -- profile_item（P1 仅此；后续扩 learned_fact/understanding/ledger_item/diary）
  item_id      TEXT NOT NULL,
  anchor_kind  TEXT NOT NULL,     -- person | topic | event | project | book
  anchor_value TEXT NOT NULL,
  created_at   TEXT NOT NULL,
  UNIQUE (item_kind, item_id, anchor_kind, anchor_value)   -- 业务唯一约束（row_key 之外第二道锁）
);
-- 同锚邻座召回（反查索引）
CREATE INDEX IF NOT EXISTS idx_anchor_lookup
  ON memory_anchors(anchor_kind, anchor_value, item_kind);
```
- 纯文本，无向量列 → 直接进 `SYNC_TABLES`，各端同明文即一致（红线见 `sync_store_sqlite.py` L224-L243）。
- `row_key` 是**确定性字符串**（不含随机 uuid）→ 两端同一条锚必得同一 `row_key` → 同 `sync_uuid` → 自动合并（照 `proactive_ledger`/`llm_circuit_breaker` 的 `sync_uuid_kind="string"` 口径）。
- 新增即纯增益：表空 / 关召回 → 退回今天 FTS 口径，**零破坏**。

## 五、召回顺边走一跳（`recall_items` 改造伪码）

```python
# —— 现有 FTS 段保持不变（L845-870 原样）——
fts_hits = [...原 FTS 结果...]

# —— 新增：顺锚走一跳（整段 try/except 包住，fail-open 退回纯 FTS）——
if os.getenv("DESKMATE_ANCHOR_RECALL", "1") != "0":
    try:
        seed_ids = [h["id"] for h in fts_hits]
        if seed_ids:
            with self._connect() as conn:
                rows = conn.execute(
                    "SELECT anchor_kind, anchor_value, item_id FROM memory_anchors "
                    "WHERE item_kind='profile_item' AND item_id IN (?,?)",  # 实际参数化展开
                    seed_ids,
                ).fetchall()
                # 单锚召回上限（防炸库），如 ≤8
                siblings = _collect_sibling_ids(rows, per_anchor_cap=8, exclude=set(seed_ids))
                if siblings:
                    srows = conn.execute(
                        "SELECT id, layer, dimension, topic, content, confidence "
                        "FROM profile_items WHERE id IN (...) AND status='active'",
                        siblings,
                    ).fetchall()
                    for r in srows:
                        if r[0] in excl:
                            continue
                        fts_hits.append({
                            "id": r[0], "layer": r[1], "dimension": r[2], "topic": r[3],
                            "content": r[4], "confidence": r[5],
                            "via_anchor": True,
                            "anchor_evidence": _evidence_for(r[0], rows),  # 如 "同主题：X"
                        })
    except Exception:
        pass  # 锚召回失败 → 退回纯 FTS，不影响主链路

return fts_hits[:top_k]
```
- **关键**：邻座段纯增益；任何异常 → `pass` → 返回原始 FTS 结果（=今天口径）。
- **去重**：邻座不与 FTS 命中、`exclude_ids` 重复。
- **封顶**：总返回仍受 `top_k`（实测 L858 限制在 1~50）；邻座额外占比受 `per_anchor_cap` 控。

## 六、安全与红线

- **全部 fail-open**：抽锚失败不影响主抽取；邻座召回失败退回纯 FTS；建表失败不影响既有查询。
- **不碰神圣稿件守卫**：锚抽取只读条目文本，沿用 `extractor` 既有 `guarded_*` 守卫（红线见 `deskmate/sacred_paths.py`）。
- **绝不搬向量**：锚表纯文本，各端重算无依赖；同步只走明文 `sync_uuid`。
- **本地史料库优先**：§八.4 拍板「主动查史料佐证」将来用本地库；P1 虽不直接查史料，但锚表明文结构为后续「同书目/同事件」邻座打底，不引入联网。
- **可回退**：删 `memory_anchors` 表 + `DESKMATE_ANCHOR_RECALL=0` → 完全退回今天 FTS 口径。

## 八、验收判据（来自设计 §2.6 + 实证补充）

1. 抽 100 条新条目 → 至少自动长出可解释的锚关联（人工抽看 `anchor_value` + 邻座来源 `anchor_evidence`）。
2. 实际对话验证：召回里邻座条目出现，**真的改善**「你以前也……」类回答（拿几条历史对话验）。
3. 回归：关 `DESKMATE_ANCHOR_RECALL` → 退回 FTS 口径，回答不崩、结构兼容。
4. 跨端：锚表同步后，两端邻座召回一致（**集合级对账**，非游标）。
