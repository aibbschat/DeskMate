## 二、判断层（本轮核实）

判断层拆成四块：**认知**（她怎么认识你）、**理解**（她怎么解读一件事）、
**世界观**（她自己怎么看世界）、**自主**（她能自己做什么），外加一个合流点（judge + 写闸门）。

### 2.1 认知：她怎么「认识你」

- **抽取**：`cognitive/extractor.py` 用 LLM 从文本/对话/作品抽五维——立场 / 论证模式 /
  价值排序 / 思维框架，**要求带证据与置信度**（L35-L67、L106-L166）。
- **更新与矛盾**：`cognitive/profile.py` L101-L230 —— 新增立场、补来源、检测矛盾、
  把可疑条目标 `questioned`，并为矛盾**自动生成 cognitive gap**；L232-L276 —— 已有立场
  发生**显著变化**时 `superseded` 旧条目 + 建新条目 + 记 `item_history`。
  > 也就是说：认知层**有**类似记忆层的「演化/取代」机制，不是只增不减。
- **访谈闭环**：`cognitive/interview.py` L205-L252 —— 按 `questioned / open gap / 低置信`
  优先级生成**苏格拉底式**问题并做 topic 去重；L276-L329 —— 回答回灌分两路
  （澄清=校正条目 / 深化=补来源 + 保底提升置信度），**明确避免“答了等于白答”**。
- **短板**：认知条目**平铺无关联**（见 1.2）——她记得「你的取舍」也记得「某件具体的事」，
  但两条之间没有边，检索时各回各的。
- **未确证**：抽取的**调度触发点与频率**（谁在什么时候调用 extractor）本轮未核。

### 2.2 理解：她怎么「解读一件事」

- **主路径**：`proactivity/understanding.py` 是**统一后处理**——对 `understanding` 为空的
  待办条目，由 LLM 产出 120 字以内「我的理解」，并接住**三路 fail-open 上下文**：
  她的 **worldview** + 跨库 **FTS 相关记忆** + 项目级**人物圣经**（L150-L162、L273-L285），
  用来**反“凭空编”**。
- **护栏**：空 content 直接跳过（不浪费 LLM、防递空卡，L241-L247）；有 key 但调用失败→
  标 `understanding_failed` **降级递**（L292-L297）；冷却 10 分钟、失败重试窗 60 分钟
  （L35-L42）。设计原则是「**加工完成前不递**」。
- **世界观察的理解**：`agency/behaviors/understand_observations.py` `decide_and_digest`
  （L242-L319）——LLM **自主判断**哪些世界动向值得记，输出独立段落并关联 `fact_keys`。
- **短板**：理解是**单条、一次性**的（一条一评）。她不会把「我对这件事的理解」和
  「我上个月对类似事件的理解」放在一起看——沉淀那一步交给世界观，但两者之间没有互相引用。

### 2.3 世界观：她自己怎么看世界

- **怎么长出来**：`agency/behaviors/worldview_reflection.py` L2-L19 —— 世界观**不是当场总结**，
  而是攒够观察（`min_observations=5`）、过冷却（`cooldown_hours=168`，即 **7 天**）后
  「回望」生成；**允许弃权**；写进 `profile_items layer='worldview'` 后交给认知演化机制
  处理取代/矛盾（L63-L81、L452-L518）。
- **视角配比**：回望 prompt 里把**萧盛底层视角前置锚定**，且「萧盛影响」条目的权重
  高于「外部观察」（置信度 0.7 vs 0.6，L348-L388）。
- **消费端**：`load_worldview_beliefs`（L261-L292）被发帖 / 回信 / 聊天注入消费；
  认知注入器用 `subject="你"` 把它当**「她自己的看法」**单独成段（`memory_injector.py`
  L316-L374）——与「她眼中的你」严格分开，避免把她的观点说成你的。
- **短板**：她**只沉淀、不自省**——看法写进去之后，没有「主动去验证/证伪自己看法的回路」。
  它靠下一次 7 天回望去覆盖，属于**被动演化**，不是主动求证。

### 2.4 自主：她能自己做什么

- **引擎**：`agency/engine.py` `AgencyEngine.tick()`（L43-L96）—— 读设置 → kill switch
  检查 → 遍历**白名单动作** → 按风险分级：**低风险直接执行**，**高/未知 → 生成提议卡待人审**。
  云端由 `scripts/xiaoju_agency_tick.py`（systemd，每小时）驱动。
- **注册表与风险**：`agency/registry.py` L29-L133 给每个动作定**内禀风险等级**；
  `agency/risk.py` 未知动作**默认 high**（fail-safe）；高风险如写文件 / 发消息 / 删除 /
  外部信息裁决**必须用户确认**。
- **护栏**：`outbound.py` `claim_outbound`（频率 / 去重 / peer 冷却一把梭，L191-L240）；
  `visibility_gate.py` `is_public_safe`（公开内容按来源 / 私密词 / 感知原始流保守拦截，
  L96-L127）；`_archive_expired_external` 给外部信息加**过期机制**（engine.py L99-L107）。
- **决策路由**：`route_task` 当前**恒返回 "self"**（接缝已留、未接其他执行者，engine.py L67-L70）。
- **深度判定**：她目前是一个 **「白名单 + 风险分级」的定时行为执行器**，
  **不是有目标的智能体**——代码里没有「目标设定 / 计划 / 自我评估」对应模块。
  换句话说：**做什么是她被注册好的，不是她自己想出来的。**

### 2.5 合流点：judge + 写闸门

- **judge**：`proactivity/judge.py` 用 LLM 判断「要不要主动介入」，输出
  `should_act / confidence / suggestion_type / content / reasoning`；写作场景专列四类维度
  （情节矛盾 / 角色不一致 / 伏笔遗漏 / 时间线）。它**是活代码**——被 `proactivity/tick.py`
  的云端审计生产者调用（tick.py L29、L49-L66）。
- **写闸门**：`proactivity/confidence.py` —— `should_act=False` **强制 NO_ACTION**（哪怕模型
  自报 0.9，L63-L70）；≥0.8 = SUGGEST、0.5–0.8 = PREPARE、<0.5 = 不动；情感关怀单独
  0.6 门槛；阈值还会被成长系统的信任度调制。
- **台账守卫**：空 content 与噪声 kind（`_NOISE_KINDS`，含 `no_action`）在写台账前拒收
  （tick.py L52-L58）——这正是 2026-10-07 修掉的那批空卡片。

## 三、判断与方向

### 3.1 一句话诊断

- **记忆层**：点清楚，**点与点无线**。
- **判断层**：四块都在，但**「散」**——judge 不知道她上一条判过什么，理解不知道别条的理解，
  世界观 7 天才回望一次；**每一条判断都是一次性、无状态的**。
- **自主层**：**窄**——只能执行预制行为，不能自己定目标。

整条道：**地基（记忆）实，中段（判断）齐但散，上层（自主）窄。**

### 3.2 缺口排序（按「离懂你最近」排）

1. **认知条目之间没有关联**——记忆层遗留，同时也是判断层「串不起来」的**同一个根**。
2. **判断是「无状态」的**——她没把「我以前怎么判过同类事」接进这一条判断，
   于是判断容易前后反复、不稳。
3. **自主缺目标与优先级**——她「做什么」是被注册的，不是她想的。
4. **世界观缺自省回路**——只沉淀、不主动求证。

### 3.3 建议方向

- **若目标是「更懂你」→ 先做 1 + 2。** 它们其实是**同一件事的两面**：
  判断的稳定性，来自记忆的**关联性**。把「我判过什么 / 我理解过什么」挂到相关的记忆点上，
  判断就从「每次都从零开始」变成「带着历史判断」。
- **若目标是「更像独立的人」→ 做 3**（给她目标与优先级），这是**代价最大**的一步，
  因为它牵扯安全边界（她现在靠「白名单 + 风险分级 + 人审」守着，加了自主目标要先想清楚护栏）。
- **4 是锦上添花**，放最后。
