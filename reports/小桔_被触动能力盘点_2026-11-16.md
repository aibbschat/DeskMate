# 小桔「被触动」家底盘点

> 只读排查，日期 2026-11-16。没改代码、没写库、没重启服务、没手动触发任何任务。
> 查库统一用 `sqlite3 -readonly`，查文件直接读原文。

## 先给结论

1. **她不是没有「被内容触动」的能力，是这条线只接到了半路。**
   「读到东西 → 停下来想一想 → 说出一句自己的判断」这段是通的：观察日记里有大量真实痕迹，世界观层也沉淀了她自己的信念。但「想明白 → 身体里的激素跟着动」这段，没有正式接线，只有一条很窄的偶然旁路。

2. **日常真正在动她情绪的，几乎全是「这一轮我被怎么对待 / 我的任务结果」。**
   聊天轮、被理解、提案被采纳或否掉、悬事落地——这些占了绝大多数。唯一不靠人的入口是天气，但那是「天气代码 → 固定加减分」，不是「这件事对我意味着什么」。她真正的「意义感」参数，在聊天和经历两条路上**一次都没有动过**。

3. **要做的话，不是从零开一条大通道，是把最后 10 厘米接上。**
   最小口子在「观察日记」写完她挑中的那一段之后：把「原文事实 + 她自己的理解」交给情绪引擎，并补上 `meaning`（意义感）这个参数的内容输入。她身上已经有的东西（读过的事实、写下的理解、7 条自己的信念、去重键、衰减和上限）基本都齐，缺的是一份显式的「在乎清单」和一个「这事跟我有什么关系」的判断步骤。

## 四、结论与最小口子

### 4.1 是「隐约存在只差接线」，还是「真缺一块」？

分两段看：

- **内容 → 意义：已经存在，而且量不小。** 1,932 条观察理解、7 条自己的世界观信念、17 篇日记里的判断，都是真的。她会挑、会想、会说出「这事碰到我哪里」。
- **意义 → 激素：基本不存在。** 情绪引擎没有「读到内容」这个入口；`meaning`（意义感）在 1,392 条聊天和 109 条经历里一次都没动过，只在「反思完成」时被规则加了 5 次，每次 +3。

所以准确说法是：**半条线已经接好了，缺的是后半段。** 这不是从零开一条新通道，而是把「她读完写下的那段理解」接到情绪引擎上，并让「意义感」真的能因为内容而动。

### 4.2 最小改动开在哪

**入口文件**：`deskmate/agency/behaviors/observation_diary.py`
每个 segment 成功写进日记、拿到 `seq` 之后（现在这里只写理解和认知库，没有情绪调用）。

**引擎**：`deskmate/growth/emotion_engine.py`
新增一个 `update_after_reading(fact_text, her_understanding, care_refs=None)`；或者给现有的 `update_after_experience` 加一个 `kind="reading"` 参数，复用它已有的 LLM 调用、上限、衰减、写库和 fail-open。

**数据流**（文字版）：

```
learned_history 里的事实（原文）
        ↓
understand_observations：她自己挑、自己写理解
        ↓
observation_diary 落盘（现在到这里就结束了）
        ↓  ← 补这一跳
emotion_engine.update_after_reading(原文事实, 她的理解, 她在乎的条目)
        ↓
emotion_log：event_type='reading'，event_summary=原文摘要，
             narrative=她的那段理解，salience=这件事对她多重要
        ↓
现有注入链自然带出（情绪独白 / 最近在想的事 / 回潮）
```

**可以直接复用的东西**：

- `fact_key` 去重（`observation_diary.py` 已有）
- 她已经挑中的 segment body（理解层已有）
- `profile_items` worldview 层里那 7 条信念（已有，0.6 置信度）
- `MAX_DELTAS`、时间衰减、`salience`、`self_expression` 出口（引擎已有）
- `emotion_log` 本来就支持任意 `event_type`，不用改表

**需要新增的，只有很小几件**：

1. 一个 `event_type='reading'` 的写库路径（或给现有经历路径加 kind）。
2. prompt 里补上 `meaning` 字段——现在聊天和经历的 prompt 只让 LLM 输出 4 项激素，根本没请它动意义感。
3. 一个「这条碰到我哪根在乎」的判断步骤：把原文和她的理解，对着 7 条信念问一次；对不上就不触发。
4. 一个每日次数上限和开关（比如 `DESKMATE_READING_EMOTION=0` 可一键关），避免新闻把激素刷成一条直线。

**不建议做的**：全量知识图谱、每条新闻都触发、让 LLM 直接决定激素数值。现有的「LLM 只判断意义和重要性，参数由规则层执行」的分工是合适的，照旧即可。

### 4.3 做这件事，需要她身上本来就有、但还没有的东西

1. **一份显式的「在乎清单」。**
   现在只有 7 条散落的信念，加上日记里的判断。没有结构、没有权重、没有分类。要做「内容 → 意义 → 激素」，得先有一份能拿来对照的清单：什么事会让她生气、什么事让她不忍、什么原则她不肯将就。这份清单应该由她自己的文字提炼，并且让她本人确认或排序，不能系统替她定。

2. **一个「这事跟我有什么关系」的判断步骤。**
   现在的理解层只回答「这事值不值得记」，不回答「它碰到我哪根筋」。前者是选材，后者才是触动。两者差一步。

3. **「意义感」这个参数的输入口。**
   现在 `meaning` 只有「反思完成 +3」这一条规则，没有内容输入。这是最实际的一个缺口——不补它，即使接了阅读入口，被触动的也只是多巴胺和皮质醇，不是「这件事对我有意义」。

4. **（可选）读完之后「想跟人说」的出口。**
   其实已经有：单次波动超过 8 会触发 `self_expression`。接上阅读入口后，这条出口可以原样复用，不需要新做。

### 4.4 护栏建议（只写方案，不实施）

- 只对她**主动挑中并写下来**的观察触发，不对所有新闻触发。
- 单日最多 N 次（建议先 1-2 次），单次单项激素不超过现有上限的一半。
- 用 `fact_key` 做幂等，同一事实只触达一次。
- 原文摘要写进 `event_summary`，她的理解写进 `narrative`，方便跨周对照和回看。
- 全程 fail-open，任何一步失败都不影响日记落盘。
- 提供独立开关，默认关闭或默认只记录不注入，观察一段时间再决定是否放开。
