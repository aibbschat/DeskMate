## 三、真实 bug（原报告未发现，本报告新增）⚠️

### 3.1 现象

`§ 工作 #work`（TTL = 30 天）中存在条目 `- 2026-08-13: ...`，
距今 **39 天 > 30 天**，**却未被衰减**；`forgot.jsonl` 至今未生成。

### 3.2 根因：写入端与读取端的格式契约不一致

衰减判定的日期正则（`manager.py:1101`）：

```python
m = re.match(r"(\d{4}-\d{1,2}-\d{1,2})[:：]", entry)
```

要求日期**紧贴条目行首**（`re.match` 从第 0 位匹配）。

而 MEMORY.md 中实际落盘格式为：

```
- 2026-08-13: 短剧/剧本由专门公司负责，用户只提供小说原著。
```

**以 `- ` 开头 → 正则不匹配 → 走"无日期，安全起见保留"分支 → 永不衰减。**

### 3.3 只读探针实测（`/tmp/decay_probe.py`，纯内存不落盘）

| section | TTL 匹配 | entry 块数 | 其中能被正则识别的 |
|---|---|---|---|
| § 纠正 #correction | 无（设计如此） | 1 | 0 |
| § 工作 **#work** | **30** | 3 | **2** |
| § 日记沉淀 #moment | 无 | 19 | 19 |

`§ 工作` 下开头带 `- ` 的块（含多条 08-xx 老条目）→ **`re.match` 命中 False**，整块跳过。
只有开头**不带** `- ` 的块（如 `2026-09-21: ...`）才进得了衰减逻辑。

### 3.4 两个叠加因素

1. **格式不统一**：MEMORY.md 中同时存在 `- YYYY-MM-DD:` 与 `YYYY-MM-DD[:：]` 两种写法，
   说明写入路径（LLM 抽取 / 规则兜底 / 手工）未归一。
2. **条目粒度错误**：`entries = re.split(r"\n\s*\n", sec["body"])` 按**空行**切分（manager.py:1097）。
   连续单行条目会被当成**一个** entry，用首条日期判定整块 → 要么整块归档（连带未超龄条目），
   要么整条被漏掉。

### 3.5 影响与修复方向

- **影响**：`#work` / `#note` 两类记忆实际处于"只增不减"状态；`forgot.jsonl` 与"遗忘可见"能力形同虚设。
- **修复（小改动）**：
  1. 正则兼容前缀：`^\s*[-*]\s*(\d{4}-\d{1,2}-\d{1,2})[:：]`
  2. entry 切分改为**按行**（`splitlines()`）逐条判定，而非按空行分块
  3. 统一写入端的条目格式（建议带 `- ` 前缀，与现有主流格式一致）
- **⚠️ 数据影响预警**：修好后会**立即归档/删除一批存量超龄条目**
  （`§ 工作` 中最老 08-13 已 39 天，`>= 30` 走 vault 归档可恢复；`< 30` 的 note 类是**直接删除**）。
  上线前应先 dry-run 打印将受影响的条目清单并确认。

## 四、其他需修正项 ❌

### 4.1 vault 没有向量检索

原报告写"Archival（vault，向量检索）"。实际 `vault_store.search()`（vault_store.py:287-312）

真正的向量能力在 `semantic_search.py`，但它**只服务 `external_items`（外部世界信息表，185 条）**，

→ 结论应修正为：**vault（251 条冷记忆）尚无向量检索**，比报告描述的"检索弱"更靠前一步。

### 4.2 top-200 是死常量

`_SEMANTIC_CANDIDATE_LIMIT = 200`（semantic_search.py:43）**全仓库仅这一处出现，零引用**。
`semantic_search()` 实际遍历并计算**全部**已向量化条目的余弦相似度，无候选截断。

→ 语义检索实为**全量扫描 + 纯 Python 余弦**（`cosine_similarity` 无 numpy）。

### 4.3 存在记忆质量评测集

`tests/memory_bench/`：`benchmark_dataset.json`（50 题）+ `runner.py` + `test_memory_bench.py` 门禁。
用 `tempfile.mkdtemp()` 隔离，不触真实库。**实测结果**：

```

USER.md 近重复率: 0.0%   (P0-5 目标趋近 0)
全局记忆陈旧率: 0.0%   (P0-6 时间感知：越低越新鲜)
```

→ 结论应修正为：**已有本地 fixture 基准（50 题、量化召回率 + 重复率 + 陈旧率），
缺的是标准化基准（LoCoMo/LongMemEval）与多跳时间推理评估**——而非"无任何基准测试"。

局限也要说明：fixture 为人工构造、判定用 `kw in text` 子串命中，不等于标准信息检索的精确率/召回率。

### 7.1 根因：读写不对称

```python
def _load_global_memory(self) -> str:      # manager.py:930
    parts.append(MEMORY.md)                 # 文件 1
    parts.append(diary_memory.md)           # 文件 2 ← 检索视图

```

读 **2** 个文件、写 **1** 个文件。于是任何 `load → parse → render → save`
路径都会把 `diary_memory.md` 的日记**固化进 MEMORY.md**，且 `_parse_sections`

```

_parse_sections 得到 12 个分节，其中「日记沉淀」4 个
_render_sections 渲染后 13776 字符  含 § 日记沉淀 4 处
→ 若此刻 _save_global_memory(rendered)，MEMORY.md 变成 4 份
```

**结论：每次落笔 +1 份。** 从 1 份涨到 3 份只需两次。
`diary_memory.md` 创建于 2026-09-14 08:35，此后该文件一直存在，拼接持续生效。
