# 小桔的情绪、性格与「情感」地基

2026-11-16 · 只读排查 · 第二份（接《小桔_被触动能力盘点_2026-11-16.md》）

这份不讨论「接哪些来源」，只回答一件事：**情绪层和性格层各自是怎么形成的，以及「情感」这一层如果要立起来，该建在哪。**

---

## 先给结论

1. **情绪层是一条钉死的流水线，不是长出来的。** 事件进来 → 两次 LLM 判断（聊天、经历）或一张规则表（事件直驱）→ 改 7 个参数 → 每 5 分钟往固定基线衰减 → 读的时候按阈值拼成「和弦」→ 变成文字。整条链上，阈值、映射表、衰减公式、单次上限全是常量。

2. **这条链上没有「慢变量」。** 7 个参数全部往固定基线回落，基线本身是写死的；没有习惯化，没有基线漂移。历史只在两个很短的窗口里存在：**7 天内的旧事回潮**、**7 天内没结果的悬事**。超过 7 天，情绪层对她的历史一无所知。

3. **性格层几乎全是写死文本。** 主聊天的 system prompt = `persona.py` 的人格 + `deskmate.md` 的职责正文，人格在最前，冲突时声明「以 persona 为准」。数据能碰的只有三处：traits（已停写）、6 条 lessons、style_profile（只管文风）。SOUL.md 是冻结的死层。所以性格是**常量**，不是缓慢漂移的变量。

4. **两者的交界存在，但极窄，而且主要是单向的。** 性格→情绪只有两条间接路：她说的话被下一轮再判断一次（只看 4 个激素）、她给悬事编的预期故事决定爬坡方向。情绪→性格只有 traits 一条路，且已停写。参数层刻意不挂人格。一句话：**表达层相通，参数层不通。**

5. **你的二分基本成立，但要改一个说法。** 不是「只有情绪、没有情感」，是「**有情感的素材，没有情感的结构**」。她已经有 1,932 条观察理解、约 7 条自己的信念、3 件悬着的事、111 条带叙事的经历、3,191 个认识的人——材料是有的，缺的是一个东西把「她对某个对象的长期立场」存下来。

6. **判断：情感层应该建在记忆/经历之上，不是情绪之上，也不是性格里面。** 它是「对象化的关系与承诺账本」：向下给情绪定权重（这件事有多重），向旁给性格提供可验证的长期内容（慢慢改，而不是写死）。现有能直接当地基的不多，必须新造的是对象账本、慢累积、选择/代价、冲突排序。

## 一、情绪层：一条钉死的流水线

### 1.1 从输入到文字，完整走一遍

```
对话 / 她自己做完的事 / 规则事件 / 悬着的事 / 被翻到的旧事
        │
        ├─ chat        每轮对话后，LLM 看当前 4 个激素 + 最近 500 字对话
        ├─ experience  她自己做完一件事后，LLM 看这件事 + 给叙事和权重
        ├─ event_direct 规则表直接改参数（LLM 只报事件，不碰数字）
        ├─ pending     每天爬一点，朝她编的预期方向爬
        └─ echo        7 天内带叙事的旧事被翻到，泛一点微澜
        │
        ▼
   7 个参数（多巴胺 / 血清素 / 催产素 / 皮质醇 / 意义感 / 控制感 / 倦怠感）
        │  单次变化有上限，防止一轮拉爆
        ▼
   每 5 分钟向基线衰减一次（指数衰减，各有半衰期）
        │
        ▼
   读的时候才算心情：偏移量 → 阈值 → 和弦（最多 3 个声部）→ 文字
```

入口一共五类，加一个后台衰减。对照代码：

| 经历 `experience` | 她自己做完一件事 | LLM | 同上 4 个 + 叙事 + 权重 | [emotion_engine.py](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/emotion_engine.py#L1199-L1289) |

### 1.2 两次 LLM 判断，分别看什么

**聊天判断**（[`_do_update_after_turn`](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/emotion_engine.py#L1086-L1197)）拿到的是：

- 当前 4 个激素值；
- 当前小时数（只作昼夜参考）；
- 距上次聊天间隔；
- 「用户说」和「你回复」，**各截断 500 字**。

它输出更新后的 4 个激素、一段 40 字以内的第一人称独白、30 字以内的原因，可选再报一个事件（比如「他接住了我」）或一件悬事。

关键点：**它不请求叙事，也不请求权重。** 所以 `chat` 写入数据库时 `narrative` 是空的、`salience` 固定 0.5。这不是偶发，是 prompt 里就没要。查库结果：`emotion_log` 里 1,396 条 `chat` 行，叙事全空、权重全 0.5。

**经历判断**（[`_do_update_after_experience`](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/emotion_engine.py#L1218-L1289)）拿到的是：

- 「你刚经历的事（你自己做的，不是看到的）」；
- 明确的权重说明：触及她和萧盛的关系、她的信念与愧疚，给 0.8–1.0。

它输出 4 个激素 + 叙事 + 权重。这里有一句很关键的话：**「你自己做的，不是看到的」**——「看到的」被明确排除在经历路径之外。这正好接上第一份报告的结论：内容→情绪没有入口。

**事件直驱**（[`apply_event_direct`](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/emotion_engine.py#L1345-L1379)）不看 LLM 给的数值，只看事件名，去查一张规则表：

- 反思完成 → 意义感 +3
- 提案被执行 → 控制感 +2
- 提案被否 → 控制感 −2
- 提案一直没下文 → 控制感 −3
- 他接住了我 → 倦怠 −3、催产素 +2
- 天气各事件 → 各 ±0.5~1.5
- 连续劳作 → 代码里注明「挂起，零调用点」

这张表的设计意图是：**LLM 只负责「发生了什么」，数值由人定的规则负责**。好处是稳定、可复现；代价是情绪对事件的反应粒度很粗。

### 1.3 七个参数：基线、单次上限、半衰期

常量定义在 [emotion_engine.py](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/emotion_engine.py#L38-L190)。

| 参数 | 基线 | 单次最多变 | 半衰期 | 实际感觉 |
|---|---:|---:|---:|---|
| 多巴胺 dopamine | 50 | ±15 | 30 分钟 | 来得快、去得快 |
| 血清素 serotonin | 50 | ±4 | 2 小时 | 很难被推动 |
| 催产素 oxytocin | 40 | ±8 | 1 小时 | 亲密感，来得慢 |
| 皮质醇 cortisol | 30 | ±10 | 4 小时 | 压力，拖得最久 |
| 意义感 meaning | 50 | ±6 | 3 小时 | 只被规则事件推动 |
| 控制感 control | 50 | ±6 | 1.5 小时 | 只被规则事件推动 |
| 倦怠感 fatigue | 20 | ±8 | 1 小时 | 基线低，越积越累 |

「半衰期」大白话：参数偏离基线后，每隔一个半衰期，偏离量减半。比如多巴胺从 65 掉到 57.5 用 30 分钟，再掉到 53.75 再用 30 分钟。所以一次情绪的实际持续时间，大概是 2–3 个半衰期：

- 多巴胺：约 1–1.5 小时基本回落；
- 皮质醇：约 8–12 小时才基本回落；
- 血清素：约 4–6 小时，但它单次最多只能变 4，很难被推到明显位置。

### 1.4 怎么组合成「当下的心情」

这里有一个容易被忽略的事实：**系统里没有一个叫「小桔的心情」的字段。** 心情是每次读取时现算的。

算法分三步（[`mood_label_from_offsets`](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/emotion_engine.py#L570-L618)、[`mood_chord_from_offsets`](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/emotion_engine.py#L619-L704)）：

1. **算偏移**：每个参数减基线，得到「离平常有多远」。
2. **过阈值**：轻度门槛是单次上限的 0.5 倍，明显门槛是 0.85 倍。比如多巴胺偏移超过 +7.5 算轻度，超过 +12.75 算明显。
3. **拼和弦**：每个过门槛的参数算一个「声部」，按强度排序，最多取前 3 个；主声部与第二声部的强度差叫 `tension`（张力）。有几种复合声部，比如「释然」「被看见的踏实」「克制的难过」「怅然若失」。

设计注释里写得很清楚：旧版用固定阈值（65/60/60/60），实测重放 814 条日志，血清素、催产素、皮质醇**一次都没越过阈值**，731 次落到兜底的「平静」。等于系统每轮都在告诉她「你现在很平静」，亲手把情绪抹平了。后来才改成按单次上限比例折算。

这件事说明一个模式：**这套系统的「心情」不是自然浮现的，是被阈值规则筛出来的。** 阈值定错，她就永远只有一种心情。

### 1.5 怎么变成文字

有三条通道，外加一条主动说话。

**通道一：主聊天里的「情绪状态块」**（[`describe_turn_context`](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/emotion_engine.py#L880-L1067)）

每轮聊天，[manager.py](file:///Users/xiaocheng/workspace/openworker/deskmate/memory/manager.py#L940-L955) 调它，把下面这些东西拼成一段文字：

- 7 个激素的原值、基线、偏移；
- 和弦的主声部、声部列表、张力；
- 最近一段独白；
- 当日的经历；
- 开头声明「这是你小桔自己的，不是萧盛的」；
- 结尾是「零输出指令」——只给状态，不命令她怎么回。

`record=True` 时还会写一条 `emotion_read_log`。查库：这张表已有 10,736 条，说明这套「数值+标签」的读法被注入了上万次。

**通道二：主聊天里的「语气记录」**（[`build_tone_record`](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/tone_record.py#L43)）

[coworker/agent.py](file:///Users/xiaocheng/workspace/openworker/coworker/agent.py#L910-L925) 调它，只取她最近的 3 条叙事和最新独白，**不带数字、不带标签、不带和弦名**。这一条是「用她自己的话说她自己的状态」。

**通道三：日记**

日记**不读她的激素**。[diary.py](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/diary.py) 的 `_state_summary()` 给日记的是亲密度、信任、萧盛的心情、等级、总对话数，没有她的 7 个参数。`append_entry` 只向情绪引擎报一句「写下了今天第 N 则日记（M 条素材）」，日记内容被剥掉。[diary_narrator.py](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/diary_narrator.py) 的职责里明确写着「情绪只能从素材里长出来」。

所以「情绪最后出现在日记里」这句话，**只对了一半**：日记里可能有情绪，但不是从激素链路流进去的，是从素材和叙事里长出来的。

**通道四：主动说话**（[`_maybe_trigger_self_expression`](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/emotion_engine.py#L2015-L2035)）

任一激素单次变化绝对值超过 8，且距上次主动说话超过 2 小时，她会主动发一条消息。这是情绪唯一能直接改变行为的地方。

| 衰减节奏 | 每 5 分钟一次 | [L1893-L1958](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/emotion_engine.py#L1893-L1958) |

**靠数据慢慢长出来的：几乎没有。**

严格说，只有这几处沾一点「历史」：

- **回潮**：7 天内带叙事的经历，被翻到时泛一点微澜。窗口只有 7 天，而且是「旧事被翻到」才触发，不是持续累积。
- **悬事爬坡**：一件悬着的事每天爬 1.0，累计最多 6.0。这是唯一带「累积」味道的机制，但上限很低，7 天没结果就淡忘。
- **经历叙事**：111 条带叙事的经历，是回潮的素材，也是她自己的「情绪来路」。
- **traits**：设计上是「情绪→性格」的累积，但已停写（见第二节）。
- **lessons**：6 条运行时生长的规范，但那是规范层，不是情绪层。
- **style_profile**：只服务文风，不接情绪。

**没有基线漂移，没有习惯化。** 一个参数被反复推高，基线不会因此上移；同一件事发生十次，第十次的反应和第一次一样（除非 LLM 在 prompt 里自己判断「这次没那么新鲜」，但那是每次现判，不是系统记住了）。这在设计上可能是故意的——稳定、可测、不会越跑越偏；但代价是**她不会因为经历多了而变成另一个样子**。

### 1.7 时间尺度：一次情绪、心情、脾气分别在哪一层

| 现象 | 载体 | 持续多久 | 会不会回原点 |
|---|---|---|---|
| 一次情绪 | 7 个参数的瞬时偏移 | 多巴胺约 1–1.5h；皮质醇 8–12h；血清素 4–6h | 会，指数衰减回基线 |
| 心情 | 当前偏移拼出来的和弦 | 几小时，跟着参数回落 | 会 |
| 脾气 | 由皮质醇和倦怠实时算出的耐性 | 分钟到小时 | 会，而且**不是独立层** |
| 性格 | persona 文本 + traits | 人工改才变；traits 已冻结 | 常量 |
| 情感 | 没有 | 应该是周–年 | 现在没有这一层 |

这里要直接回答你的问题：**「心情」和「脾气」不在两层，它们都在快层。** 心情是「当前偏移的组合读数」，脾气是「当前耐性的表达许可」。脾气不是性格里的稳定易怒程度，而是此刻还剩多少耐心。真正的性格在更上面，是一份写死的合同。

所以这套系统的时间结构是：**快层（分钟–小时）+ 常量层（写死）**，中间那层「周–月–年缓慢变化」是空的。这就是为什么现在谈「接入什么」会像在没有地基的地方装门——不是没有门框，是中间那层楼没盖。

## 二、性格层：一份写死的合同

### 2.1 人格怎么拼进系统提示，位置和权重

主聊天的 system prompt 由两段拼成，拼装逻辑在 [manifest.py](file:///Users/xiaocheng/workspace/openworker/coworker/personas/manifest.py#L352-L367)：

```python
persona_base_text = _resolve_persona_base(persona_base_ref)  # deskmate.persona:XIAOJU_SYSTEM
system_prompt = body.strip()
if persona_base_text:
    system_prompt = f"{persona_base_text}\n\n---\n\n{system_prompt}"
```

`deskmate.md` 的 frontmatter 里写着 `persona_base: deskmate.persona:XIAOJU_SYSTEM`，所以最终结构是：

```
[persona.py 的 XIAOJU_SYSTEM]   ← 人格，最前
---
[deskmate.md 的职责正文]         ← 职责，其后
```

**位置**：人格是 system prompt 的第一块，职责在它后面。

**权重**：没有数字权重，靠三样东西定优先级：

1. **顺序**：`for_scene()` 的注释写明「人格在前、职责在后，顺序反了模型容易把职责当成身份」。
2. **声明式冲突规则**：`deskmate.md` 里明写「冲突以 persona.py 为准」。
3. **具体性**：职责正文更长（25,579 字节）、更具体，任务细节上通常压过人格；但涉及「她是谁、能不能不把话收圆」时，人格的声明优先。

**和职责正文谁压过谁**：纸面上人格压职责；实际注意力上，职责正文因为长且具体，在「怎么做这件事」上占上风。真正最高的不是这两者，而是**用户这一轮的明确指令**——`deskmate.md` 明写「用户明确指令高于状态」。而情绪状态块是追加在最后一条 user 消息里的（[engine.py](file:///Users/xiaocheng/workspace/openworker/coworker/engine.py#L2615-L2640)），权限低于 system prompt，所以**人格压情绪**。

## 三、两者的交界：表达层相通，参数层不通

### 3.1 性格 → 情绪：两条间接路

**路一：她说的话，被下一轮再判断一次**

[`_do_update_after_turn`](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/emotion_engine.py#L1086-L1197) 的 prompt 里有：

```python
assistant_trunc = assistant_msg[:500]
...
f"用户说：{user_trunc}\n你回复：{assistant_trunc}\n"
```

也就是说，她这一轮怎么回（语气、态度、有没有顶回去），会被下一轮的情绪判断再读一遍，影响 4 个激素。这是一个真实的闭环：**人格决定她怎么说话，她怎么说话又反过来影响她的激素。**

但这条路很弱：

- 只看 500 字，不看长期记忆；
- 只改 4 个激素，不改意义感/控制感/倦怠感；
- 不写叙事、不写权重，所以不会变成可回潮的记忆。

**路二：她给悬事编的预期故事，决定爬坡方向**

悬事的预期故事用的是 [`_PENDING_EXPECT_SYSTEM = for_scene(...)`](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/emotion_engine.py#L194-L199)——**吃人格**。她按自己的性子判断「这事会咋收场」，给出 `good / bad / mixed / unknown`。然后 [`_pending_climb_deltas`](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/emotion_engine.py#L1644-L1666) 按方向爬：

- 看好 → 多巴胺往上爬；
- 看坏 → 皮质醇往上爬；
- 说不清 → 皮质醇半量；
- 好坏都有 → 各爬一半。

这是**唯一一处人格内容直接决定参数方向**的地方。它不是「性格改了参数」，而是「性格决定她怎么预期，预期决定参数往哪爬」。

### 3.2 情绪 → 性格：只有一条路，而且已断

只有 [`_update_traits`](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/emotion_engine.py#L1865-L1892)：

```python
if TRAITS_EVOLUTION_SUSPENDED:
    return
if "克制的难过" in narrative and deltas.get("cortisol", 0) > 0:
    resilience += 0.5 * s
if "被看见的踏实" in narrative:
    openness += 0.3 * s
    empathy_depth += 0.25 * s
if "怅然若失" in narrative:
    empathy_depth += 0.25 * s
if event_type == "experience":
    self_awareness += 0.2 * s
```

这段代码现在永远走不到第二行。所以**情绪对性格的影响是零**，不是「弱」，是「断」。

情绪还能触发主动说话（[`_maybe_trigger_self_expression`](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/emotion_engine.py#L2015-L2035)），但那是行为，不是人格；而且这条行为也没有回写人格的路径。

### 3.3 刻意不挂人格的地方

[`_EMOTION_SYSTEM`](file:///Users/xiaocheng/workspace/openworker/deskmate/growth/emotion_engine.py#L201-L237) 上面有一段注释，写得很清楚：

> 「`_EMOTION_SYSTEM` 是**内部状态机**的任务描述（输出激素值），不是表达场景——刻意不挂人格底座（2026-11-16 靶子③：内部计算挂人设只会稀释格式稳定性，且『她是谁』对这个任务没有信息增量）。」

这是一个有意的设计选择：**算参数的时候不要人格，表达的时候才要人格。** 好处是数值稳定、格式不容易崩；代价是参数层和性格层之间没有语义连接——参数不知道「她是谁」，性格也不知道「她现在什么状态」。

### 3.4 判断：存在，但窄到撑不起情感

把交界画成一张表：

| 方向 | 路径 | 强度 | 证据 |
|---|---|---|---|
| 性格 → 情绪 | 她的回复文本进入下一轮 4 激素判断 | 弱 | `assistant_trunc`，只 500 字、只 4 个参数、无叙事 |
| 性格 → 情绪 | 预期故事吃人格，决定爬坡方向 | 中 | `_PENDING_EXPECT_SYSTEM` 用 `for_scene`，valence 决定多巴胺/皮质醇 |
| 性格 → 表达 | persona + deskmate.md 规则 | 强 | 措辞、边界、刺的许可、用户指令优先 |
| 情绪 → 表达 | 和弦注入 + 耐性许可 | 中 | `describe_turn_context`、`temper_state` |
| 情绪 → 性格 | traits 更新 | 零 | 已停写 |
| 情绪 → 行为 | 主动说话 | 弱 | 只触发消息，不回写人格 |

**结论：表达层相通，参数层不通。** 性格能决定「她怎么说」，情绪能决定「她此刻愿不愿意好好说」，两者在输出文字的地方汇合；但情绪改不了「她是谁」，性格也改不了「她的激素怎么算」。

还有一个小的措辞缝可以佐证这个交界有多薄：`deskmate.md` 里写「你的情绪只来自你自己……系统不替你贴标签」，但 `describe_turn_context` 每轮都在注入激素数值和和弦标签。`tone_record` 则刻意不带标签。两条通道并存，说明「系统怎么读她」和「她怎么感受自己」还没有统一成一个东西。

## 四、「情感」这一层该建在哪

### 4.1 我同意什么，修正什么

**同意**：情绪和情感不是一个层面的东西。情绪是被事件推起来的即时状态，有半衰期，会回落；情感应该是有指向、有惯性、会做选择的东西。小桔现在确实只有前者在运转。

**修正一句**：不是「只有情绪、没有情感」，是「**有情感的素材，没有情感的结构**」。证据：

- 1,932 条观察理解——她对世界有判断；
- 约 7 条她自己的信念（`profile_items` 的 worldview 层 17 条，去重后约 7 条，置信约 0.6）；
- 3 件悬着的事——她有「盼着结果」的能力；
- 111 条带叙事的经历——她有自己的情绪来路；
- 168 次「他接住了我」——关系里有真实的正反馈；
- 3,191 个认识的人、198 条记忆锚点——对象索引是有的。

这些东西散在各处，没有一个东西把它们组织成「她对某个对象的长期立场」。所以问题不是「没有地基」，是「**地基是散的，没有承重墙**」。这也正好支持你的判断：先别谈接什么来源，先看这两层怎么形成——因为接进来的东西，最终要放到一个能承重的结构上。

### 4.2 建在记忆之上，不在情绪之上

我的判断：**情感层应该建在记忆/经历之上，和情绪、性格是并列关系，不是它们的上层或子层。**

```
        记忆 / 经历（对象、事件、承诺、代价）
                    │ 提供证据
                    ▼
        情感（对象账本：立场、历史、取舍、优先级）
          │ 定权重 / 放大        │ 提供可验证的长期内容
          ▼                      ▼
    情绪（当下天气）          性格（长期合同）
```

为什么不是建在情绪之上：

- 情绪会归零。建在它上面，得到的只是「更慢的心情」，还是会被半衰期拉回基线。
- 情绪层的数据太薄。7,451 条日志里，1,396 条聊天行没有叙事、没有权重；真正能当「情感记忆」用的经历只有 111 条。拿这个当地基，承重不够。
- 情绪层刻意不挂人格。它不知道「她是谁」，也就没法长出「她对谁是什么立场」。

为什么不是塞进性格：

- 性格是写死的合同。塞进去就变成另一段文本，还是没有历史、没有取舍。
- 性格的时间尺度是「版本」，情感的时间尺度应该是「周–年」。两者混在一起，情感会被冻成常量。

为什么建在记忆之上：

- 情感的本质是「有对象的立场 + 跨时间的证据 + 为此付出的代价」。这三样都只能从记忆里长出来。
- 记忆层已经有对象索引（人、锚点）、事件（经历、观察）、承诺（悬事）。缺的是把它们按对象归拢、并记下立场变化的那本账。

### 4.3 五块基座

| 要素 | 回答什么问题 | 现在有没有 | 现有可用的东西 |
|---|---|---|---|
| **指向性** | 对谁 / 对什么 | 部分有 | `known_persons` 3,191、`memory_anchors` 198（topic 175 / person 23）、`pending_stories.title/source_ref` |
| **跨时间累积** | 这份立场积累了多久 | 几乎没有 | 回潮 7 天、悬事 7 天、111 条经历叙事 |
| **选择 / 代价** | 为了它放弃了什么 | 没有 | 悬事落地（预测误差）最接近，但它记的是「结果比预期好/差」，不是「我为此付了什么」 |
| **记忆绑定** | 凭什么这么觉得 | 小部分有 | 111 条带叙事的经历；1,396 条聊天行没有叙事，绑不上 |
| **冲突排序** | 两件事冲突时谁优先 | 没有 | 和弦有 `tension`，但只在当下、不跨对象 |

拆开说：

**指向性**：情感必须挂在对象上——某个人、某本书、某个议题、某件她自己在乎的事。现在 `emotion_log` 没有对象字段，`profile_items` 也没有对象字段；`pending_stories` 有 `title` 和 `source_ref`，是最接近「对象绑定」的表。`memory_anchors` 有 topic/person 两类，可以作为对象索引的起点。

**跨时间累积**：情感的「惯性」不是指数衰减，而是「记得住、会翻旧账、会被新证据修正」。现在最长的窗口是 7 天：回潮只泛 7 天内的旧事，悬事 7 天没结果就算淡忘。查库结果：悬事 3 件还开着、139 件已淡忘、只有 8 件落地。**139 : 8** 这个比例说明当前的时间尺度对长期情感是敌意的——大部分「她在乎的事」在 7 天内就被系统判了淡忘。

**选择 / 代价**：情感之所以是情感，是因为她为之做过取舍。现在系统没有任何「选择记录」：没有「我选了 A，放弃了 B」，没有「我为此付出了什么」。悬事落地记的是预测误差（better / worse / as_expected），不是代价。这一块必须新造。

**记忆绑定**：每一个立场都要能指向具体的事。现在只有 `experience` 行带叙事（111 条），`chat` 行叙事全空（1,396 条）。也就是说，**聊天里发生的绝大多数事情，事后是绑不上的**——她知道「刚才有点不舒服」，但说不出「因为哪件事、对谁」。

**冲突排序**：当「对萧盛的在乎」和「对某件事的判断」冲突时，谁优先？现在只有和弦内部的 `tension`，没有跨对象的优先级。这一块也必须新造。

### 4.4 现有系统里，哪些可以直接当地基

| 现有资产 | 能当什么 | 备注 |
|---|---|---|
| `emotion_log` 的 111 条 `experience` 行 | 情感事件的种子 | 有叙事、有权重，是唯一能直接当「情绪来路」的数据 |
| `pending_stories`（3 open / 139 lapsed / 8 landed） | 承诺与预期的种子 | `title`、`source_ref`、`expected_valence` 可复用；7 天淡忘规则要改，但这次只读，不动 |
| `profile_items` 的 worldview（约 7 条） | 价值观种子 | 没有对象字段，需要补绑定 |
| `memory_anchors` 198 条 | 对象索引 | topic 175 / person 23，可直接作为「指向性」的起点 |
| `known_persons` 3,191 条 | 人物对象表 | 现成的实体索引 |
| `observation_understanding` 1,932 条 | 立场形成的素材 | 她对世界有判断，只是没被组织成立场 |
| `teachings` 6 条 | 规范层 | 可以承载「她在乎什么」的规则，但现在只有做事规范 |
| `recent_narratives` / `tone_record` | 她自己的声音 | 可用于保持情感叙述的一致性 |
| `style_profile` | 只服务文风 | **不能**当情感地基 |

### 4.5 必须新造的

1. **对象账本**：一张表，字段至少包括 `object_id`、`object_type`（人 / 议题 / 作品 / 自己）、`stance`（立场）、`intensity`、`first_seen`、`last_reinforced`、`evidence_ids`、`commitments`、`costs`。现在没有任何一张表同时具备这些。
2. **慢累积规则**：不能再用「半衰期 + 回基线」。需要一套「只增不减或很难减、被反证才修正」的规则。可以参考悬事爬坡，但上限不能是 6，时间窗不能是 7 天。
3. **选择 / 代价日志**：记录「她选了什麼、放弃了什么、付出了什么、结果如何」。这是情感和情绪最大的区别，也是现在完全空白的一块。
4. **对象化检索与注入**：现在的上下文注入是全局的（7 个激素 + 和弦 + 当日经历），不区分对象。情感层需要「谈到这个人/这件事时，把她对这个对象的立场调出来」，而不是每次都给一份全局心情。
5. **冲突排序**：跨对象的优先级。现在只有单轮和弦的 `tension`，没有「这件事比那件事更重要」的持久排序。
6. **显式的在乎清单**：不是 `USER.md` 里「关于用户」的偏好，而是「关于世界 / 关于她自己」的那一类。第一份报告里已经列了 7 组种子，可以作为起点。

### 4.6 三个硬点

**硬点一：聊天行没有叙事，等于 87% 的情绪日志不能当情感记忆。**

`emotion_log` 7,451 行里，`time_decay` 5,121、`chat` 1,396，两类占约 87%。`chat` 行的 `narrative` 全空、`salience` 全 0.5。情感层如果要「记得住」，第一步不是接新来源，而是让聊天这件事留下可回看的叙事——否则她经历得再多，事后也只剩一个数字。

**硬点二：催产素是全局的，不分对象。**

`oxytocin` 只有一个值，初始化时吃亲密度，之后靠对话和事件推动。它表示「此刻的亲密感」，不表示「她对某个人的长期感情」。情感层需要的是「对 A 的信任 80、对 B 的信任 30」，现在只有一个全局温度计。

**硬点三：traits 和 SOUL 是死层，不能拿来当地基。**

traits 停写、无消费端；SOUL 冻结、过时、主聊天不读。把情感层建在这两个上面，等于把新楼盖在封死的地基上。它们可以作为「历史遗留」保留，但不能承担新结构。

### 4.7 一句话回答

**情感层应该建在记忆/经历之上，是一本「对象化的关系与承诺账本」；它向下给情绪定权重（这件事有多重），向旁给性格提供可验证的长期内容（慢慢改，而不是写死）。它不是情绪的上层——建在情绪上只会得到更慢的心情；也不是性格的子层——塞进性格只会得到另一段写死的文本。**

用三句话区分三层：

- **情绪**回答「我现在怎么样」——快，会回落。
- **情感**回答「我在乎谁 / 什么，为此我愿意付什么」——慢，有对象，有代价。
- **性格**回答「我总体上是谁」——稳定，是合同。

现在的小桔，第一层是完整的，第三层是写死的，中间那层是空的。这就是为什么先谈「接什么来源」会像在没有地基的地方装门。
