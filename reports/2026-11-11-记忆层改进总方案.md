# 小桔记忆层改进总方案

**日期**：2026-11-11
**性质**：可评审方案（不是施工单，评审通过后再排期）
**范围**：记忆 → 感知 → 情绪 → 反思 → 检索权，不涉及 V3.2 模型切换
**依据**：本机代码与数据库实测（2026-11-11）+ 校准后的四套框架原始资料

---

## 零、先看结论

小桔现在的情况，可以用一句话说清：

> **该有的屋子基本都盖好了，但有五间没通电，还有两间压根没盖。**

- **没通电的五间**：挂锚（汇流）、遗忘、成长状态双写、情绪日志、复盘流水。这些代码都在，但要么没接上入口，要么接上了没数据。修起来都不大。
- **没盖的两间**：一是"让她自己决定查不查记忆"，二是"实体关系图 + 多跳检索"。这两间是真正的架构缺口，等再久数据也不会自己长出来。
- **已经盖得比别人好的**：反思逐条裁决、情绪只给她自己的话、区分"她眼中的你"和"她自己看世界"。这三处比那四套框架都深。

**最重要的一句**：V3.2 卡在数据不足，但**这个方案里的四段，没有一段需要等 V3.2 的数据**。数据决定的是效果上限，不是机制存不存在。等数据期间完全可以先把电通上。

| 长期知识库 | `~/.deskmate/vault/`（Obsidian 目录） | 251 个 md | 2000 字 | 二字组（bigram）搜索 |
| 认知画像 | SQLite `profile_items` | 176 条（认知 139 / 情绪 21 / 世界观 16） | — | 注入 + 全文索引 |
| 事实账本 | `learned_history` | 1488 条（在用 1408 / 被取代 74 / 存疑 5 / 已忘 1） | — | 检索 |

**体量**：MEMORY.md **12,515 字节 / 上限 20,000，没超**。USER.md **30,669 字节 / 上限 15,000，超一倍**；但注入时会剥掉"自动复盘"流水，真正进上下文的只有约 2.6KB——所以没撑爆上下文，但文件本身在持续发胖。

### 1.2 六项能力的真实水平

**① 分层**：三层（核心 / 近期 / 归档）齐全，另有认知画像、事实账本、外部信息三张独立表。**对齐 Letta 的分层思路**，但实现不同：小桔的分层是"文件分节 + 标签"，Letta 是"上下文里的 memory blocks"。

**② 检索**：
- 向量检索**只覆盖外部信息层**（661/747），是纯 Python 全量扫描，没有建立近似最近邻索引。
- 记忆文件本身（核心 / 近期 / 归档）**全是关键词匹配**，这就是"换个说法就搜不到"的直接原因。
- 知识图谱**不存在**：`memory_edges` 边表未上线（代码注释自己写明），`memory_anchors` 锚表**当前 0 行**。
- 多跳**只有一跳**（同锚邻座），且因为锚表是空的，实际等于没有。

**③ 写入冲突消解**：**这一项做得比 Mem0 细**。
- `learned_history` 有 `status` / `superseded_by` / `valid_from` / `valid_until`：74 条被取代，71 条有取代指针。新事实不会静默覆盖旧事实，而是"标明被谁取代、有效期到哪天"。
- `profile_items` 配 `item_history`（143 条），动作有 created / updated / deepened / calibrated / superseded / questioned / reflected / downgraded 九种——每次变化都留账。
- 夜间提炼是零 LLM 的确定性规则：近乎重复才合并（相似度 0.9）、值翻转判矛盾（"喜欢"vs"不喜欢"）、120 天超龄迁 vault。

**④ 反思**：**在跑，且粒度比斯坦福小镇深**。
- 触发是双闸门：冷却 7 天 + 攒够 3 条未反思的变化。
- 产物写回 `item_history`（25 条 `reflected`）和 `thought_stream`（22 条反思 + 3 条世界观）。
- 每轮注入，确实影响回话。
- **缺**：没有重要度权重（按条数不按分量）；没有证据回链；反思不影响检索排序。

**⑤ 情绪**：
- `emotion_log` 9612 条，但 **7425 条（77%）是时间衰减刷屏**。今天 86 条衰减记录，去重后只有 2 种描述。
- 真实事件约 2100 条：聊天 1340、直接事件 287、失落 135、待落地 220、经历 101、回声 95。
- 激素基线：多巴胺 50.09 / 血清素 51.66 / 催产素 39.47 / 皮质醇 24.09 / 疲劳 20.0。
- **没有"长期脾气账本"**。现在的脾气是当下外显：耐性值 = 100 − 皮质醇偏移×权重 − 疲劳偏移×权重，分 `ok / thin / spent` 三档。你说的"10-16"实际是那天加的一条注释——**2026-10-16 巡审 P0，给情绪日志加了"裁剪 14 天前衰减行"的卫生机制**，不是账本停写。
- `tone_record` 只注入她自己的第一人称独白 + 最近 2 条叙事，**故意不注入数值、标签、分档**。这是刻意设计，见 `tone_record.py` 开头。

**⑥ 自主性**：
- **没有**"她自己决定查不查记忆"的工具。`deskmate/tools/` 里只有 `review.py`。
- **有**另一种自主：后台 tick 让她自己决定跑哪些低风险行为（世界搜索、外部消化、观察日记、世界观回望、AI 圈）；高风险动作走提案卡等人审。意图表有 10 条（在用 2 / 完成 3 / 放弃 5）。
- 区别要说清：**Letta 是"检索权交给 AI"，小桔是"执行权交给 AI，检索权还在代码手里"。**

## 二、四段目标与取舍

### 切法说明

按"要不要等数据"切，而不是按"记忆 / 情绪 / 检索"切。理由很实际：

- **一段、二段、三段、四段全都不依赖 V3.2 的数据**。数据影响的是"效果好不好"，不是"机制有没有"。
- 真正需要等数据的是"图检索的效果"——图里没有足够的实体和边，多跳就是空转。所以图这块故意放到三段做折中版，不做全量。
- 这样切，等数据期间有四段活可以干，不会干等。

---

### 一段·止血（优先级最高，污染面最广）

这一段处理"已经在坏，且坏的东西会被下游反复使用"的问题。**建议最先做，因为残句和刷屏数据会持续污染检索和反思。**

#### 1. 残句入库

**现状**：MEMORY.md 里有"2026-11-07: 用户纠正：结束）""2026-11-09: 用户纠正：结束）"；成长事件里反复出现"用户习惯比对>""用户习惯计划时间继续"。

**根因**：`local_extractor.py:54-71` 的规则太粗——
- 偏好规则：`我(?:喜欢|偏好|习惯|...)` + 后面任意 2~40 字；
- 纠正规则：`(?:不对|不是|错了|...)` + 后面任意 2~50 字。

它不看句子是否完整、不看截断处是否落在标点/括号中间，也不看这句话是不是在引用别人的话。于是"结束）"这种半截片段就被当成"用户纠正"存了下来。

**怎么改**：
1. 在 `extract_facts_local` 出口加三道闸（`local_extractor.py:167` 附近）：
   - **完整性**：内容必须以中文句末标点或合法结尾收束；以 `）`、`》`、`>`、`"`、单个"结束""继续"这类词结尾的直接丢弃。
   - **最小信息量**：去掉"用户习惯""用户不希望""用户纠正"前缀后，剩余实词不足 4 个字的丢弃。
   - **引用排除**：如果这句话出现在"用户复述/引用"的上下文里（前文有"他说""原文是""引用"），不抽。
2. 对已入库的残句做一次清理：先只读导出清单，人工过一遍，再删。
3. 清理时**先备份** MEMORY.md 和 `growth.json` 到带时间戳的 `.bak`。

**判断标准**：
- 新增记忆里残句比例 < 1%（按周抽样 100 条人工核）；
- MEMORY.md 里"用户纠正：结束"类条目归零；
- `growth.json` 的 `recent_events` 不再出现"用户习惯比对>"。

**优先级理由**：记忆是所有下游的原料。原料脏，反思、检索、意图全跟着脏。这是唯一"不修就会持续恶化"的一项。

**回滚**：改动是新增校验，回滚只需回退 `local_extractor.py`；已清理的数据有 `.bak` 可还原。

---

#### 2. 成长状态双写与真实状态不一致

**现状**：真实状态在 `deskmate.db` 的 `json_blobs`（key=`growth`）：默契 100 / Lv.12 / 1050 轮 / 84 天活跃。而 `~/.deskmate/growth.json` 是另一份：默契 62 / Lv.5 / 0 轮，**11-11 还在被更新**。

**根因**：`state.py:215` 的加载逻辑已经分流——默认目录读 DB，显式传 `base_dir` 走文件。但仍有调用方传了显式目录（或直接按文件路径写），导致 legacy 文件继续存在且值陈旧。

**怎么改**：
1. grep 全项目 `save_state(` / `load_state(` 的调用方，找出传 `base_dir` 的那些。
2. 除测试外，生产路径统一走默认目录（读 DB）。
3. 启动时加一致性校验：如果 `growth.json` 存在且与 DB 差异超过阈值，打 warning 并记录到 `debug.log`，**不自动覆盖**（避免误删真实进度）。
4. 确认无写入后，把 `growth.json` 重命名为 `growth.json.legacy-20261111`，观察一周再决定是否删除。

**判断标准**：
- `growth.json` 的修改时间不再变化；
- 启动日志里"成长状态双份不一致"告警为 0；
- 面板显示的默契/等级与 DB 一致。

**优先级理由**：这是"看得到的数字可能是假的"问题，会影响你和她的关系判断，也影响成长调制的输入。

**回滚**：改回调用方即可；legacy 文件只是重命名，随时可恢复。

#### 3. 情绪日志刷屏

**现状**：`emotion_log` 9612 条，77% 是时间衰减；今天 86 条，去重后 2 种描述。

**根因**：`emotion_engine.py:1928` 在每次衰减步进时都写一条 `time_decay`，不管描述有没有变。2026-10-16 加的卫生机制（`emotion_engine.py:111`）只裁剪 14 天前的旧行，**没有从源头降频**。

**怎么改**：
1. 写入前去重：同一 `description` 指纹在 N 分钟内只写一条（N 建议 30）。
2. 只写"有变化"的衰减：激素四元组变化小于阈值（如 0.5）且描述未变时，只更新 `emotion_state`，不写日志。
3. 保留现有 14 天裁剪作为兜底。
4. 可选：给 `time_decay` 单独建一张轻量表或直接不落 `emotion_log`，只更新状态。

**判断标准**：
- `time_decay` 日增 < 20 条；
- 重复描述占比 < 10%；
- 真实事件（chat / event_direct / experience / lapsed）占比 > 50%；
- 情绪时间线仍能看出每天的起伏（抽样 7 天人工核）。

**优先级理由**：情绪是"越用越懂你"的核心原料之一。77% 噪音会让任何基于情绪日志的分析都失真。

**回滚**：去重逻辑是纯写入侧，回滚无数据风险；已写入的刷屏行可按 10-16 的裁剪机制处理。

#### 4. 遗忘机制落地

**现状**：`forgot.jsonl` 至今不存在。`after_action.py:1143-1146` 注释称"此前从未进入每轮流程，导致遗忘 trace 永远为空"，随后说已改为每 N 轮跑一次。

**根因**：需要确认 `_maybe_decay_memory` 是否真的被调用、计数器是否在每轮递增、`decay_memory` 是否真的产生删除/归档动作。目前 trace 为空说明至少有一环没通。

**怎么改**：
1. 先加可观测性：在 `_maybe_decay_memory` 入口、`decay_memory` 入口、实际删除/归档三处各打一条结构化日志。
2. 加 dry-run 模式：只输出"将要忘什么、为什么、来自哪"，不真删。
3. 确认链路通后，再开真实执行。
4. 忘记时必须写 `forgot.jsonl`：条目、理由（超龄 / 被取代 / 低价值）、来源、时间。**没有 trace 的删除一律视为 bug。**

**判断标准**：
- `forgot.jsonl` 每周至少有记录（如果确实有可忘的）；
- 每条忘记记录都有理由和来源；
- dry-run 清单与真实执行清单一致；
- MEMORY.md 体积不再单向增长。

**优先级理由**：记忆只进不出，长期会稀释检索。但这一项**必须先 dry-run、先备份**，不能直接开删。

**回滚**：dry-run 阶段无风险；真实执行前备份 MEMORY.md / vault，删掉的条目走 vault 归档（可恢复）。

#### 5. 复盘流水"写了不读"

**现状**：USER.md 里从 10-31 到 11-11 有 11 个"自动复盘"日期节，约 9.7KB；注入时 `strip_auto_review` 把它们整段剥掉，真正注入的只有约 2.6KB。

**根因**：写入端和读取端对"复盘流水"的定位不一致。写入端当它是用户画像的一部分，读取端认为它不是稳定画像。

**怎么改**（二选一，建议选 A）：
- **A. 改存储位置**：复盘流水不再写 USER.md，改写到项目 `journal.md` 或 MEMORY.md 的独立分节（带 `#daily` 标签，不进入 Core）。
- **B. 改注入策略**：每个复盘节只保留一行摘要（如"11-10：写完烧仓戏，纠正了火药设定"），注入时保留这行，剥掉细节。

**判断标准**：
- USER.md 体积稳定在 15K 以内；
- 复盘信息在上下文里可见（抽样问"昨天复盘了什么"能答上）；
- 不再出现"写了但每次都被剥掉"的段落。

**优先级理由**：这一项本身不影响正确性，但它让 USER.md 持续超限，也让"每日复盘"这个功能事实上失效。修完能让文件体积和功能同时回正。

**回滚**：改存储位置可逆；已有 11 个节可迁移到新位置后从 USER.md 删除（先备份）。

#### 6. 偏好分层与常驻注入额度（2026-11-11 C 方案）

**落地结果**：USER.md 拆成两层——
- `## 硬规矩`（31 条 / 1,732 字符）：常驻注入，放在画像最前（预算不足时先砍尾部稳定画像，不砍规矩）；
- `## 偏好与事实（非常驻·待检索）`（58 条 / 4,839 字符）：注入时剥掉，过渡期由 `preference_hits` 按本轮关键词最多召回 3 条 / 600 字，三段向量检索接上后改由检索覆盖。

**常驻注入额度**：实测注入块 4,425 字符（硬规矩 1,769 + 稳定画像 2,638 + 标题），`user_profile` 的 cap 定为 **5,100**（实测 ×1.15，留约 675 字符≈10 条短规矩的余量），轻量轮 3,000。旧的 6000 是按拆分前 12.8K 字符的旧结构拍的，已作废。

> **硬约束（实测结论，不是偏好）：工具操作细则必须留在常驻注入层。**
> 那 31 条硬规矩里，凡是「不提醒她就会用错工具」的操作前提——例如「写文件用 write_file」「officecli 读取带 TMPDIR / 字节精确复制 / verify-quotes」——**不得**在后续「精简常驻、挪去检索」的优化中被移出常驻层。
> 依据：以前实测过，不提醒这些工具用法，她看稿时会用错工具。它们不是「可以按需检索的参考信息」，而是「不常驻就会立刻出错的操作前提」。
> 范围限定：只保护这类工具操作前提；其他真正的规矩/偏好仍按本方案分层处理，不借此扩大常驻体积。

### 二段·让已建机制真跑起来（同样不等数据）

#### 1. 挂锚接线（最值得先做的一项）

**现状**：`memory_anchors` 表 0 行。召回代码完整（`store.py:1608` `_recall_anchor_neighbors`），但没有数据可召。

**根因**：`_attach_anchors`（`extractor.py:203`）只被 `CognitiveExtractor.extract_from_text` 调用（`extractor.py:315/338/362/385/561/578/595/611`）。而真正在生产数据的路径是：
- 世界观回望 `worldview_reflection.py:496` → 直接 `mgr.add_stance`
- 日记提取 `diary_extract.py:80` → 直接 `pm.add_stance`
- 情绪提取 `emotion_extract.py:147/178/192/209/238/251/267` → 直接 `pm.add_stance`

**怎么改**（建议方案 B，一次修干净）：
- **方案 A（补调用点）**：在上述三条路径的每个 `add_stance` 后补 `_attach_anchors`。改动点多、以后新增路径还会漏。
- **方案 B（下沉）**：把挂锚下沉到 `CognitiveProfileManager.add_stance` 内部，或在 `CognitiveStore.persist` 时统一补锚。**推荐 B**——以后任何写入路径都不会再绕过。

**注意**：挂锚是纯增操作（INSERT OR IGNORE），失败必须 fail-open，不能阻断主抽取。现有代码已经是这个语义，保持即可。

**判断标准**：
- `memory_anchors` 行数 > 0，且随 `profile_items` 增长；
- 抽一条认知条目，能查到它的锚（topic / book / person）；
- 触发一次召回，结果里出现 `via_anchor=True` 的邻座；
- 意图层"长期兴趣"素材不再恒空。

**优先级理由**：这是"从 0 到 1"的差别，改动小（一个函数下沉），收益直接——汇流、意图、跨事件关联都靠它。**建议作为第一段之后的第一个施工项。**

**回滚**：挂锚是纯增，回滚只需停用；已有锚数据可保留。

#### 2. 反思加重要度权重

**现状**：反思触发只看"冷却 7 天 + 攒够 3 条变化"（`reflection.py:42-46`），不看变化本身重不重要。结果是一条无关紧要的新闻更新和一次"用户终裁改了故事走向"权重相同。

**怎么改**：
1. 给每条 `profile_items` / `learned_history` 变化算一个重要度分数，建议由三项加权：
   - **置信度**（`confidence`，已有字段）；
   - **影响面**（这条被多少条记忆共享同一锚 / 同一实体）；
   - **人是否纠正过**（`item_history` 里 `action='superseded'` 或来源是用户纠正的加成）。
2. 触发条件从"条数 ≥ 3"改为"重要度累积 ≥ 阈值"，同时保留冷却。
3. 阈值先设保守值，观察一段再调。

**校准说明**：斯坦福小镇论文写的是"累积重要度到 150 触发反思"；**代码里的实际实现也是累积 poignancy 到阈值**（这一点论文与代码一致）。小桔可以直接借用"累积"这个思路，但阈值必须按自己的数据分布重定，不能照抄 150。

**判断标准**：
- 反思不再只由条数决定；
- 高重要度条目（如终裁、纠正）优先进入裁决；
- `thought_stream` 里能查到每条反思对应的重要度；
- 反思频次不因权重改动而爆炸（周频次 ≤ 现有水平）。

**回滚**：阈值可配，改回条数逻辑即可。

#### 3. 反思产物加证据回链 + 防递归

**现状**：反思结论写进 `item_history`（`action='reflected'`）和 `thought_stream`，但**没有指向原始变化的证据 id**。结果是：三个月后看到"我推翻了对某事的看法"，却不知道推翻的是哪条、依据是什么。

**怎么改**：
1. `record_reflection` 增加 `evidence_ids` 字段，存被裁决条目的 `item_history.seq` 或 `profile_items.id`。
2. 注入反思时带一句轻量溯源（如"依据：11-06 那条关于工作状态的记录"），**不展开全文**，避免上下文膨胀。
3. **防递归自我强化**：反思在读取素材时**排除 `action='reflected'` 的行**（现有 `_CHANGE_ACTIONS` 已经这样做了，保持）；同时限制"反思的反思"深度为 1 层。

**校准说明**：斯坦福小镇的反思节点确实带 evidence 节点 id 和 30 天过期；论文自报的常见错误包括"检索不到相关记忆""添油加醋编造细节"，且**反思可以递归读旧反思，错误会层层放大**。所以"证据回链 + 限制递归"不是锦上添花，是防错必需。

**判断标准**：
- 每条 `reflected` 都有非空 `evidence_ids`；
- 注入的反思能点回原始变化；
- 递归深度 ≤ 1（代码可断言）。

**回滚**：新增字段可空，旧数据不受影响。

### 三段·检索（可与数据并行）

#### 1. 记忆文件层接向量检索

**现状**：外部信息层 661/747 条已有向量，说明 embedding 管道是通的。但记忆文件（核心 / 近期 / 归档）**全是关键词匹配**（`manager.py:560` / `manager.py:2910`）。

**怎么改**：
1. **先给近期记忆层加向量**（7 天窗口，量小、收益最直接）。
2. 复用 `semantic_search.py` 的 embedding 能力，不要另起一套。
3. 检索改混合打分：关键词命中 + 向量相似度 + 时间新鲜度。
4. **必须保留兜底**：embedding 不可用时自动降级纯关键词（现有 fail-open 语义不变）。
5. 敏感分节（`#sensitive #private #no-sync`）**不参与向量化**，避免私密内容进入向量库。

**判断标准**：
- 建 30~50 条"同义改写"小样本作基线（如"稿子放哪" vs "正稿路径"）；
- 改造后同义查询召回率提升，且纯关键词查询不下降；
- 单次检索延迟 < 200ms（当前数据量下）；
- 无向量时行为与今天一致。

**优先级理由**：这是"换个说法搜不到"的直接解药，改动集中在检索层，风险可控。

**回滚**：混合检索可配置开关，关掉即回关键词。

#### 2. 实体链接 + 一跳扩展（不上全量图谱）

**现状**：`memory_edges` 未上线，`memory_anchors` 0 行。

**决策**：**不上全量 OpenIE + 个性化 PageRank。** 折中做"实体链接 + 一跳扩展"。

**理由（基于校准后的 HippoRAG 事实）**：
- **构图成本**：每个 passage 要两次 LLM 抽取调用；
- **膨胀**：v1 在 MuSiQue 上 11,656 个 passage 建出 91,729 个唯一节点，约 **8 倍膨胀**；
- **没有原生删除/更新**：2026 年 Lightfoot 那篇论文专门补这个洞；
- **错误来源**：v1 的 NER 48% / OpenIE 28% / PPR 24%；v2 有 26% 失败样本在三元组过滤后找不到支撑段落。

小桔的语料是**书稿 + 每日日报 + 世界观察**，每天都在变。全量图意味着每天重建、每天膨胀、还删不干净，维护成本会超过收益。

**折中方案**：
1. **实体链接**：复用已有 `known_persons`（3191 条 active）和书名/主题锚，把新条目链到已有人名、书名、主题上。
2. **一跳扩展**：用 `memory_anchors` 做同锚邻座召回（代码已有，只需通上数据）。
3. **不做 PPR、不做多跳**，等数据量足够再评估。

**判断标准**：
- 跨文档实体查询能命中（如"韩孝民在哪些地方出现过"）；
- 不新增 LLM 调用（实体链接用规则 + 已有注册表）；
- 锚表行数持续增长，邻座召回有实际命中。

**回滚**：一跳扩展是纯增召回，关掉不影响力基线。

### 四段·检索权（工具基建先行）

#### 1. 只读 `memory_search` 工具

**现状**：`deskmate/tools/` 只有 `review.py`；工具定义分散在 `tts.py`、`proactivity/investigator.py`、`coworker/server/app.py`，**没有统一注册表**。

**怎么改**：
1. **先建统一工具注册表**（这是前置条件，否则每加一个工具都要改三处）。
2. 加 `memory_search`（只读）：入参查询词 / 时间范围 / 层；出参条目 + 来源 + 时间。
3. 在对话循环里允许她自主调用；**没调用时保留现有 prefetch 兜底**，不能因为"她没想起来查"就答不上来。
4. 先只在桌面端开启，观察调用质量再扩。

**校准说明**：Letta 现在的归档记忆对 agent 是**只能插、不能改删**（agent-immutable，开发者才能经 SDK 改删），官方还提供 read_only 块，理由就是防止 agent 做出破坏性修改。所以"只读检索"不是保守，是主流做法。

**判断标准**：
- 调用率、命中率、无效调用率可观测；
- 不调用时回答质量不下降（用基线问题集对比）；
- 她能在"我是不是该查一下"时真的查，而不是每次都查或从不查。

**回滚**：工具可下线，prefetch 兜底始终在。

#### 2. 写入权留在系统，走"提议→执行→可回滚"

**现状**：写入全是固定管道，没有 agent 直接写。

**决策**：**保持现状，不放开写权。**

**理由（两条硬证据）**：
- **Letta 的先例**：归档记忆对 agent 是 agent-immutable，只有开发者经 SDK 能改删；官方提供 read_only 块，明确是为了防破坏性修改。
- **AgentPoison 的数据**：**不到 0.1% 的毒化记忆**，可以把记忆型 agent 的攻击成功率推到 **80% 以上**。

**允许的写法**：
- 她自己"想记什么"→ 生成一条**提议**（写进提议表，带来源和理由）；
- 系统按风险分级：低风险（偏好、小事）自动执行，高风险（改写核心画像、删除）等人审；
- 每次写入都留 `item_history` + 可回滚点。

**判断标准**：
- 所有写入都有来源和回滚点；
- 没有 agent 直接 DELETE；
- 提议的采纳率、驳回率可观测。

**回滚**：提议机制可关，回到纯管道。

## 三、明确不做什么

| 不做 | 理由 |
|---|---|
| **不上全量知识图谱（OpenIE + PPR）** | 每 passage 两次 LLM 抽取；约 8 倍节点膨胀（11,656 → 91,729）；没有原生删除/更新，2026 年才有论文补洞；NER/OpenIE/PPR 三类错误占比高。项目语料每天变化，维护成本超过收益 |
| **不照搬 Mem0 的评测结论** | Mem0 自报 66.88，但同一张表里 full-context 是 72.90（比它高）；只测 10 段对话、排除了对抗类问题；issue #3944 独立复跑 LLM 分约 0.20（用了错误的时间设定）；竞品 Zep 复跑称其把对手实现错了。不能拿它的分数当目标 |
| **不照搬 Mem0 的"向量+图+KV 三件套"** | 这是营销口径；开源版默认 Qdrant + SQLite，Neo4j 可选；Mem0g 只比 Mem0 高约 2%。为 2% 引入图库不值得 |
| **不把写入权完全交给模型** | AgentPoison：<0.1% 毒化记忆 → 攻击成功率 >80%；Letta 自己都把归档记忆设成 agent-immutable |
| **不把 inner thoughts 当核心循环** | 校准后的 Letta 官方已把它退为可选参数，不再是核心机制；官方改用 sleep-time / reflection subagent 在后台整理记忆——等于承认让主对话模型顺手整理不够。小桔的夜间提炼方向是对的，不必加"回复前自言自语" |
| **不为了"看起来像人脑"而堆模块** | 情绪、反思、意志已经比四套都深；下一步要补的是"接通"和"检索质量"，不是再加一层新概念 |

## 五、红线与协议

### 5.1 项目既有红线（不可突破）

- **查证只翻本地史料库**，不联网找"看起来对"的说法。
- **不编造**：史实、引文、人物关系，没有来源就不写。
- **不替用户写原稿**：可以提意见、给判断，不能代笔正文。
- **不自动外发**：任何对外内容（日报、帖子、评论、邮件）必须人审后发。
- **代码提交只进 fork/base，绝不 push origin。**

### 5.2 涉及删改数据的操作协议

本方案里有一段、一段 4、二段 1 会动到已有数据。**统一按三步走**：

1. **先备份**：目标文件复制为 `<原名>.bak-YYYYMMDD-HHMMSS`；数据库先 `VACUUM INTO` 或文件级复制。
2. **先只读核对**：dry-run 输出完整清单（条目、理由、影响），人工过一遍；抽样核对不少于 10%。
3. **再动**：执行后保留 `forgot.jsonl` / 清理日志，任何删除都能追溯到"为什么删、谁确认的"。

**额外约束**：

- **敏感分节**（`#sensitive #private #no-sync`）不参与向量化、不外发、不进入任何外部检索。
- **书稿记忆**与**用户记忆**的边界不能动：清理只动"你的记忆"，绝不碰书稿正文和项目记忆。
- **遗忘先 dry-run 至少一周**，确认清单合理后再真实执行。

## 附录：校准后的四套框架事实卡

> 评审时如果对"XX 不是这么做的"有疑问，以这张卡为准。它基于论文原文、官方文档、仓库代码和 issue，不是网上二手简化说法。

### Letta（原 MemGPT）

- **结构**：memory blocks（在上下文里）+ archival memory（向量库）+ conversation search + files。**不是严格三层**。
- **工具**：旧名 `core_memory_append` 已被 `memory_insert / memory_replace / memory_rethink` 取代。
- **权限**：归档记忆对 agent **只能插、不能改删**（agent-immutable），开发者才能经 SDK 改删；官方提供 read_only 块，理由是防破坏性修改。
- **内心独白**：已退为**可选参数**，不再是核心循环。
- **后台整理**：官方用 sleep-time / reflection subagent 在后台整理记忆——等于承认让主对话模型顺手整理不够。
- **出处类型**：官方文档 + 仓库代码。

### HippoRAG

- **做法**：OpenIE 抽三元组建图 + 查询侧 NER + 个性化 PageRank。
- **代价**：每个 passage **两次 LLM 抽取调用**；v1 在 MuSiQue 上 11,656 个 passage 建出 **91,729 个唯一节点（约 8 倍膨胀）**。
- **删除/更新**：**没有原生能力**；2026 年 Lightfoot 那篇论文专门补这个洞。
- **错误来源**：v1 为 NER 48% / OpenIE 28% / PPR 24%；v2 有 26% 失败样本在三元组过滤后找不到支撑段落。
- **出处类型**：论文（v1 / v2）+ 仓库代码 + 后续论文。

### Mem0

- **做法**：ADD / UPDATE / DELETE / NOOP 四选一 + 向量召回 top-10 旧记忆给 LLM 判断。
- **评测不可信**：自报 66.88，同一张表里 full-context 是 **72.90（更高）**；只测 10 段对话、排除对抗类问题；issue #3944 独立复跑 LLM 分约 **0.20**（用了"当前是 2026 年"而非 LoCoMo 时间戳）；竞品 Zep 复跑称其把对手实现错了。
- **存储**："向量 + 图 + KV 三件套"是营销口径；开源版默认 **Qdrant + SQLite，Neo4j 可选**；Mem0g 只比 Mem0 高约 **2%**。
- **出处类型**：论文 + 仓库代码 + issue #3944 + 竞品复跑。

### Generative Agents（斯坦福小镇）

- **检索权重**：论文写 1:1:1，**代码实际是 [0.5, 3, 2]**。
- **衰减**：论文 0.995，**代码 0.99**。
- **反思触发**：累积重要度到 **150**。
- **反思产物**：thought 节点写回 memory stream，带 poignancy、embedding、**evidence 节点 id**、**30 天过期**。
- **已知问题**：论文自报常见错误是"检索不到相关记忆""添油加醋编造细节"、继承 LLM 正式语气；453 条回答里 **1.3% 是 hallucinated**；**反思可递归读旧反思，错误会被层层放大**。
- **出处类型**：论文 + 仓库代码。

### 安全（AgentPoison）

- **结论**：**不到 0.1% 的毒化记忆**，可把记忆型 agent 的攻击成功率推到 **80% 以上**。
- **对本方案的含义**：这是"写入权不放开"的核心依据。
- **出处类型**：论文。
