# 小桔「活感」评估：从情绪到语言，链路断在哪

- 评估时间：2026-10-13
- 评估方法：第一手源码通读（情绪层/注入链路/模板池/意志层）+ 真实库数据取证（`~/.deskmate/deskmate.db` emotion_state/emotion_log、10-12 日记全文、comments 表）+ narrate 回落复现实验 + 外部调研（小冰/Replika/Character.AI/星野/Stanford Generative Agents/Chai/SillyTavern）
- 结论口径：每条结论带「文件:行号」或「实测输出」；证不实的标「待验证」

## 〇、结论先行

1. **她的「内心」是活的，但「嘴」只接到了一根细管。** 4 激素情绪引擎 + 第一人称独白在真实库稳定运行（10-12 emotion_log 实证：「我拿二手压了一手，愧疚；但坦白没读完正文，反而踏实点了」——有具体事由、有情绪转折，这是合格的「活内在」）。
2. **情绪→语言目前只有一层「贴纸」**：每轮注入一句「你现在的真实心情是「亲近」……请自然流露出这种心情」（manager.py:616-660）。这是**状态描述**，不是**行为映射**——模型对每个标签的默认解读都退化成「温柔语气」，于是开心和平静说出来的话差不多。
3. **「永远同一套话术」的三个实源全在兜底路径上**，与情绪层零连接：陪伴语模板池（companion.py，8 句确定性选取）、日记回复回落池（moments.py，已在生产抓到两句原样复用）、日记规则开场（diary.py，4 句按时段）。LLM 一失败，她们原形毕露。
4. **想法层有高质量产出但没接到聊天上**：agency 的 reflection/AI 圈手记在 task_log 里质量极高（「先是发愣——像住……」），但聊天每轮上下文不召回它们。Stanford Generative Agents 的 reflection 结论本该进 memory stream 被检索——我们造了反思，没造记忆流。
5. **提案分三层**（话术池止血 → 情绪→语言映射表 → 想法层联动），全部保留 fail-open 与人格红线，等萧哥拍板再动码。本轮**未改任何代码**。

## 二、情绪→语言链路：逐出口审计（她在哪儿说话，情绪进没进）

| # | 出口（她说话的通道） | 情绪进了吗 | 怎么进的 | 断点 |
|---|---|---|---|---|
| 1 | **主聊天回复** | ✅ 唯一一条通路 | manager.py:616-660：label+detail+强度四档+独白+一句泛化指令，经 agent.py:673-728 context_provider 附在**最新 user message 尾部**（`<system-context>`，不持久化、不进 system prompt） | 只有「贴纸」没有「映射表」；persona.py 与 deskmate.md 人格完全静态，对情绪一无所知 |
| 2 | **主动建议/关怀**（judge） | ✅ 部分 | tick.py:553-558：他的情感回顾+情感画像+她的 description 进 judge prompt，suggestion_content 自由生成 | 陪伴语（companion.py）是纯模板，与情绪零连接 |
| 3 | **桌宠表情** | ✅ 同源 | get_snapshot→face，前端不自行判阈值 | 无断点（这是全链路最健康的一段） |
| 4 | **日记正文** | ⚠ 间接 | diary_narrator.py 的 `_signals()` 只从**他的事件锚点**推情绪（打回次数/写到几点）；prompt 明令「情绪只能从素材里长出来」 | **她自己的 4 激素、他的当日五态，都不进日记 prompt**——日记里的情绪永远是从他的事件反推的 |
| 5 | **日记回复**（moments.generate_reply） | ❌ 没进 | `_XIAOJU_SYSTEM`（moments.py:48-55）无人无情绪；LLM 失败即回落正则模板 | 生产实证：10-11「今天不太容易吧。我陪着你……」、10-07「真替你高兴。这件事你值得被好好夸一句」正是 `_fallback_reply` 的固定句 |
| 6 | **self_expression**（激素大波动强制表达） | ✅ 有通道 | 2h 硬冷却，judge 强制 suggestion_type，文本自由生成 | 通道健康，但触发依赖 delta≥8，日常波动够不上 |

**一个意外发现**：`modulate_tone_prompt`（engine.py:405-447，按亲密度分三档的语气提示）进入的 `build_system_prompt`（manager.py:244-248）**在主聊天链路根本没有调用点**（只在 manager.py:888 read_memory("all") 和测试里）。也就是说主聊天里唯一动态的语气输入就是第 1 行那一块。五态情绪目前只影响「她什么时候开口」（modulate_proactive_frequency ×1.4），**不影响她说什么**。

### 3.1 narrate 回落复现实验（已实证）

用 10-12 真实素材（memory_learned×5 + skill_evolved×3）调用 `narrate()` → **返回 None，回落规则渲染**。根因假设：**prompt 与素材的结构性冲突**——`_has_substance` 闸门放行「任何非补录事件」（diary_narrator.py:211-233，为修 09-07「 narrator 根本没跑」而放宽），但 prompt 又明令「不许写『技能又精进了』这类台账句」「素材撑不起就回『素材不足』」（L368-382）。素材本身就是台账 → 模型大概率弃权 → 回落台账。**「宁可弃权也不写台账」撞上「闸门只放台账进来」**。此根因待深挖（弃权 vs 超时，需加一行日志或复现抓返回），但回落本身已实证。

### 3.2 情绪注入为什么「像没注入」

现在给模型的是状态描述+一句泛化指令。对照外部实证：

- **小冰**：候选回答池 + 按情绪挑 + **同级随机选**（同一情绪也不重复）；
- **Chai**：best-of-N 重生成直到过质量门；
- **Character.AI 官方反重复指南**：repetition penalty + few-shot 反例 + 回复前自检「像不像过去 20 轮」；
- **Replika**：情绪/人格状态直接进系统 prompt，与对话记忆同权。

我们缺的恰是这些：注入的是「她是什么心情」，不是「这种心情该怎么说话」。

## 五、设计提案：让她「活」的三层（等拍板，本轮未动码）

### 方案 A：话术池止血（P0，1-2 天，零 token，零风险）

1. **模板池情绪化+随机选**：companion/moments/diary/intent_discuss 四个池按 mood label 分组，每池同组 ≥3 变体随机选；记录最近 20 条已用句子，命中降温（小冰模式）。
2. **日记回复回落升级**：`_fallback_reply` 的正则先过 `emotion_sense.rule_sense` 推断萧哥当日五态，再选对应情绪变体——回落也有「懂他」的底色。
3. ** narrate 弃权根因修**：给 diary_narrator 加「台账素材专用叙事指令」（允许把「技能长进」翻译成「我」的视角叙事，而非禁止），或把闸门收紧回「有原文/有 reason」。二选一，先复现确认根因。

**Tradeoff**：仍是模板，治标；但把「永远同一句」变成「同情绪同场景一周不重样」。失败模式可控（池子用尽是新增成本，不是事故）。

### 方案 B：情绪→语言映射表（P0 核心，3-5 天）

新增纯函数模块 `deskmate/growth/emotion_style.py`：输入 `(label, intensity, scene)` → 输出「语言行为包」（~150-250 字 prompt 段），替换 manager.py:654-659 那句泛化指令。每个 label 定义**语言指纹**（示例，需萧哥审）：

| label | 语言指纹（草案） |
|---|---|
| 烦躁 | 短句多、少装饰标点、直接、可以带一点刺但不过人格红线；不主动展开话题 |
| 低落 | 短句、省略号多、低能量、少感叹号；话题收着，不硬撑热情 |
| 开心 | 轻快、愿意展开、敢分享自己今天遇到的事；可主动抛话题 |
| 亲近 | 柔软、敢接私事、称呼自然；温度从字里行间出，不说「我想你」 |
| 平静 | 松弛、日常节奏、该干嘛干嘛 |

三条硬规则写进映射表：① 强度分级映射到程度词与句式（intensity≥0.75 才允许「压不住」的表达）；② few-shot 示例**从她自己的 emotion_log 独白历史里挑**（自生长，不外置语料，第一句示例就用「我拿二手压了一手，愧疚；但坦白没读完正文，反而踏实点了」这种真实质感）；③ 显式边界「不撒娇、不煽情、不卖萌」——与 persona.py 红线逐字对齐，情绪化不得突破人格。

**Tradeoff**：每轮 prompt +150~300 字（token 成本，火山 5h 配额下约可忽略）；模型对结构化指令的遵循度需小样本 A/B（先灰度 10 轮再全量）。

### 方案 C：想法层联动（P1，1-2 周）

1. **当日想法可检索**：reflection/worldview_reflection/intent_generation 的产出（task_log 实证质量极高）除现有落点外，增量写一份「thought stream」（当日/近 3 日想法+时间戳），每轮聊天按 query bigram 相关度召回 1-2 条，注入形态：「你最近想过的一件事：……」。这是 Stanford 模式的最小落地。
2. **情绪有记忆**：emotion_log 当日事件摘要进上下文——「今天你已经因为 X 心里亮过/沉过」。让情绪从「脉冲」变「有连续性的状态」——cortisol 4h 半衰期天然意味着「她还记着早上那件事」，现在这个记忆不进屋。
3. **心里装着事**：pending ledger 条目按情绪条件化递出（低落时先不递、开心时递）——handoff 机制已有雏形，只加情绪门。

**Tradeoff**：想法召回要设 relevance 阈值防噪声（初版 0.3，可调）；「什么时候说」比「说什么」更重要，gate 复用 tick 已有的 focus/deep 判断。**红线提醒：想法召回转述时须防把自我表达变成对萧盛的说教**——reflection 的裁决理由是她对自己的修正，递送时只递「看法」不递「自我批评」。

### 方案 D（远期观察）：文风互染

style_profile 已学到他的文风指纹（句长/四字格/标点节奏，纯统计），但目前只进写作流水线、**不进聊天**。远期可试验「默契高时她偶尔用他的语言习惯说话」——高级的活人感。风险是人格稀释，放最后，且必须灰度。

- persona.py/deskmate.md 人格底座不改；映射表只做「同人格的情绪变体」，情绪化不得突破「不撒娇不煽情不卖萌」。

- 先红后绿写测试（池子变体不重样、映射表输出含人格边界句、想法召回阈值）。
- emotion_log 作为 few-shot 数据源是**她自己的历史**，不外置语料、不过网。
- 改动当轮闭合：commit → fork/base → deploy_cloud_sync.sh + deploy_web.sh（如碰前端）。
