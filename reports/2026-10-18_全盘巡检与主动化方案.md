## 一、一句话结论

**小桔的「机器」已经很厚（台账、情绪、认知、日记、感知、主动管道一应俱全），但「嘴巴」很窄。** 大量主动产出被层层闸门压住，真正能递到用户面前的极少。

所以「更主动」不是再加一层记忆，而是**把已有产出的递送闸门重新设计**——让她敢开口、开得对、不烦人。

## 二、真实 bug / 死代码（带证据）

### 🔴 1. 首页主动开场白链路已断，`getDeskmateHandoff` 是死代码

- `surfaces/gui/src/api.ts:4144` 定义了 `getDeskmateHandoff()`，**全仓无任何组件 import**（grep 只命中定义处）。
- 它在 `ad873de`「接前端开聊挂载点」时曾挂进 `DeskHome.tsx`，后在 `097ef28`「首页减负」被摘掉。
- **连带断链**：
  - `build_handoff_opening()` 里标记 `delivered_at` 的逻辑（`deskmate/proactivity/ledger.py:806-815`）在首页路径永不触发；
  - `render_delivered_context()`（`deskmate/memory/manager.py:700`）取不到「今天已递待办」；
  - 层一「她递出的卡片接得住」在**首页场景**失效。
  - 只剩活跃会话的 inline 相关性路径（`POST /handoff` + `DeskMateProactiveInline`）能标 `delivered_at`。
- **影响**：用户开新会话时，她**不会**主动递出昨晚/手机端产出的事——而这正是萧哥点名的核心场景。

### 🔴 2. `writing` 生产者硬编码单一书稿

- `deskmate/proactivity/health_producers.py:461-464` 写死：

      "~/Documents/已出版/20.国子监秘闻录/国子监秘闻录.docx"

- 换书、多书并行、或稿子移位置 → 静默不报（`if not p.is_file(): return []`）。
- 萧哥是历史小说作者，多书是常态。

### 🔴 3. 认知层默认关，导致「它眼中的我」决策栏永远空

- **后果**：决策偏好、行为规律两栏**永远为空**，除非手动开分身。这是 8-30 审计就发现、至今未动的断链。

## 四、让它「更主动」的方案（核心）

### 4.1 核心矛盾

产出侧很丰富（`proactive_ledger` 有 `automation` / `sync_health` / `writing` / `cloud_audit` / `mobile_voice` 五类生产者），但递送侧被**五道闸**叠压：

```
DAILY_DELIVERY_CAP=3  →  understanding 门（空不递）  →  情绪门（低落不递）
   →  OPS_MAILBOX_ONLY（运维只进信箱）  →  bigram 相关性（零重叠不递）
```

结果：**她盯出来的事，九成躺在台账里，用户看不到。**

### 4.2 建议的 8 条改动（按性价比排序）

**① 恢复「开聊即递」，但让她先开口（最高优先）**
- 把 `GET /v1/deskmate/proactive/handoff` 接回 `DeskHome`（或做成她主动 append 一条助手消息）。
- 基础设施**已存在**：`coworker/server/app.py:4551-4559` 的 `append_session_messages` + `broadcast_session` 就是「她先说话」的通道，目前只挂在「聊这个」按钮后。**去掉按钮门槛即可。**
- 关键：不是弹卡片等用户点，而是**她真的说一句**，用户顺着接。

**② 分级打扰，取代固定日上限**
- 把 `DAILY_DELIVERY_CAP=3` 改成按 `trust` / `活力` / `focus` 动态：高价值（伏笔未收、停笔超 3 天、情绪事件）不受限；低价值才吃额度。
- 已有 `modulate_proactive_threshold` / `modulate_proactive_frequency`（`app.py:2722-2752`），接上即可。

**③ 手机端开 app 时递一次（不做后台轮询）**
- 手机端冷启动拉一次 `handoff`，把昨晚的产出带理解递出。符合 D8「不轮询」决策，又补上跨端主动。

**④ 认知层默认开**
- `alter_ego` 的决策偏好/行为规律值得默认注入（至少情感 + 认知都开），否则「它眼中的我」永远半空。

**⑤ 写作生产者泛化**
- 从 `novel_index` / 圣经读「当前活跃稿」，支持多书；不再硬编码一个 docx。

**⑥ 默认装 `deskmate-embed`**
- 让「聊到某主题才递」真正语义化，而不是 bigram 猜。

**⑦ 主动「记住」回流闭环**
- 手机端「记住这个」→ `mobile_voice` → 开聊时她带自己的理解递出（`understanding.py:57` 已为 mobile_voice 写了专门口吻）。设计已有，确认 UI 落地即可。

**⑧ 防 nag 可解释**
- 每条主动产出附「我为什么现在提这个」；用户能一键「以后别提这类」→ 进 `DisturbManager` 黑名单。让她「敢提」也有「刹车」。
