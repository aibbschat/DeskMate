## 三、数据模型（新增，明文，不同步）

```sql
CREATE TABLE IF NOT EXISTS emotion_state (
  key         TEXT PRIMARY KEY,   -- 固定 'self'（单行，小桔自己的情绪状态）
  dopamine    REAL NOT NULL,     -- 0~100
  serotonin   REAL NOT NULL,     -- 0~100
  oxytocin    REAL NOT NULL,     -- 0~100
  cortisol    REAL NOT NULL,     -- 0~100
  description TEXT NOT NULL,     -- 自然语言情绪描述（注入上下文用）
  updated_at  TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS emotion_log (
  id              TEXT PRIMARY KEY,
  ts              TEXT NOT NULL,
  source          TEXT NOT NULL,  -- chat | time_decay | circadian | proactive
  deltas          TEXT NOT NULL,  -- JSON: {"dopamine": 5, "serotonin": -2, ...}
  description     TEXT NOT NULL,
  conversation_id TEXT           -- 可空
);
```
- 纯数值 + 文本，无向量列 → 天然满足「不同步」红线（不注册 `SYNC_TABLES`）。
- 单行 `emotion_state`：所有变更走**单原子事务 + 模块级锁**（见 §六 P1-2 落实），杜绝读-改-写竞态。
- 新增即纯增益：表空 / `DESKMATE_EMOTION_ENGINE=0` → 全链路退回今天口径，**零破坏**。

- **`EmotionEngine` 类**：
  - `_lock = threading.Lock()`：所有 `emotion_state` 读-改-写串行化（P1-2）。
  - `get_state() -> dict`：读单行；空 → 用基线 + 默认描述初始化（oxytocin 首值 = `max(intimacy, 40)` if `intimacy>0` 否则 40，见 P0-2）。

## 五、更新/衰减机制伪码（核心）

```python
# —— 对话后（异步线程）——
def update_after_turn(self, u, a, interval, now):
    if not self.enabled: return
    try:
        s = self.get_state()
        prompt = build_emotion_prompt(s, u, a, interval, hour=now.hour)  # 昼夜仅作特征
        out = llm_deepseek(prompt)          # fail-open：异常 → 保持原值
        nd = clamp4(out.values, s, MAX_DELTA)
        desc = out.description
        with self._lock:
            self._atomic_write_state(nd, desc, now)   # 单事务写单行
            self._append_log('chat', delta_dict(s, nd), desc, conv_id)
    except Exception as e:
        logger.warning("emotion update skipped: %s", e)

# —— 每 5min（tick）——
def decay_step(self, now):
    with self._lock:
        s = self.get_state()
        nd = exponential_decay_toward_base(s, now, RATES, extra_oxytocin_by_interval)
        self._atomic_write_state(nd, s['description'], now)
        self._append_log('time_decay', delta_dict(s, nd), "", None)
```

## 六、安全与红线（落实 §9.7 + §9.9 待修订）

- **【P0-1 红线】mood 不碰**：`GrowthState.mood` 仍由 `engine.set_mood_from_emotion()`（L1116）独占结算作「当日心情」展示；本模块 4 激素是更细内在动力学，**任何代码不得写 `mood`**。已在 §二「不做」钉死。
- **【P0-2】oxytocin 口径**：首值 `seed = max(intimacy, 40)`（intimacy>0 取较大者，默认 0→40），之后独立变量按自身速率衰减，**不与 `intimacy` 混写**（避免与 `_gain_relation()` L465 事件驱动逻辑打架，P0-3 已确认无交叉写路径）。
- **【P1-1】昼夜节律**：当前小时仅作为**特征**传入 LLM 提示，由 LLM 决定对血清素等的影响；**代码不得硬编码「深夜→血清素-X」**（守住「LLM 驱动不硬编码」原则）。
- **【P1-2】并发竞态**：单行 `emotion_state` 所有读-改-写串行于 `self._lock` 之后、以**单原子事务**写回；tick 与对话更新同进程串行，杜绝后到覆盖先到丢 delta（项目红线：多入口写同文件须锁）。
- **【P1-3】成本口径统一**：触发＝「5 分钟冷却 + 有情感内容才触发（~30% 轮次）」，与设计 §9.4 成本表一致；即便每轮触发，日均仍 <¥0.01，可忽略。
- **【P1-4】after-turn 挂载**：用既有 `_save_session_turn`（L2746，已异步）作挂载点，不新造 hook。
- **【P2-1】对比表失真**：设计 §9.3 对比表 `agent-vibes` 行已加 ⚠️ 脚注（公开版为 TTS 工具非 VAD 框架），非承重，施工不依赖该出处；MindPaw / Project Riley 亦未单独联网核实，仅作选 Yoji 的旁证。
- **全部 fail-open**：LLM 失败 → 跳过本次更新保持原值；建表/读状态异常 → 退回无情绪段；`DESKMATE_EMOTION_ENGINE=0` → 关 LLM 更新仅衰减。
- **神圣稿件守卫**：情绪引擎只读对话文本、不读原稿，沿用既有 `guarded_*` 守卫。
- **可回退**：删两表 + `DESKMATE_EMOTION_ENGINE=0` → 完全退回今天口径（零破坏）。

## 八、验收判据（来自设计 §9.8 + 实证补充）

1. 一次对话后，`emotion_log` 有记录，delta 有原因，`description` 自然语言可读；
2. 长时间不对话后，dopamine/oxytocin**真的在衰减**（查 `emotion_state` 数值）；
3. 注入上下文后，对话中能感受到她的状态（「今晚有点安静」之类，不是报数字），且**不会把她的情绪当成对你的关怀**；
4. 主动 tick 中，情绪状态**真的影响了判断/主动表达**（低落时少打扰、开心时多分享、自己郁闷时冒一句「小桔的心情」）；
5. 你能在 UI 上看到她的「天气」并觉得「这像她」；
6. 关 `DESKMATE_EMOTION_ENGINE` → 退回纯衰减/无情绪段，系统不崩、结构兼容。
