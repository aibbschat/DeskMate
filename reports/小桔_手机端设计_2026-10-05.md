## 〇、一页速览（TL;DR）

- **手机不可用与「上云」「同步」无关**。云这一侧反而是好消息：Caddy 同源反代把静态页、`/v1/*`、`/ws/*` 全收在 `xj.aibbs.chat` 一个源上，token 由同源 `runtime-config.json` 在运行时注入（`surfaces/gui/index.html:39-60`），**手机打开就能拿到凭据，不需要为手机重做任何登录**。
- 真正的原因只有一个：**这套 GUI 从结构上是桌面壳**。硬网格 `264px 侧栏 + 1fr`、右栏固定 `332px`、`height:100vh`、大量交互挂在 hover 与 ⌘ 快捷键上、全库只有 6 个 `@media` 且几乎全是 `min-width`（详见 §一，逐条带行号）。390px 宽的屏上，两个固定栏相加 596px，正文被挤成约 126px。
- 所以手机端**不需要重写后端，也不需要新端点**（第一批零后端改动），需要的是：一个窄屏外壳 + 一套拇指优先的信息架构 + 一条能装进主屏的入口。
- 落地方式：新增第二个构建入口 `mobile.html` + `src/mobile/`，**原样 import 现有的 `api.ts` / `types.ts` / `Transcript.tsx` / `Markdown.tsx` / `Emote`**，只重写 `Composer`（桌面 chrome 占七成）和花园的展示层（yard 全景 SVG 不搬）。桌面 `index.html` 与 `App.tsx`、`styles.css` 一行不动。
- 一次 `npm run build` 同时出两端产物，`scripts/deploy_web.sh` 原样可用 —— 守住 `docs/DEPLOY-PARITY.md` 的铁律（只构建一次、本地与云端同一份字节）。
- **上云给手机端带来的真价值**：手机连的是云端副本，手机上产生的记忆/日记写入 B 层 → 被 oplog 捕获 → 回灌 Mac（阶段 1/2/6 闭环已在 2026-10-05 验收）。**但逐字稿不在同步范围内**（`chat.db` 本期不动），这条边界要写清，见 §1.4 与待拍板 D4。
- 7 个待拍板决策点集中在 §九，每个都给了我的建议和代价。

## 一、成因定位：手机上为什么不能用（逐条带证据）

### 1.1 布局是硬网格，不是流式

| 症状 | 代码证据 | 手机（390px）上的实际表现 |
|---|---|---|
| 侧栏固定 264px | `styles.css:499` `.app { grid-template-columns: 264px 1fr }` | 正文只剩约 126px，中文一行放不下 7 个字 |
| 右栏固定 332px | `styles.css:628` `.main.rail-open .main-topbar { right: 332px }`、`:675` `.main-chat { margin-right: 332px }`、`:50` `--artifact-rail-w` | 一旦打开附件/检查器栏，两栏相加 596px > 屏宽，内容被推出屏外 |
| 用 `100vh` | `styles.css:501` `.app { height: 100vh; overflow: hidden }` | iOS Safari 动态地址栏吃掉约 90px；键盘弹起时输入框被顶到屏幕外且回不来 |
| 没有面向窄屏的断点 | 全库 `@media` 仅 6 处：`styles.css:1834`、`:2631`（reduced-motion）、`:3415`、`:3420`、`:3438`（都是 `min-width:768/1024`）、`:4202`（`max-width:1080`，只调 padding） | 手机视口 390px 一个断点都不命中，等于拿到 1080px+ 的桌面版式 |
| 正文内边距按桌面给 | `styles.css:676` `.main-scroll { padding: 24px 8% 24px }` | 窄屏上两侧各 8% 是浪费，实际可读宽更窄 |
| 控件尺寸按鼠标给 | `styles.css:657` `.topbar-icon-btn { width:30px; height:30px }` | 低于 44×44 的触摸目标下限，误触率高 |

### 1.2 交互挂在 hover 和快捷键上

- `styles.css:535` `.nav-hover-zone`：左边缘 **14px 宽的悬停热区**用来唤出折叠导航 —— 手指没有 hover，这个入口在手机上等于不存在。
- `styles.css:519-531` `.nav-collapsed` / `.nav-peek`：折叠导航靠 `:hover` 浮出，且注释里写明是为「cursor」设计的。
- 顶栏折叠簇（`⌘B`、hover 才显的 pin/重命名/归档）同样是鼠标语义。
- 花园花丛的提示是 hover-only：`components/garden/GardenFlowers.tsx`。
- 桌面 `Composer.tsx:16-24` 引入 `../tauri`（听写、原生文件选择）、`:578-581` 文件拖放 —— 手机没有这些输入姿势（调用点都有 `isTauri()` 守卫，不会崩，但功能为空洞）。

### 1.3 没有 PWA，也没有任何移动适配痕迹

- `surfaces/gui/public/` 下无 `manifest.webmanifest`、无 `sw.js`；`index.html:5` 有正确的 `viewport` meta（唯一做对的一条），但没有 `viewport-fit=cover`、没有 `apple-touch-icon`。
- 全库 `src/` 内 `matchMedia` 只出现在 `src/theme.ts`（读 `prefers-color-scheme`）；没有 `maxTouchPoints`、`pointer: coarse`、`isMobile`、任何 touch 事件处理。
- 结论：手机现在只能用 Safari 标签页打开一个为 1440px 设计的界面，且每次都在地址栏下面工作。

### 1.4 一处必须诚实说明的边界（避免手机端承诺过度）

手机端对话打到的是**云端副本**。她的记忆、画像、日记（B 层）会通过 oplog 回灌 Mac —— 这条链路 2026-10-05 已实测闭合。但**聊天逐字稿本身不在同步范围**：会话存储在 `ConversationStore` / `chat.db`（`coworker/server/manager.py:212`、`:295`），架构稿阶段 2 明确记录「`chat.db` 本期不动」。

> 所以对用户的正确说法是：**「在手机上跟她聊过的内容，她回到你 Mac 上还记得（作为记忆），但 Mac 的会话列表里不会凭空长出这段聊天记录。」**

不要把这个说成 bug，也不要在手机端文案里暗示"两端聊天记录同步"。是否把 `chat.db` 纳入同步范围 → 待拍板 **D4**（本质是架构稿的下一期，不是手机端的工作量）。

## 二、载体选择（含被否掉的路，留决策痕）

| 路线 | 结论 | 理由 |
|---|---|---|
| **独立手机端（新第二入口，复用 api/组件）** | ✅ **采用** | 桌面端是你每天在用的主战场，风险必须隔离在外；手机的拇指优先信息架构（两屏 + 底部 tab）与桌面的多栏工作台式 IA 本来就不该是同一套壳；能原样复用 `api.ts` 与 `Transcript.tsx`，重复的只有外壳 |
| 把现有 GUI 改成响应式 | ❌ 否 | 要动 `styles.css` 5637 行 + `App.tsx` 2138 行，`.app` 硬网格、`.main-topbar` absolute、`.nav-hover-zone` 等桌面语义全得改；桌面回归面太大，收益不抵风险 |
| Tauri Mobile 打包原生 App | ❌ 否（第一批） | 要 Xcode/签名/分发，工程最大；而且 §一的布局问题一个都躲不掉，仍得先做 Web 层窄屏版。等手机端两屏跑顺、确认真有「非原生不可」的需求（系统推送、离线）再议 |

代价明说：独立手机端意味着**两端各自维护一份壳**，将来新增屏幕要考虑两处；第一批只覆盖 2 屏，其余视图（收件箱独立屏、定时任务、创作流水线、圆桌、技能商店、集成、审计）在手机上**不出现**（见 §四「明确不做」）。

## 三、手机端必须原样复刻的 7 条契约

这几条是手机端的"物理定律"，写错了不会报错、只会表现为"页面能开但聊天不回话"。**直接复用 `src/api.ts` 就自动满足前 3 条**，不要自己拼 fetch。

| # | 契约 | 出处 | 手机侧做法 |
|---|---|---|---|
| 1 | token 三源解析：`window.__COWORKER_API_TOKEN__` → 同源 `runtime-config.json` → 构建期 dev token → 空串 | `api.ts:57-60` | 复用 `api.ts` 即得。手机端页同样要在 HTML 里跑那段 `fetch("runtime-config.json")` 引导脚本（与 `index.html:39-60` 同一段） |
| 2 | 所有 REST 带请求头 `X-OpenWorker-Token` | `api.ts:64-72`（模块内自建 `fetch` 包装） | 复用即得。**禁止**把 token 放进 URL query 或 localStorage |
| 3 | WS 鉴权＝**子协议对** `new WebSocket(url, ["openworker", token])`；服务端 `accept()` 前校验，不过就 `close(1008)` | `api.ts:74-79`；`coworker/server/app.py:294-302`、`:5158-5167` | 复用即得。手机 4G 上 1008 与网络故障要区分提示（"连不上她的服务器" vs "凭据不对"） |
| 4 | `session_id` 由**客户端**铸造（`crypto.randomUUID().slice(0,12)`），服务端在 `turn_start` 才懒落库 | `App.tsx:119-121`；`app.py:5611-5620` | 手机冷启动**先** `GET /v1/sessions`（`app.py:946`）挑最近一条 deskmate 会话续聊，只有列表为空才新建。否则每次开 App 都会在 Recents 里长出一条空会话 |
| 5 | 发消息**只有 WS 帧**，无 REST 兜底：`{type:"user_message", text, model?, attachments?, skill?}` | `api.ts:2476-2486`（`Session.userMessage`） | **手机端不写重连，复用同一个 `Session` 类。** 本稿初稿写的「手机端必须自写重连」已过期：`98dbc08` 给 `Session` 补上了 **25s 保活 ping + 指数退避重连（500ms 起 ×2、封顶 15s）+ CLOSED/CLOSING 时消息入 outbox + 主动 `close()` 清定时器不留幽灵 socket**，并由 `src/sessionReconnect.test.ts` 5 条用例锁住不变量；配套后端 `96e4ead` 让 `/ws/session` 认 `{"type":"ping"}` 并回 pong。手机端只要 `import { Session }` 就自动继承这套（另写＝两端行为漂移的雷）。<br/>**新增契约**：心跳帧就是 `{"type":"ping"}`，手机端复用同一条，别自造 keepalive 字段。 |
| 6 | 事件流以 `turn_done` 为「这轮真结束」的权威信号；事件类型 20+ 种 | 类型联合 `src/types.ts:1-28`；消费分支 `App.tsx:702-949`；服务端枚举 `coworker/events.py:14-44` | 手机端 switch **必须带 default 忽略未知事件**：服务端实际还会发 `tool_requested`、`team_proposed`、`items_proposed`，这三个**不在 `types.ts` 联合里**，遇到未识别事件不能崩 |
| 7 | 审批有**纯 REST 通道**，不需要常驻 socket：`GET /v1/inbox?session_id=&state=` + `POST /v1/inbox/{item_id}/resolve {resolution}` | `app.py:453-495`；条目形状 `coworker/inbox.py:63-93`；幂等 + 先到先得 + 能唤醒重启孤儿轮 `manager.py:1209-1220` | 手机端主用这条：切回前台拉一次 inbox 即可。`ApprovalDecision` 枚举 `once\|deny\|always_tool\|always_command\|always_domain\|always_task\|readonly_session`（`types.ts:41-48`）—— 手机上只暴露 `once / deny / always_task`，`always_*` 大范围放行别在手机上顺手点 |

补充两条现网约束：

- **WS Origin 门禁**：`app.py` 在 accept 前校验 Origin，白名单原本只有 tauri/localhost。云端部署清单阶段 5.5 已处理（方案 A 加 `COWORKER_EXTRA_ORIGINS` 或方案 B 在 Caddy 里 `header_up Origin`）。手机端与桌面浏览器同源，**不新增此项工作**，但 M0 骨架页要把「WS 是否 101」做成可见状态，避免将来排查时和手机端代码混在一起。
- **会话内速率限制**：`app.py:5901-5911` 对入站帧限流；手机端 outbox 重连后一次性补发多条时要退避，别硬怼。

### 4.1 对话屏（默认落地屏）

- **正文复用 `Transcript.tsx`**（原样 import）。它的 props 是纯数据（`items/onApprove/running/streamingText/onRetry/onAllowAnyway/onUndoMemory`，见 `Transcript.tsx:389-409`），依赖链里没有 Tauri、没有 three、没有 pdfjs/xlsx —— 判定见 §五。
- 窄屏版式覆写（写在**新的** `src/mobile/mobile.css`，不改 `styles.css`）：消息内边距 `24px 8%` → `12px`；气泡最大宽 86vw；正文 15px（iOS 上 <16px 的输入框聚焦会强制放大整页，输入框另按 §六.6）；代码块/表格横向滚动且**不撑破屏宽**。
- **输入区自写 `MobileComposer`**，只保留：单行自增高 textarea（上限 6 行）、相册图片→`attachments[{kind:"image",data_url}]`、发送。砍掉：模型/模式下拉、`ProjectBindMenu`、`EmotePicker`、usage 胶囊、桌面附件菜单。**契约只有一个**：`onSend(text, attachments?)` → 拼成 §三.5 那个 WS 帧。
- **审批**：不新开屏。顶栏一条「⚑ N 件在等你点头」，点开是抽屉，按钮走 §三.7 的 REST。这是手机端最值钱的能力 —— 她在跑任务、你在外面，你能点一下。
- **主动性（她主动找你说话）**：桌面是客户端轮询 `POST /v1/deskmate/proactive/tick`（`useProactiveTick.ts:41-76`，最小 15s 间隔 + 5min 慢心跳）。手机端**不做前台常驻轮询**（费电且移动网络下常失败），改为「切到前台时拉一次」，结果仍是 `window` 自定义事件 `deskmate:suggestion`（它不是 transcript `Item`，要自己渲染成一条可点开的提示）。真正的推送留到第二批（见 D2/§七.7）。
- **emote 语法必须保留**：`![alt](emote:NAME)` 在 `Markdown.tsx:32-48,154` 被拦截渲染，`Transcript.tsx:20-30` 还会裁剪半截 token。手机端复用 `Markdown.tsx` + `emotes/`，不要另写一套。
- **artifact / board 芯片**：`Markdown.tsx:11,15` 发 `ocw-open-artifact` / `ocw-open-board` 窗口事件，桌面唯一消费者是 `RightRail.tsx`（那是 pdfjs/xlsx 重模块，`RightRail.tsx:3,518,568`）。手机端第一批**拦住这两个事件，渲染成「这份成果在桌面上打开看」的只读提示**，不做预览、不引入 pdfjs/xlsx。

### 4.2 花园屏（个人中心）

现有 `GardenProfileCenter.tsx`（179 行）有两种形态：`yard` 全景（`:75-148`，重 SVG 场景 + hover-only 花丛提示）和 rooms（`:154-178`）。**全景不搬**：在 390px 上把装饰性 SVG 缩到能看，是一次负优化（信息密度掉光、还费渲染）。手机端把它降级成**「门的清单」**——一屏 5 行可点：

| 手机端行名 | 目标端点（现网已验证，全部只读，除日记写口） | 数据落到的表 |
|---|---|---|
| 📖 日记（默认展开） | `GET /v1/deskmate/moments?limit=50`、`POST /moments/post`、`/moments/comment`、`/moments/{id}/love`、`/moments/{id}/archive` | `user_posts` + `comments`（阶段 6 已进同步） |
| 👁 它眼中的我 | `GET /v1/deskmate/alter-ego`（画像分节 `sections[].articles[]`） | 认知层 |
| ⌗ 长期记忆 | `GET /v1/deskmate/learned-history?limit=200`（读 `ts,fact,category`，`learned_store.py:543`） | `learned_history` |
| ✎ 她自己的记录 | `GET /v1/deskmate/diary`、`GET /v1/deskmate/diary/{date}` | 日记文件 |
| ▦ 统计与默契 | `GET /v1/deskmate/growth`（`level`、`achievements[]`、`bond{stage,depth}`） | 成长层 |

- **手机上最该第一眼看到的是日记时间线**：`user_posts` 的 `author ∈ {"me","xiaoju"}`（`diary_store.py:263`），本身就是时间线形态，天然适配手机；`loved_entries`（🩷）没有独立读口，`/moments` 只回 `loved:[moment_id]`（§七.5 记一条"不要指望在手机上列所爱心"）。
- **写口只给三个**：发日记、留言、点🩷。**不给删除** —— GUI 侧本来就没有 wired 的删除端点（`profile-item` 的 DELETE 存在但花园屏不调用），手机端不自造删除。
- **勋章墙、`/v1/deskmate/garden` 全景状态、`guestMode`、`/garden/storybook`、`lit` 点灯**：第二批再看。`guestMode` 是纯客户端开关（`GardenProfileCenter.tsx:82,120-135`，后端照样吐数据），手机端**不要**把它当隐私开关复用。

## 六、构建与部署落点

1. **第二入口**：新增 `surfaces/gui/mobile.html` + `src/mobile/{main.tsx,App.tsx,mobile.css}`；`vite.config.ts` 的 `build.rollupOptions.input` 加一条 `mobile`。一次 `npm run build` 同时出两端，产物仍是一个 `dist/`，**`scripts/deploy_web.sh` 一行不改**（它 tar 的就是 `dist/`，并照样写同源 `runtime-config.json`）。
2. **产物名与 `base: "./"` 的坑（已按此落地）**：入口源文件 `surfaces/gui/mobile.html`，vite 原样产出 **`dist/mobile.html`**，URL 即 `xj.aibbs.chat/mobile.html`。为什么必须留在 dist **根**：`vite.config.ts:43` 的相对 base 让资源走 `./assets/…`，若塞进 `/m/` 子目录就会解析成 `/m/assets/x.js` → 404（实测过桌面与手机端共用同一批 `assets/`，产物里 `mobile.html` 引的是 `./assets/styles-*.js` 等共享 chunk，不重复打包）。
3. **Caddy 只动一行**：加 `redir /m /mobile.html`（短链入口）。**要 `redir` 不要 `rewrite`** —— rewrite 会把地址留在 `/m/`，相对资源就又踩上一条。现有 `handle /v1/*`、`handle /ws/*`、静态兜底都不动。
4. **零新增密钥 + 自检已扩**：手机端与桌面共用同一份同源 `runtime-config.json`。`scripts/deploy_web.sh` 的部署后自检已改：token 扫描从只查 `assets/` 扩成**整个前端目录**（排除 `runtime-config.json` 本身），并新增两条断言——`mobile.html` 存在且加载 config、`m.webmanifest` + `m-icon-192.png` 可达。防的就是「只扫一半的假绿」和「手机页没随包上去」。
5. **PWA（第一批：装主屏，不装 SW）**：已落 `public/m.webmanifest`（`start_url=/mobile.html`、`scope=/`、`display=standalone`、**不注册 Service Worker**）+ 三张**不透明**图标（`scripts/gen_mobile_icons.py` 从小桔立绘重出 180/192/512，透明底在深色桌面会糊成一块）+ `theme-color` 由 `src/mobile/main.tsx` 的 MutationObserver 运行时跟随 `--accent`（换肤/切深浅色都重取，manifest 里那个只是兜底）。
   - 有意先不装 SW：这是一个自更新站点，SW 缓存会把旧版钉在用户手机上。代价明说：**没有离线兜底**（D5 已拍）。
   - 加了个合法小能力：`/mobile.html#yard` 深链直开花园（PWA 快捷方式与真机验证都用它）。
   - **有意先不注册 Service Worker**：这是一个自更新站点，SW 缓存会把旧版钉在用户手机上（我们的教训是"版本一致要钉四处"）。代价明说：**没有离线可用**；iOS 无 SW 也能"添加到主屏幕"，只是没有离线兜底。→ 待拍板 D5。
6. **尺寸与可点性契约**：外壳高度用 `100dvh`（`100lvh` 兜底 + `@supports not (height:100dvh)` 退回 `100vh`）；`padding-bottom: env(safe-area-inset-bottom)` 给输入区和底部 tab；触摸目标 ≥44×44；输入框 `font-size ≥16px`（iOS 小于 16px 聚焦会强制放大整页且不回弹）；`overscroll-behavior: contain` 防 iOS 橡皮筋与内层滚动打架。
7. **后端零改动**（第一批）：手机端只用现网已验证的读写口，不加端点、不动 `sync/`、不动 oplog。这也顺带守住架构稿的红线 —— 手机端不属于同步层，它只是云端副本的又一个客户端。

## 七、红线与隐私（手机端必须自己扛的一道）

1. **手机端只连云端，不直连 Mac**。Mac 数据靠 oplog 收敛，手机端永远不试图访问局域网里的 `127.0.0.1:8765` 语义（现网默认值就是它：`api.ts:21`）。
2. **原稿（A 类）红线**：架构稿 §6.1 规定 A 类 Mac 单写、云端只读镜像。手机端第一批**不提供任何写作目录浏览/编辑**；将来若做"手机上读稿"，必须走云端只读镜像 + 明确只读文案，且不得提供写回路径。
3. **感知原始遥测一律不上手机**：`GET/POST /v1/deskmate/perception/screen`（`app.py:3788,3804`）花园屏根本没调，手机端也不许调；剪贴板/文件/日历原始事件同样排除在任何屏之外（萧哥的公开口径：感知层原始遥测默认不上公开页）。
4. **⚠ 花园读口没有敏感过滤**：`deskmate/memory/sensitivity.py` 的 `classify()`/`redact()`（`:92-109,:125`）只作用在**写入与日志**时；`deskmate/agency/visibility_gate.py` 的家人词表与"感知来源"拦截（`:8,:40,:83`）作用在**发布到 AI 圈**的路径上。也就是说 `GET /v1/deskmate/learned-history` 与 `/moments` **原样返回全部内容**。手机是在地铁上用的设备 —— 这道过滤要么手机端展示层补（折叠可疑条目、默认模糊），要么新增带标签的读口（=一次后端改动）。→ **待拍板 D3**。
5. **不要指望手机上能列出"所有点过心的内容"**：`loved_entries` 无独立读口，`/moments` 只回 `loved:[moment_id]`。
6. **凭据姿势不变**：token 不进 bundle、不进 URL query、不进 localStorage（与桌面一致，靠运行时注入）。手机端不做"手动填服务器地址"的输入框（会把 token 带进浏览器自动填充历史）→ **待拍板 D1**。
7. **推送**：第一批不做（要 VAPID + 订阅表 + 服务器侧投递，且要碰云端 env 与 systemd）。手机上的"她主动找你"目前只能靠切前台拉一次，**这条预期必须写在界面文案之外、写在给萧哥的说明里**，别让用户以为装了主屏就会收到通知。
8. **不新增前端依赖**：不引 React Query、不引组件库、不引图标库；沿用现有 Tailwind + 一个新的 `mobile.css`（用同一批 `--paper/--panel/--ink/--accent/--skin-*` CSS 变量，皮肤切换自动生效）。
