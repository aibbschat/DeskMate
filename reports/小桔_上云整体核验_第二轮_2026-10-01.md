## 三、缺口（按严重度）

### ★ 缺口1：默认模型指向未配置的 OpenAI —— 首次对话会直接报错
- 实测 `/v1/settings`：`provider=openai`、`model=gpt-5.6-sol`、`onboarded=False`。
- 实测 `/v1/providers`：`openai configured=False`；而 `ark-agent-plan-cn configured=True`、`deepseek configured=True`。
- 代码路径：`manager.get_settings()`（`coworker/server/manager.py:3478-3480`）会把当前默认模型**强制插到可选列表首位**（即便其 provider 未配置）；`openai_provider._ensure_client()`（`coworker/providers/openai_provider.py:179-183`）在没有 key 时抛 `No model API key configured. Set OPENAI_API_KEY ...`。
- 影响：不动设置就发第一句话 = 报「No model API key configured」。而且 `onboarded=False` 说明云端是**全新未引导状态**。
- 处置：在界面设置里把模型切到 **`ark-agent-plan-cn:doubao-seed-evolving`**（或 `deepseek:deepseek-v4-flash` / `deepseek-v4-pro`），不要用 OpenAI。⚠ 也别选 `omniroute:auto`（云端没有本机那个 localhost:20128）。

### ★ 缺口2：记忆层拿不到 provider 凭证 —— 语义检索降级、记忆抽取不可用
- 实测（在实例上载入 `/etc/openworker/env` 后，用部署代码做只读探针）：`ARK key: True / DEEPSEEK key: True`，但 `deskmate.memory.llm._resolve_provider()` → `has_key=False`、`llm_available()=False`；`semantic_search.embed_text()` → **FAILED**，`last_error = api(text-embedding-3-small): 无 LLM provider API key`；模块自述「embedding 不可用 → 语义检索降级为纯关键词」。
- 根因：**两套凭证解析路径不一致**。coworker 对话层读 env（所以 `configured=True`、客户端能建），而 `deskmate/memory/llm.py:38-90` 只读 `prefs.json` 的 `default_model` + SecretStore 的 `provider:<id>` profile——而云端 `/var/lib/openworker/` 里 **既无 prefs.json 也无 secrets.json**（实测全盘 find 为空）。所以 env 里的两把 key 对记忆层不可见。
- 影响：①语义检索退化为关键词匹配（305 条记忆的价值大打折扣）；②记忆抽取/认知沉淀（`llm_available()` 为假时通常直接跳过）不可用；③凡走 `deskmate/memory/llm.py` 的功能（如 proactivity/close_loop）同样受影响。
- 附加：embedding 默认走 OpenAI 兼容 `/embeddings` + `text-embedding-3-small`；DeepSeek **没有** embeddings 接口，本地 BGE（`BAAI/bge-small-zh-v1.5`）因未装 `fastembed` 而 `local_available=false`。所以修 embedding 要单独选路（火山方舟的 embedding 模型，或给服务器装 fastembed 走本地）。
- 处置建议：在云端写 SecretStore profile（`provider:deepseek` / `provider:ark-agent-plan-cn` 的 api_key+base_url）与 `prefs.json.default_model`；或改用界面「Manage → Settings」把 provider 配进去（它写的就是 SecretStore）。embedding 另按上面二选一。

### 缺口3：AI 圈 mcp.json 未迁 —— 回信功能持续报错
