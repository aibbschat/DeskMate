# 小桔 · 江河设计：从「散落的点」到「流动的河」（2026-10-07）

> **这是一份设计，不是施工单。** 只画河道，不动一铲土。
> 上游依据：`reports/小桔_纵深巡检_记忆与判断层_2026-10-07.md`（巡检结论）
> 指导原则（萧哥 2026-10-07 口述）：
> **养孩子式的自主**——自由是默认，拦是例外，**拦必留教**；
> 不是怕危险就不让做，是「有人教她应该怎么做」。

---

## 一、总图：一条河，三段水

```
   〔散落的点〕                    〔汇流〕              〔反思〕            〔自主〕
 记忆点 · 理解点 · 判断点  →   连成网、能互看  →   回看自己、会改看法  →  有意图、能提案
        （各自为政）              （河床）            （自净）           （自己找路）

  ═══════════════════ 护栏横贯全程：自由默认 · 拦是例外 · 拦必留教 ═══════════════════
```

现状一句话：**地基（记忆）实，中段（判断）齐但散，上层（自主）窄。**
这条河今天是「三段断流」——水在，但不流。

---

## 二、第一段 · 汇流：把点连成网

### 2.1 要解决什么

记忆点之间没有边、理解点之间老死不相往来（见巡检 §1.2、§2.2）。
她要能自己说出「这件事，很像你一贯的脾气」——靠的就是**点与点之间的线**。

### 2.2 现状与缺口

- `profile_items` 表**无任何条目↔条目关联列**（`deskmate/cognitive/store.py` L246-L258）；
- 全库唯一像连线的 `cognitive_gaps.related_items_json`（同文件 L293）是「盲区挂条目」，不是条目互连；
- `learning_graph.py` 有「图」，但读的是 markdown 文件、连的是「技能↔记忆」，**不是我们要的桥**。

### 2.3 设计：两把锁，一显一隐

**主路（显式边表）**——真连线，可查、可解释：

```
memory_edges(
  id           TEXT PK   -- 确定性：<src_kind>:<src_id>:<rel>:<dst_kind>:<dst_id>（双端同 id → 自动合并）
  src_kind     TEXT      -- profile_item | learned_fact | understanding | ledger_item | diary
  src_id       TEXT
  dst_kind     TEXT
  dst_id       TEXT
  relation     TEXT      -- 同人 | 同主题 | 印证 | 对立 | 因果 | 派生
  weight       REAL      -- 0~1，随证据累积
  evidence     TEXT      -- 凭什么连（不做无据的连接）
  source       TEXT      -- 谁连的：extractor | reflect | human
  created_at   TEXT
)
```

**辅路（隐式共享锚）**——不硬连，先「邻座」：

条目抽取时顺手抽出**锚**（人物 / 主题 / 事件 / 项目 / 书目），同锚即相邻。
锚不落边，只作**自动补边**的线索与召回的兜底——省得每两条都硬连一遍把库撑爆。

### 2.4 接点（谁写、谁用）

| 动作 | 在哪 | 怎么改 |
|---|---|---|
| **写边** | `cognitive/extractor.py` 抽出条目时 | 顺手抽锚；同锚已有条目 → 自动落一条边（`source=extractor`） |
| **写边** | 反思/人审 | 反思发现两条相关 → 补边（`source=reflect`）；你手动连 → `source=human` |
| **用边** | `cognitive/store.py` `recall_items()` | 命中种子条目后 **顺边走一跳**，把邻居一并召回（这正是「流动」） |

### 2.5 边界与风险

- **防炸库**：只连「证据支持」的边；同锚自动连设**上限**（如单锚 ≤ N 条），超了降权不新增。
- **跨端一致**：边是**明文文本**，可进 `SYNC_TABLES`（照 `sync_uuid` 那套）；**绝不搬向量**（红线见 `sync_store_sqlite.py` L224-L243）。
- **可回退**：边是纯增益，去掉边表，召回退回今天的 FTS 口径——**零破坏**。

### 2.6 验收判据

- 抽 100 条新条目，至少能自动长出可解释的边（抽样人工看 `evidence`）；
- 一次召回里，邻居条目的出现**真的改善了回答**（拿几个「你以前也……」的实际对话验）。

## 三、第二段 · 反思：让沉淀带自省

### 3.1 要解决什么

世界观现在有，但**被动**：攒够 5 条观察、过 7 天、回望一次、允许弃权
（`agency/behaviors/worldview_reflection.py` L63-L81）。它是「到点总结」，不是「照镜子」。

### 3.2 现状与缺口

- 有沉淀（worldview 写入 `profile_items layer='worldview'`）；
- **无自省**——`item_history` 其实记了每条看法的变化史（old/new/reason），
  但从没被用来回看「我为什么变了」；
- 判断层同理：`judge` 每次都是独立一判，**不记得自己以前怎么判的**（巡检 §2.5）。

### 3.3 设计：加一个「反思 tick」

在既有的**每小时 agency tick** 里挂一个低频反思（比如每天/每周一次，与 worldview 回望错开）：

**它做三件事**：
1. **回看判断**：翻最近的判据记录——哪几条判了、后来应验没有；
2. **回看看法**：翻 `item_history` ——哪些看法在这段时间里被改过、为什么改；
3. **照镜子**：产出「维持 / 修订 / 推翻」的结论 + **理由**，落到对应的 worldview / 认知条目上。

**关键差别**：现在的 worldview 是「重新生成一条覆盖旧的」；反思是「**对已有看法做出裁决，并留下为什么**」——
沉淀变成**有记忆的沉淀**。

### 3.4 数据模型

```
reflections(
  id           TEXT PK
  ts           TEXT
  scope        TEXT      -- 本周判断 | 本季看法
  subject_kind TEXT      -- judgment | profile_item | worldview
  subject_id   TEXT
  observation  TEXT      -- 我看到了什么（判得对不对）
  verdict      TEXT      -- maintain | revise | overturn
  revision     TEXT      -- 修订后的说法
  reason       TEXT      -- 为什么变（这是灵魂，不能空）
  applied_to   TEXT      -- 落地到哪条
)
```

> `item_history` 已有 `old_value / new_value / reason / ts` 四列——反思可直接复用，
> 不必另造一套变化史；`reflections` 只承载「回看」这个动作本身。

### 3.5 接点

- **触发**：agency tick（`agency/engine.py`）新增一个低频行为，或复用 `worldview_reflection` 前置一步；
- **消费**：反思结论 → 更新 worldview；同时把「理由」写进注入上下文，
  让她下次谈相关话题时，**知道自己是这么想的、也是这么变的**。

### 3.6 验收判据

- 反思产出**必须带理由**（`reason` 空 = 这次反思作废）；
- 一段时间后，worldview 里能看到「变化 + 原因」的痕迹，而不只是当前结论。

## 四、第三段 · 自主：从「上发条」到「有意图」

### 4.1 要解决什么

她今天是个**「白名单 + 风险分级」的定时执行器**：低风险动作自己跑，高风险/未知 → 提议卡等你裁决
（`agency/engine.py` L43-L96、L313-L408；`agency/registry.py` L29-L133）。
**做什么是被注册好的，不是她自己想的**——这就是「上发条」。
目标是：**让她自己产生意图，并据此提案；危险动作先拦、等你一句话；裁决变成她的经验。**

### 4.2 现状：护栏已有，缺的是两头

**已有（且跟萧哥的设想几乎一致）**：
- 低风险 → 自主执行；高风险/未知 → **提议卡**（`task_log.py` 状态机 done/proposed/executed/rejected/never）；
- 你裁决 → `resolve_proposal()`（`agency/engine.py` L351-L408）；
- `kill switch`、频率去重（`agency/outbound.py` L191-L240）、公开过滤（`agency/visibility_gate.py` L96-L127）；
- 甚至已有先例：**AI 圈对外表达被明确授权自主、无审批闸**（`registry.py` L72-L93）
  ——你的「养孩子」理念，代码里其实已经开过一扇窗。

**缺的两头（正是分界线）**：
1. **意图的源头被锁死**：`route_task` 恒 self（`engine.py` L67-L70），她只能提「注册好的动作」，不能提「她自己想干的事」；
2. **裁决不留教**：`resolve_proposal()` 除个别特例（`memory_subject_conflict`）外**只改状态**，
   不写任何经验；`never_list()` 是「**整个动作类型拉黑**」，粒度粗、无理由、且是临时的
   （`task_log.py` L189-L191）——**你拦下就只是拦下，她没学到东西。**

### 4.3 设计：意图 → 提案 → 裁决 → 教学（四段闭环）

**① 意图层（她想做什么）**

新增 `intents` 表，让「目标」成为一等公民：

```
intents(
  id          TEXT PK
  ts          TEXT
  goal        TEXT      -- 我想做什么（第一人称）
  motivation  TEXT      -- 为什么想做（从哪条记忆/理解长出来的）
  horizon     TEXT      -- short | long
  status      TEXT      -- open | active | done | dropped
  origin      TEXT      -- 意图从哪来：未满足的关怀 | 未接着的观察 | 长期兴趣 | 你的话
  proposed_task_id TEXT -- 关联到 task_log 的那条提案
)
```

意图从哪来（**不凭空造**，都从前面的河床里长）：
- **未满足的关怀**：台账里挂着的、你没接的话；
- **未接着的观察**：观察日记/理解里悬而未决的事；
- **长期兴趣**：关联边聚出来的主题簇（这就是汇流层的用处）；
- **你的话**：你随口说过想做什么。

**② 提案层（她怎么说）**

扩开提案来源：不限于 `REGISTRY` 里的动作。新意图 → 生成 `proposed` 记录，
`extra` 里带 `intent_id` 与**她打算怎么做**。**未知动作照旧走「提案」，不是「卡死」**
——这正好落地你说的「不是怕危险就不让做」。

**③ 裁决层（你怎么管）**

沿用现有提议卡（`task_log` propose/resolve）+ kill switch，不重造。
你能看到的每条提案都带：**她想干什么 + 为什么 + 她打算怎么做**——你才好"教"。

**④ 教学层（她怎么学）——本次设计的核心**

`resolve_proposal()` 裁决后**新增一步：写 `lessons`**：

```
lessons(
  id          TEXT PK
  ts          TEXT
  subject     TEXT      -- 动作类型 或 意图
  decision    TEXT      -- executed | rejected | never
  user_note   TEXT      -- 你的理由/指示（没有就留空）
  rule        TEXT      -- 提炼成一条边界：可做 / 不可做 / 该怎么做
  scope       TEXT      -- 适用范围（这条类型？这类事？永久？）
)
```

- `executed` → 学会「这样做可以」（甚至值得复用）；
- `rejected` → 学会「这次不行」（**带上下文**，不是永久拉黑）；
- `never` → 「这类事就别做了」，但**要带理由**，且可撤销——升级掉今天「整类型临时拉黑」的粗粒度。

**最要紧的一步**：`lessons` 必须像 `memory-context` 那样**被注入她每轮上下文**。
否则学了白学——**裁决不回流，等于没教**。

### 4.4 护栏原则（把萧哥口述落成三条硬规矩）

1. **自由默认，拦是例外**：新动作默认「可以提案」；只有真高风险才升级到必须人审。
2. **拦必留教**：任何裁决（放行/拦下/永不做）都必须写一条 `lesson`；`reason` 为空则拒绝记录
   ——不允许出现「拦了但不知道为什么拦」。
3. **未知不卡死**：未知动作走「提案待人审」，不静默丢弃（现在代码已是「未知→提案」，
   本设计只是把**提案的源头**从白名单放开到意图）。

### 4.5 接点与安全

| 环节 | 落点 |
|---|---|
| 意图生成 | agency tick 增一个低频行为（读关怀/观察/关联边 → 写 `intents`） |
| 提案 | 扩 `agency/engine.py` 提案来源；`task_log` 不动 |
| 裁决 | 扩 `resolve_proposal()`：新增写 `lessons` |
| 教学生效 | `memory/manager.py` 注入链新增 `lessons` 段（与 `<memory-context>` 同层） |
| 安全 | kill switch 保持最高优先级；`outbound`/`visibility_gate` 不动；高风险动作**永远**走人审 |

### 4.6 验收判据

- 她**提出过**至少一条「不在原白名单里」的意图型提案（=真的会想事了）；
- 你拦下一条之后，她**下一次同类提案的行为有可见变化**（=教进去了）。

## 五、为什么是这个顺序（三段不能乱）

- **汇流是河床**：没有边，反思没有素材（不知道哪些事相关），自主没有依据（不知道兴趣簇在哪）；
- **反思是自净**：没有自省，世界观只是「隔段时间重写一次」，自主会把旧的错看法当真理去行动；
- **自主是出海口**：前三段都通了，自主才有底气——**她的每个意图都站在自己记得、想过的事上**。

但**护栏横贯三段**：不管做到哪一段，`拦必留教` 从第一天就要成立。

## 六、改动范围与代价（供拍板，非估时）

| 段 | 新增 | 修改 | 跨端 |
|---|---|---|---|
| 汇流 | `memory_edges`（+锚） | `extractor.py`（抽锚/连边）、`store.recall_items()`（顺边走） | 进 `SYNC_TABLES` |
| 反思 | `reflections`（可选，或复用 `item_history`） | agency tick 增行为；worldview_reflection 前置一步 | 可同步 |
| 自主 | `intents`、`lessons` | `engine.py`（意图→提案）、`resolve_proposal()`（写教）、`manager.py`（注入教） | 进 `SYNC_TABLES` |

**共同红线**：
- 新表若跨端，**只同步明文**，向量各端重算（`sync_store_sqlite.py` L224-L243 的启动守卫）；
- 敏感来源（手机灵感/日记类）沿用行级 `visibility='local'` 的不同步开关；
- 所有 LLM 环节 **fail-open**（现状风格），不许因新机制把主链路拖崩。

## 七、分期建议（若做，一步一步来）

- **P1 · 汇流最小版**：只做「抽取时抽锚 + 同锚自动连边 + 召回顺边走一跳」。**零破坏、可回退**，先验证「连着走」到底有没有让回答变好。
- **P2 · 反思**：低频反思 tick + 强制带理由。让世界观从「重写」变「修订」。
- **P3 · 自主闭环**：意图 → 提案 → 裁决 → 教学，四段一起上。**这是最大的一步**，因为它动了「她做什么」的决定权，护栏规格必须在 P3 之前先定死。

## 八、已拍板决策（2026-10-07 萧哥定，逍遥整理）

> 原「待拍板」四项现已拍板。设计仍是设计，未进入施工；P1 施工单见
> `reports/P1_汇流最小版_施工单_2026-10-07.md`。

1. **汇流用哪种 → 先用「共享锚」轻量试水，显式边表延后。**
   - P1 不建 `memory_edges` 显式边表；只在抽取时抽锚 + 同锚自动连「邻座」+ 召回顺边走一跳。
   - 理由：自动连边上限是拍脑袋阈值，价值证据浮现前边是噪声；先验证「连着走一跳」到底有没有让回答变好。
   - 何时落显式边：某关系被锚反复证明有价值（reflect/human 发现）→ 由 `reflect`/`human` 落成可解释、可查的显式边（非 extractor 自动）。

2. **反思记录 → 复用 `item_history`，不新开 `reflections` 表。**
   - `item_history` 已有 old/new/reason/ts 四列，反思直接复用；`reflections` 仅承载「回看这个动作」本身（如确需）。
   - 硬断言：`reason` 为空 = 此次反思作废（不写 worldview），落代码当断言，不靠自觉。
   - 风险钉死：反思 verdict 回写 worldview 时，**「为什么变」的痕迹必须留在 `item_history` 并被召回**，不得被覆盖吞掉。

3. **lessons 注入上下文预算 → 限最近 N 条 + 永久规则，随总开关。**
   - 只注入「最近 N 条（默认 3）+ scope=永久 的规则」；其余 lessons 进库沉淀，不每轮硬灌。
   - 挂 `DESKMATE_AUTO_INJECT` 同开关：关整体记忆注入时连 lessons 一起关。
   - 理由：每轮上下文已装记忆/画像/情感/读书/已递待办（灵动三层刚挂的），无脑灌会挤爆。

4. **意图允许跨哪些领域 → 写作是永久红线，查资料无闸，主动查史料佐证完全可开。**
   - **替你写作 = 永久红线，不可能发生。** 但她「自主写作」（AI 圈手记、花园日记、广场发帖）是**她写她的，不是替你写**——谁也不替谁，不在此红线内，照常。
   - **查资料 = 她一直在做，无闸门。**
   - **主动帮你查史料佐证 = 完全可开**：你写好的稿子里可能没留意史实细节，她主动查、回来告诉你，锦上添花，不必拦；随 P1 汇流自然长出来。**必须用上本地自有史料库**（史料以本地库为准，不瞎联网）。
   - **自主总原则（萧哥重申，与历史意见一致）**：要让她自主，只在关键时刻拦一下；P3「拦必留教」的意义**不是「危险了就限制自由」，而是「告诉她为什么危险」**——拦必带理由，教而不禁。
